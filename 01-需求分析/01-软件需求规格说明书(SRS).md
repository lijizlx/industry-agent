## 1. 引言

### 1.1 目的

本说明书依据 IEEE 830 风格编制，定义 IndustryAgent（工业智能体平台）v1.0 的功能需求、数据需求、接口需求与设计约束，作为设计、开发、测试与验收的基准。本需求源于《用户需求说明书》（IA-RM-001）UR-001~UR-030。

### 1.2 范围

- 产品名称：IndustryAgent 工业智能体平台 v1.0
- 产品定位：面向芯联半导体（虚拟）12 英寸晶圆厂的良率根因分析智能体平台，覆盖"监控→根因→建议→审批→报告"五 Agent 闭环及配套业务平台。
- 排除项：见《项目章程》（IA-PM-001）第 4.2 节（排产优化、RUL 预测、真实工厂对接等）。

### 1.3 定义与缩略语

| 缩略语 | 全称/定义 |
|---|---|
| Agent | 智能体（监控/根因/建议/审批/报告五类） |
| FDC | Fault Detection and Classification，故障检测与分类 |
| MCP | Model Context Protocol，智能体工具调用协议 |
| RBAC | Role-Based Access Control，基于角色的访问控制 |
| OPA | Open Policy Agent，策略引擎 |
| OIDC | OpenID Connect，认证协议 |
| RAG | Retrieval-Augmented Generation，检索增强生成 |
| KG | Knowledge Graph，知识图谱 |
| SPC | Statistical Process Control，统计过程控制 |
| 8D | Eight Disciplines，八步问题解决法报告 |
| DoD | Definition of Done，完成的定义 |
| 事件 | 由异常检测产生、触发智能体链路处理的一次异常记录 |

## 2. 总体描述

### 2.1 产品前景

平台处于虚拟企业既有系统（MES/ERP/SCADA/FDC/LIMS）之上，作为智能分析与协同处置层。系统上下文：

```
外部数据源                    IndustryAgent 平台                     用户
┌─────────────┐   MQTT/Kafka  ┌──────────────────────────┐  HTTPS/OIDC  ┌───────┐
│ 设备传感器    │ ───────────► │ 数据接入层 → 存储(TSDB/PG/ │ ◄──────────► │ Web   │
│ SCADA/FDC    │              │ Neo4j/MinIO/pgvector)    │              │ 前端   │
├─────────────┤   REST 同步   │ 智能体层: 监控/根因/建议/  │              │ React │
│ MES/ERP/LIMS │ ───────────► │ 审批/报告 (LangGraph+MCP) │              └───────┘
└─────────────┘              │ 业务层: Egg.js 4.0 + OPA  │
                              │ AI层: FastAPI + 本地LLM    │
                              └──────────────────────────┘
```

### 2.3 用户特征

| 用户类 | 特征 | 使用方式 |
|---|---|---|
| 工艺工程师（PE） | 工艺专家，Web 操作熟练，关注可信度与证据 | 工作台高频操作、审批 |
| 设备工程师（EE） | 设备专家，关注告警质量与漂移预警 | 看板、告警处理 |
| 生产主管（PP） | 关注产能与交付，偏好大屏与汇总 | 看板、审批、报表 |

| 系统管理员（SA） | IT 运维，关注权限、配置与系统健康 | 管理后台 |

### 2.4 约束

见第 7 章设计约束（数据不出域、私有化、技术栈基线、人工审批硬约束等）。

### 2.5 假设与依赖

1. 模拟数据源（MQTT/REST）在 I2 就绪并可注入脏数据；
2. 私有化 LLM（13B 级量化）算力满足单次根因分析延迟预算；
3. 知识图谱首批 100 实体与 RAG 语料在 I2 入库；
4. 虚拟企业角色按白皮书参与评审与 UAT。

## 3. 运行环境

### 3.1 硬件环境

| 组件 | 最低配置 | 生产配置 |
|---|---|---|
| 应用服务器（Egg.js/FastAPI/前端） | 8C16G ×2 | 8C16G ×6（K8s 多副本） |
| 数据库（PostgreSQL 16+TimescaleDB+pgvector） | 8C32G+SSD | 16C64G+NVMe ×2（主从） |
| Neo4j 5 图数据库 | 4C16G | 8C32G |
| Kafka/MQTT 集群 | 4C16G ×3 | 8C32G ×3 |
| MinIO 对象存储 | 4C16G+2T | 8C32G+10T |
| GPU 推理服务器 | — | 高性能推理卡 ×2（本地 LLM + 向量化） |
| Redis | 4C16G | 8C16G（主从+哨兵） |

### 3.2 软件环境

| 层 | 软件 |
|---|---|
| 前端 | React 18 + TypeScript + Vite + Ant Design 5 |
| 业务后端 | Egg.js 4.0（兼 MCP Server），Node.js ≥18 |
| AI 微服务 | Python 3.11 + FastAPI + LangGraph |
| 数据 | PostgreSQL 16 + TimescaleDB + pgvector、Neo4j 5、MinIO、Redis |
| 消息 | Kafka 3.x、MQTT（EMQX/Mosquitto） |
| 可观测 | Prometheus + Grafana + OpenTelemetry |
| 安全 | Keycloak 24+（OIDC）、OPA |
| 部署 | Docker Compose（开发）→ Kubernetes（生产） |
| CI/CD | GitHub Actions |

### 3.3 网络环境

- 全内网部署，无互联网出口依赖（数据不出域）；
- 客户端经 HTTPS（TLS 1.3）访问前端，前端与后端经内网网关；
- 浏览器：Chrome/Edge 最近两个大版本。

## 6. 接口需求

### 6.1 外部接口

| 接口 | 协议 | 方向 | 内容 | 约束 |
|---|---|---|---|---|
| IF-01 设备遥测接入 | MQTT（TLS） | 设备/SCADA → 平台 | 参数遥测、心跳 | QoS≥1；吞吐 ≥5 万点/秒 |
| IF-02 数据总线 | Kafka | 内部/源 → 平台 | 时序/业务/事件主题 | 分区可扩展；积压告警 |
| IF-03 MES 同步 | REST/JSON（模拟） | MES → 平台 | 工单/批次/工艺路线 | 幂等重试 |
| IF-04 ERP 同步 | REST/JSON（模拟） | ERP → 平台 | 物料/订单 | 幂等重试 |
| IF-05 LIMS 同步 | REST/文件（模拟） | LIMS → 平台 | CP/WAT 结果、缺陷分类 | 文件格式校验 |

### 6.2 内部接口

| 接口 | 协议 | 方向 | 内容 |
|---|---|---|---|
| IF-06 前端-后端 | REST/HTTPS + WebSocket | 前端 → Egg.js | 业务 API、实时告警推送 |
| IF-07 后端-AI 微服务 | REST/gRPC | Egg.js → FastAPI | 分析任务、建议生成、报告生成 |
| IF-08 智能体工具 | MCP | Agent → MCP Server(Egg.js) | 图谱查询/RAG 检索/因果分析/数据查询工具 |
| IF-09 认证授权 | OIDC/OPA REST | 各服务 → Keycloak/OPA | 令牌校验、策略决策 |
| IF-10 可观测 | OTLP/HTTP | 各服务 → OTel Collector | Trace/Metric/Log 上报 |

### 6.3 接口通用约定

1. 全部接口启用 TLS 1.3 与 OIDC Bearer Token；
2. 接口错误码统一结构 `{code, message, traceId}`，traceId 与链路追踪关联；
3. 写接口幂等（幂等键 Header）；
4. 接口契约以 OpenAPI 3.1 定义并纳入配置管理，破坏性变更需评审。
