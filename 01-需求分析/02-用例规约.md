## 2. UC-001 用户登录鉴权

| 项目 | 内容 |
|---|---|
| 用例编号 | UC-001 |
| 用例名称 | 用户登录鉴权 |
| 参与者 | 主：任意角色用户（PE/EE/PP/QE/SA）；次：Keycloak |
| 前置条件 | 1. 账号已由管理员开通且状态为启用；2. 用户已分配至少一个角色；3. 平台可访问 Keycloak |
| 后置条件 | 1. 会话建立并记录审计；2. 用户按角色获得菜单与数据范围；3. 登录失败次数超限触发锁定 |

**主成功场景：**

| 步骤 | 用户动作 | 系统响应 |
|---|---|---|
| 1 | 打开平台首页 | 重定向至 Keycloak 登录页（OIDC 授权码流程） |
| 2 | 输入账号密码并提交 | Keycloak 校验凭据；成功则签发授权码 |
| 3 | — | 平台用授权码换取 Access/Refresh Token，加载用户、角色、数据范围 |
| 4 | — | 建立 Web 会话，跳转角色对应首页；写入登录审计日志 |
| 5 | 访问业务功能 | 网关校验 Token，OPA 按角色-资源策略放行/拒绝 |

**扩展流：**

| 分支 | 触发条件 | 处理 |
|---|---|---|
| E1 | 密码错误 | 提示"账号或密码错误"（不泄露具体原因）；连续 5 次失败锁定 30 分钟并告警 SA |
| E2 | 账号停用/过期 | 拒绝登录，提示联系管理员；记录审计 |
| E3 | 首次登录 | 强制修改初始密码后方可进入 |
| E4 | Token 过期 | 用 Refresh Token 静默续期；续期失败则跳转登录页，保留原访问路径 |
| E5 | Keycloak 不可用 | 登录不可用提示；管理员可启用应急只读账号流程（全程审计） |
| E6 | 会话超时 | 30 分钟无操作自动登出（可配置），提示后重新认证 |

**业务规则：**

1. BR-001：所有接口默认拒绝，无有效 Token 与策略放行不可访问（FR-003）；
2. BR-002：登录、登出、登录失败均写审计（FR-007）；
3. BR-003：一个账号同一时刻最多 3 个活跃会话；
4. BR-004：密码策略：长度 ≥8，含大小写与数字，90 天强制更换（FR-010）。

**非功能要求：** 登录接口 P95 <500ms（NFR-001）；认证链路 trace 覆盖（NFR-026）；审计记录保留 ≥1 年（NFR-018）。

## 3. UC-002 异常事件监控告警

| 项目 | 内容 |
|---|---|
| 用例编号 | UC-002 |
| 用例名称 | 异常事件监控告警 |
| 参与者 | 主：设备工程师（EE）；次：监控 Agent、外部数据源（MQTT/Kafka）、工艺工程师 |
| 前置条件 | 1. 数据源接入并正常上报（FR-011/013/015）；2. 检测规则已配置并启用（FR-029）；3. 监控 Agent 运行正常（FR-033） |
| 后置条件 | 1. 异常事件入库并分级；2. 相关角色收到告警；3. 严重/警告事件自动触发根因分析任务（UC-003） |

**主成功场景：**

| 步骤 | 参与者/Agent 动作 | 系统响应 |
|---|---|---|
| 1 | 设备持续上报参数遥测 | 数据经 MQTT→Kafka 入流，窗口计算实时指标（FR-021） |
| 2 | 监控 Agent 执行规则检测 | 阈值/SPC 规则匹配命中，产生异常候选（FR-022） |
| 3 | — | 候选去重、合并、关联设备与批次，生成异常事件并分级（FR-024） |
| 4 | — | 告警按级别路由推送：严重→设备工程师+工艺工程师+生产主管；警告→责任工程师（FR-025） |
| 5 | EE 收到站内/邮件告警 | EE 打开实时监控面板查看参数趋势与控制图（FR-027） |
| 6 | EE 标记告警性质 | 如实告警→确认并等待根因结果（UC-003）；误报→标记误报并注明原因（FR-028） |
| 7 | — | 严重/警告事件且未被标记误报时，自动创建根因分析任务（FR-034） |

**扩展流：**

| 分支 | 触发条件 | 处理 |
|---|---|---|
| E1 | 参数缓慢漂移（未越限） | 双通道漂移检测提前预警（FR-023），生成"漂移预警"级别事件 |
| E2 | 告警风暴（同源高频） | 告警收敛抑制合并为一条聚合告警（FR-026） |
| E3 | 数据源断线 | 心跳检测发现断流（FR-030），产生"连接中断"事件并告警 SA/EE |
| E4 | 事件长时间无人确认 | 按升级策略逐级上报（FR-031）：30 分钟→主管，60 分钟→部长 |
| E5 | 数据缺失/重复 | 数据质量校验打标（FR-017），异常数据隔离（FR-018），检测降级并提示 |
| E6 | 监控 Agent 自检失败 | 健康告警通知 SA，分析任务降级为排队等待（FR-033/045） |

**业务规则：**

1. BR-005：事件分级标准——严重（停机风险/批次质量风险）、警告（越限可控）、信息（漂移预警）；
2. BR-006：误报标记必须填写原因，回流评估库参与月度误报率统计（UR-028）；
3. BR-007：注入异常 30 分钟内检出率 ≥90%，告警送达 <10 秒（NFR-005/006）；
4. BR-008：误报率目标 <10%，超标触发规则调优任务。

**非功能要求：** 遥测端到端延迟 <2s（NFR-005）；写入吞吐 ≥5 万点/秒（NFR-008）；平台可用性 99.9%（NFR-011）。

## 4. UC-003 根因分析 Top-3

| 项目 | 内容 |
|---|---|
| 用例编号 | UC-003 |
| 用例名称 | 根因分析 Top-3 |
| 参与者 | 主：工艺工程师（PE）；次：根因 Agent（LangGraph 编排）、监控 Agent |
| 前置条件 | 1. 异常事件已生成（UC-002）；2. 知识图谱与 RAG 语料就绪；3. 分析服务与 GPU 算力可用；4. PE 已登录 |
| 后置条件 | 1. Top-3 根因及置信度入库并与事件绑定；2. 证据链可访问（UC-004）；3. 分析任务状态更新，全程 trace 记录 |

**主成功场景：**

| 步骤 | 参与者/Agent 动作 | 系统响应 |
|---|---|---|
| 1 | 严重/警告事件触发 | 分析任务入队（FR-034），任务管理器调度（FR-045） |
| 2 | 根因 Agent 启动编排 | 汇聚异常窗口内时序/批次/检测/维护数据（FR-035） |
| 3 | — | 并行执行三路取证：知识图谱推理（FR-036）、RAG 文档检索（FR-037）、因果推断（FR-038） |
| 4 | — | 三路证据加权融合，生成 Top-3 根因候选与置信度（FR-039） |
| 5 | — | 构建证据链：数据→图谱→文档（FR-040）；推送结果给 PE |
| 6 | PE 打开根因结果页 | 查看 Top-3 列表、置信度、相似历史案例（FR-043） |
| 7 | PE 验证结论 | 认可→一键生成调参建议（UC-005）；存疑→下钻证据链（UC-004） |

**扩展流：**

| 分支 | 触发条件 | 处理 |
|---|---|---|
| E1 | 三路证据冲突 | 输出并列结论，标注"证据不足"，置信度下调并提示人工复核 |
| E2 | 某路工具调用失败 | 按退避策略重试 2 次；仍失败则降级为双路证据并在结果中注明缺失路证据 |
| E3 | 分析超时（>5 分钟） | 任务熔断（FR-045），状态置"超时"，通知 PE 可人工接管（FR-044） |
| E4 | PE 人工接管 | PE 补充结论并提交，标记"人工接管"，计入接管率统计 |
| E5 | PE 判定 Top-3 未命中 | 标注"未命中"并填写真实根因，回流评估库（UR-028） |
| E6 | 相同设备短时间重复触发 | 任务去重合并，复用既有分析并追加增量证据（FR-034 去重） |
| E7 | GPU 推理过载 | 队列排队优先级调度（严重事件优先），超阈值告警 SA |

**业务规则：**

1. BR-009：Top-3 准确率目标 >80%（评估集口径），连续 5 次不命中触发算法评审；
2. BR-010：分析端到端延迟 <5 分钟（NFR-002），业务时效承诺为 4 小时内给出 Top-3（含排队与人工等待）；
3. BR-011：结论必须附置信度与证据引用，无证据结论不得输出；
4. BR-012：人工接管率目标 <30%（SC-04）；
5. BR-013：因果结论须标注方法（DoWhy/EconML）与数据窗口，禁止无数据支撑的断言。

**非功能要求：** 端到端 <5min（NFR-002）；Agent 每步 trace 记录（NFR-026）；分析报告页加载 <3s（NFR-004）。

## 5. UC-004 查看根因证据链

| 项目 | 内容 |
|---|---|
| 用例编号 | UC-004 |
| 用例名称 | 查看根因证据链 |
| 参与者 | 主：工艺工程师（PE）；次：根因 Agent |
| 前置条件 | 1. 根因分析已产出 Top-3（UC-003）；2. PE 对应事件有数据权限（FR-006） |
| 后置条件 | PE 完成证据核验，形成采纳/存疑判断；核验行为记录审计 |

**主成功场景：**

| 步骤 | 用户动作 | 系统响应 |
|---|---|---|
| 1 | 在根因结果页点击某嫌疑根因 | 展开该根因的证据链视图（FR-041） |
| 2 | 查看数据证据 | 显示异常窗口参数曲线、控制图、批次 CP/WAT 关联数据，可下钻原始点 |
| 3 | 查看图谱证据 | 显示设备-工艺-参数-缺陷关系子图，高亮传播路径（FR-036） |
| 4 | 查看文档证据 | 显示命中的工艺文档片段及出处链接，可跳转原文（FR-037） |
| 5 | 核验完成，标注结论 | 选择"采纳/存疑/排除"，填写备注；记录核验人与时间（FR-007） |

**扩展流：**

| 分支 | 触发条件 | 处理 |
|---|---|---|
| E1 | 数据证据缺失（数据被隔离/清理） | 显示占位说明与数据质量标记（FR-017/018），注明缺失原因 |
| E2 | 文档链接失效 | 定位文档最新版本并标注版本变更（FR-079） |
| E3 | 无数据权限的批次 | 行级过滤隐藏明细，提示申请权限（FR-006） |
| E4 | PE 导出证据包 | 打包该事件证据链（曲线快照+子图+文档片段）至 MinIO 并生成下载链接（FR-074） |

**业务规则：**

1. BR-014：证据链三层结构（数据/图谱/文档）缺项必须在视图中显式标注；
2. BR-015：证据引用与原始数据的绑定关系不可删除，确保可追溯（FR-063 复用）。

**非功能要求：** 证据链页面首屏 <3s（NFR-004）；图谱子图渲染节点数 ≤200，超出自动聚合。

## 6. UC-005 生成调参建议

| 项目 | 内容 |
|---|---|
| 用例编号 | UC-005 |
| 用例名称 | 生成调参建议 |
| 参与者 | 主：工艺工程师（PE）；次：建议 Agent |
| 前置条件 | 1. 根因分析产出 Top-3 且至少一条被采纳（UC-003/004）；2. 历史案例库可用 |
| 后置条件 | 1. 建议生成并附风险评估（FR-048）；2. 建议进入待审批状态（UC-006），未审批前不可执行 |

**主成功场景：**

| 步骤 | 参与者动作 | 系统响应 |
|---|---|---|
| 1 | PE 在根因页点击"生成调参建议" | 建议 Agent 接收根因上下文（FR-046） |
| 2 | — | 检索历史有效调参案例（FR-043），结合当前工艺窗口生成建议：参数项/目标值/调整依据 |
| 3 | — | 执行风险评估：影响范围、成本、置信度、风险等级（FR-048） |
| 4 | — | 生成多方案对比（保守/推荐/激进）及优劣矩阵（FR-049） |
| 5 | PE 查看建议 | 展示建议卡（含历史案例引用、风险评估），PE 可编辑微调参数 |
| 6 | PE 提交 | 建议进入审批流，推送审批待办（FR-051）；状态"待审批" |

**扩展流：**

| 分支 | 触发条件 | 处理 |
|---|---|---|
| E1 | 无可参考历史案例 | 生成建议标注"无历史先例，基于工艺规范推导"，风险等级强制上调一级 |
| E2 | 建议参数超出工艺窗口 | 生成时校验拦截，提示并要求重新生成（FR-046 参数校验） |
| E3 | 根因含设备劣化因素 | 触发停线/维护建议分支（FR-047），联动 UC-006 由生产主管决策 |
| E4 | 生成失败/超时 | 重试 2 次后通知 PE 手动填写建议模板，系统记录 Agent 失败原因 |
| E5 | PE 修改建议内容 | 修改留痕（修改人/时间/前后对比），提交时标注"人工修订" |

**业务规则：**

1. BR-016：调参建议 100% 人工审批，不可自动执行（DC-02 硬约束）；
2. BR-017：建议必须包含风险等级；"高风险"建议审批层级 +1；
3. BR-018：建议引用历史案例须可点击回溯案例原文；
4. BR-019：停线类建议必须附产能影响估算与替代方案（UR-013）。

**非功能要求：** 建议生成 <60s（NFR-002 分解）；审批流操作响应 <1s（NFR-009）。

## 7. UC-006 建议人工审批

| 项目 | 内容 |
|---|---|
| 用例编号 | UC-006 |
| 用例名称 | 建议人工审批 |
| 参与者 | 主：生产主管（PP）/工艺工程师（PE，按审批级配置）；次：审批 Agent、质量工程师（升级知会） |
| 前置条件 | 1. 建议处于"待审批"；2. 审批人具有对应资源与级别审批权限（FR-003/050）；3. 审批流模板已配置 |
| 后置条件 | 1. 审批结论与意见归档且不可篡改（FR-055）；2. 批准的建议进入执行跟踪（FR-054）；3. 全程审计 |

**主成功场景：**

| 步骤 | 参与者动作 | 系统响应 |
|---|---|---|
| 1 | PP 收到审批待办（站内+邮件） | 待办列表展示建议摘要、风险卡、证据链入口（FR-051） |
| 2 | PP 打开审批详情 | 完整展示：建议内容、风险等级、影响范围、成本估算、历史案例、根因证据 |
| 3 | PP 审查后批准 | 填写审批意见，点击批准（FR-052）；OPA 校验其审批权限 |
| 4 | — | 状态流转"已批准"；审批记录追加归档（审批人/时间/意见/建议版本）（FR-055） |
| 5 | — | 建议进入执行跟踪，指派执行人（FR-054）；通知 PE 与执行人 |
| 6 | PP 查看执行回评 | 执行完成后登记效果回评，闭环事件 |

**扩展流：**

| 分支 | 触发条件 | 处理 |
|---|---|---|
| E1 | PP 驳回 | 填写驳回理由；建议退回 PE，可修改后重新提交（重新走审批） |
| E2 | PP 挂起（需补充信息） | 状态"挂起"，@PE 补充说明，审批时钟暂停 |
| E3 | PP 转审 | 转给具有同级权限的审批人，转审记录留痕 |
| E4 | 审批超时 | 按策略升级（FR-053）：2 小时→上级；4 小时→制造部长；超时限未决告警 |
| E5 | 多级审批中任一级驳回 | 流程终止，状态"驳回"，全链路记录各节点结论 |
| E6 | 审批人无数据权限 | OPA 拒绝并提示申请权限，拒绝记录审计 |
| E7 | 高风险建议 | 强制 2 级审批（PE→PP/部长），并同步知会质量工程师 |

**业务规则：**

1. BR-020：关键建议（调参/停线）100% 人工审批，系统不得代替（DC-02）；
2. BR-021：审批记录不可篡改、不可删除，保留 ≥1 年（NFR-018）；
3. BR-022：审批操作与 SLA——首响应 ≤2 小时，超时自动升级；
4. BR-023：驳回必须填写理由（≥10 字）；批准意见可留空但有默认文案。

**非功能要求：** 审批接口响应 <1s（NFR-009）；审计写入为异步保障可用性（NFR-018）。

## 8. UC-007 自动生成 8D 报告

| 项目 | 内容 |

| 2 | — | 按 D1~D8 模板生成草稿：D1 团队/D2 问题描述/D3 临时措施/D4 根本原因（引 Top-3 与最终认定）/D5 纠正措施（引审批建议）/D6 实施验证/D7 预防措施/D8 结论 |
| 3 | — | 每个数据点标注来源引用（FR-063），生成 <3 分钟（NFR-010） |
| 4 | QE 在线编辑草稿 | 富文本编辑、自动暂存、版本对比（FR-058） |
| 5 | QE 提交评审 | 在线会签流程（FR-060），评审意见留痕 |
| 6 | 定稿导出 | 导出 PDF/Word（FR-059），归档并登记版本（FR-061） |

**扩展流：**

| 分支 | 触发条件 | 处理 |
|---|---|---|
| E1 | 事件未完全闭环（D6 无数据） | 生成时 D6 标注"待验证"，并列出未完成纠正措施清单（FR-064） |
| E2 | 数据引用源被修改 | 引用快照机制：生成时固化数据快照，并标注"数据版本 vN" |
| E3 | LLM 生成文案不符合体系用语 | QE 人工编辑为准；模板支持公司术语表注入（FR-056） |
| E4 | 生成超时（>3 分钟） | 降级为模板填充模式（不写长文），通知 QE 手工补写 |
| E5 | 评审驳回 | 回到编辑态，驳回意见关联；重新提交再次评审 |

**业务规则：**

1. BR-024：自动报告定位为"草稿"，最终定稿责任人为 QE，不替代人工判断；
2. BR-025：D4 根本原因必须与根因分析结论或人工认定结论一致，差异需说明；
3. BR-026：报告导出格式必须符合公司质量体系 8D 模板（FR-059）；
4. BR-027：定稿后内容不可修改，如需变更走"报告修订版"流程并保留历史版本。

**非功能要求：** 生成 <3 分钟（NFR-010）；报告页加载 <3s；归档存储于 MinIO，冗余备份（FR-081）。
