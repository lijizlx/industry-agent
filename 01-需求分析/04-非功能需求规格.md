## 1. 概述

### 1.1 目的与范围

本规格定义 IndustryAgent v1.0 的非功能需求（NFR-001 ~ NFR-047），全部条目遵循 SMART 原则：**量化、可验证、可追踪**。每条注明验证方法与验证迭代，与《SRS》（IA-RM-002）第 8 章、《RTM》（IA-RM-004）第 3.4 节联动，作为 M5/M6 验收依据。

### 1.2 优先级定义

高（Must，v1.0 必须达标）/ 中（Should，v1.0 尽量达标，允许偏差经评审确认）/ 低（Could，尽力达标）。

### 1.3 验证方法缩写

| 缩写 | 含义 |
|---|---|
| PT | 性能压测（k6/Gatling，I5 专项） |
| LT | 长时间运行监测（可用性统计） |
| CE | 混沌工程演练注入验证 |
| TR | OpenTelemetry 全链路追踪取证 |
| ADR-Q | 审计抽查与审计报告 |
| SA-C | 安全自检/渗透测试（工具+人工用例） |
| CI-Q | CI 质量门禁自动验证（流水线报表） |
| EP | 评估集跑分（I6 量化评估） |
| RV | 评审/走查记录 |
| DO | 部署与运维演练验证 |

## 12. 违约与例外处理

1. 高优先级 NFR 未达标：阻塞 v1.0 发布，须发起人书面豁免方可带病发布（预期不触发）；
2. 中/低优先级 NFR 偏差 ≤10%：经架构评审确认后可纳入遗留问题清单，二期优化；
3. 验证证据（报告、日志、trace 截图）须随验收材料归档 MinIO，保留期同审计日志（≥1 年）；
4. 本规格任何变更走 RTM 变更流程（IA-RM-004 §4），且不得违反第 10 章硬约束。
