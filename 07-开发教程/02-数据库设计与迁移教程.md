## 1. 导读与数据全景图

### 1.1 本教程定位

IndustryAgent 是一个面向 12 英寸晶圆厂的良率根因分析平台（虚拟企业沙盒）。系统要在 4 小时内完成"良率异常 → 根因定位 → 建议生成 → 人工审批 → 8D 报告"的完整闭环。这个闭环涉及五种完全不同的数据形态：

- **结构化业务数据**：用户、设备、配方、批次、审批、审计；
- **高频传感器时序数据**：每台设备每秒多条参数读数，每天千万级；
- **非结构化文档的向量表示**：工艺文档切片后的 embedding，用于 RAG 检索；
- **知识图谱**：设备-工序-参数-缺陷类型之间的关联网络，用于根因路径推理；
- **二进制对象**：缺陷图像、8D 报告 PDF、原始工艺文档。

没有哪一种数据库能同时把这五类数据管好，所以 IndustryAgent 采用"多模数据栈"。本教程回答一个问题：**这五类数据分别放在哪、怎么建、怎么迁、怎么管。**

### 1.3 各存储引擎职责速查

| 存储 | 管什么 | 不管什么 | 典型量级（沙盒） |
|---|---|---|---|
| PostgreSQL 16 (ia_main) | 16 张业务表、事务、外键约束、审计 | 时序大表、文件本体 | 每表 1e2 ~ 1e5 行 |
| TimescaleDB (sensor_readings) | 传感器时序、降采样、压缩、保留 | 强外键校验（超表不支持 FK 引用） | 每天 1e6~1e7 行 |
| pgvector (doc_chunks) | 文档切片 embedding、相似度检索 | 原始文档文件 | 1e3 ~ 1e4 切片 |
| Neo4j 5 | 实体关联网络、多跳路径推理 | 明细事实存储 | 1e3 节点 / 1e4 关系 |
| MinIO | 缺陷图、PDF、原始文档二进制 | 结构化查询 | 1e3 ~ 1e4 对象 |
| Redis | 会话缓存、限流计数、最新值缓存 | 持久事实 | 内存态 |
| Kafka | 传感器事件流、削峰、回放 | 查询 | 每秒 1e3~1e4 条 |

## 2. 环境准备

### 2.1 Docker 启动 PostgreSQL 16 + TimescaleDB + pgvector

镜像选择说明：

- `timescale/timescaledb-ha:pg16`：官方 HA 镜像，**同时内置 TimescaleDB 与 pgvector**，还带 timescaledb-tune 等运维工具，本教程首选；
- `timescale/timescaledb:latest-pg16`：只含 TimescaleDB，不含 pgvector，需要自己编译安装 vector 扩展，不推荐初学者使用。

在宿主机执行（Linux/macOS/Git Bash 均可）：

```bash
# 创建持久化目录
mkdir -p ~/ia-data/pgdata

# 启动数据库容器
docker run -d \
  --name ia-postgres \
  --restart unless-stopped \
  -p 5432:5432 \
  -e POSTGRES_USER=ia \
  -e POSTGRES_PASSWORD=ia_pg_2026 \
  -e POSTGRES_DB=ia_main \
  -e TIMESCALEDB_TELEMETRY=off \
  -v ~/ia-data/pgdata:/home/postgres/pgdata/data \
  timescale/timescaledb-ha:pg16
```

参数逐条解释：

| 参数 | 说明 |
|---|---|
| `--name ia-postgres` | 容器名，后续所有 `docker exec` 都依赖它 |
| `-p 5432:5432` | 宿主机 5432 映射容器 5432；本机已装 PG 的可改 `-p 55432:5432` |
| `POSTGRES_USER/PASSWORD/DB` | 初始超级用户与初始库；HA 镜像默认数据目录在 `/home/postgres/pgdata/data` |
| `TIMESCALEDB_TELEMETRY=off` | 关闭 TimescaleDB 遥测（数据不出域要求） |

> 注意：`timescaledb-ha` 镜像默认以非 root 用户 `postgres` 运行，数据卷属主需要匹配；Linux 上如遇权限问题执行 `sudo chown -R 1000:1000 ~/ia-data/pgdata`。

## 3. 数据建模方法论

### 3.1 从业务流程到 ER 图

先看良率异常处置的完整业务流程（这是所有实体识别的起点）：

```text
[传感器采集] → [FDC监控Agent发现异常] → [生成anomaly_event]
     → [根因Agent分析：查图谱+查时序+RAG检索工艺文档]
     → [生成rootcause_result（Top-3嫌疑）]
     → [建议Agent生成suggestions（调参/停线/维保）]
     → [工艺工程师审批 approvals（批准/驳回）]
     → [执行并记录，报告Agent生成reports_8d]
     → [全程写入audit_logs，相关人收到notifications]
```

从这个流程做**实体识别**（名词→实体，动词→关系/状态）：

| 流程环节 | 抽出的实体 | 说明 |
|---|---|---|
| 人与权限 | users, roles | 谁在系统里、能干什么 |
| 主数据 | equipments, recipes | 设备台账、工艺配方 |
| 生产事实 | lot_batches, wafers | 批次（lot）→ 晶圆（wafer），1:N |
| 质量事实 | defect_records | 每片晶圆的缺陷明细 |
| 事件 | anomaly_events | 一切分析的触发器 |
| 智能体过程 | agent_tasks, rootcause_results | 任务与结论 |
| 人机协同 | suggestions, approvals | 建议与审批闭环 |
| 报告与通知 | reports_8d, notifications | 交付物与触达 |
| 合规 | audit_logs | 全链路留痕 |

### 3.2 核心关系（ER 概览）

```text
users ──< user_roles >── roles                 (M:N)

equipments ──< lot_batches >── recipes         (批次经过设备、执行配方)
lot_batches ──< wafers                         (1:N，一lot=25片)
wafers ──< defect_records                      (1:N)
equipments ──< anomaly_events                  (异常挂在设备+参数上)
lot_batches ──< anomaly_events                 (异常时在制的批次)
anomaly_events ──< agent_tasks                 (一次分析任务)
agent_tasks ──< rootcause_results              (1:N，Top-3即3行)
rootcause_results ──< suggestions              (1:N)
suggestions ──< approvals                      (1:N，可多级审批)
agent_tasks ──< reports_8d                     (1:1)
users ──< notifications                        (1:N)
audit_logs：逻辑关联一切表（resource_type+resource_id，不做物理FK）
```

### 3.3 命名规范速查

| 类别 | 规范 | 正例 | 反例 |
|---|---|---|---|
| 表名 | 复数蛇形，名词 | `defect_records` | `DefectRecord`、`defectRecord` |
| 主键 | `id`，BIGINT（超表除外） | `id BIGSERIAL` | `defect_id` 当主键名 |
| 外键列 | `<被引表单数>_id` | `wafer_id` | `wafersId` |
| 业务编号 | 与主键分离的唯一列 | `lot_no = 'L241008001'` | 直接用业务号当 PK |
| 布尔/状态 | 状态用 VARCHAR+CHECK，不用魔法数字 | `status='pending'` | `status=1` |
| 索引 | `idx_<表>_<列…>` | `idx_wafers_lot_id` | `ix_wafer_1` |
| 唯一约束 | `uq_<表>_<列…>` | `uq_users_username` | — |
| 检查约束 | `ck_<表>_<规则>` | `ck_users_status` | — |
| 时间列 | `*_at`，一律 `TIMESTAMPTZ` | `created_at` | `createTime` |
| JSONB 列 | `*_payload` / `metadata` | `input_payload` | `data`（太泛） |

三条铁律：

1. **时间统一 UTC 存储**（`TIMESTAMPTZ`），展示层再转时区（见第 13 章 FAQ-1）。
2. **主键用代理键**（自增 id），业务编号单独唯一列——业务编号会变，主键不能变。
3. **金额/良率不用 FLOAT**：良率用 `NUMERIC(6,4)`，传感器值才用 `DOUBLE PRECISION`。

## 4. 核心业务表 DDL

本章逐表给出完整 DDL。所有脚本按 2.5 节目录组织，可直接 `psql -f` 执行。
约定：以下所有表（audit_logs、notifications 除外）都带三件套审计字段 `created_at / updated_at / deleted_at`，并统一启用软删除。

### 4.1 用户与角色（01_rbac.sql）

```sql
BEGIN;

-- ============ users：系统用户 ============
CREATE TABLE users (
    id            BIGSERIAL PRIMARY KEY,
    username      VARCHAR(64)  NOT NULL,
    email         VARCHAR(255) NOT NULL,
    password_hash VARCHAR(255) NOT NULL,
    full_name     VARCHAR(128) NOT NULL,
    employee_no   VARCHAR(32)  NOT NULL,
    department    VARCHAR(64)  NOT NULL,
    status        VARCHAR(16)  NOT NULL DEFAULT 'active',
    keycloak_id   VARCHAR(64),
    last_login_at TIMESTAMPTZ,
    created_at    TIMESTAMPTZ  NOT NULL DEFAULT now(),
    updated_at    TIMESTAMPTZ  NOT NULL DEFAULT now(),
    deleted_at    TIMESTAMPTZ,
    CONSTRAINT uq_users_username    UNIQUE (username),
    CONSTRAINT uq_users_email       UNIQUE (email),
    CONSTRAINT uq_users_employee_no UNIQUE (employee_no),
    CONSTRAINT ck_users_status CHECK (status IN ('active', 'disabled', 'locked'))
);
COMMENT ON TABLE users IS '系统用户表（对接Keycloak，keycloak_id为联邦身份标识）';
COMMENT ON COLUMN users.password_hash   IS 'bcrypt哈希；Keycloak接管登录后仅作本地兜底';
COMMENT ON COLUMN users.status          IS 'active/disabled/locked';
COMMENT ON COLUMN users.deleted_at      IS '软删除时间；NULL=未删除';
CREATE INDEX idx_users_department ON users(department) WHERE deleted_at IS NULL;
CREATE INDEX idx_users_keycloak   ON users(keycloak_id) WHERE keycloak_id IS NOT NULL;

-- ============ roles：角色（RBAC） ============
CREATE TABLE roles (
    id          BIGSERIAL PRIMARY KEY,
    code        VARCHAR(64) NOT NULL,
    name        VARCHAR(128) NOT NULL,
    description TEXT,
    is_system   BOOLEAN NOT NULL DEFAULT FALSE,
    created_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
    deleted_at  TIMESTAMPTZ,
    CONSTRAINT uq_roles_code UNIQUE (code)
);
COMMENT ON TABLE roles IS '角色表；is_system=TRUE的为系统预置角色，禁止删除';
COMMENT ON COLUMN roles.code IS '角色编码，如 process_eng/equip_eng/quality_eng/production_supervisor/admin';

-- ============ user_roles：用户-角色关联 ============
CREATE TABLE user_roles (
    id       BIGSERIAL PRIMARY KEY,
    user_id  BIGINT NOT NULL REFERENCES users(id),
    role_id  BIGINT NOT NULL REFERENCES roles(id),
    granted_by  BIGINT REFERENCES users(id),
    granted_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
    created_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
    CONSTRAINT uq_user_roles UNIQUE (user_id, role_id)
);
COMMENT ON TABLE user_roles IS '用户角色关联表；granted_by记录授权人，满足审计要求';
CREATE INDEX idx_user_roles_user ON user_roles(user_id);
CREATE INDEX idx_user_roles_role ON user_roles(role_id);

COMMIT;
```

**设计决策讲解：**

- **为什么软删除用户而不是物理删除**：用户被 `audit_logs.actor_id`、`approvals.approver_id` 等十几张表引用。物理删除要么级联毁掉审计链，要么留下悬空外键。软删除（`deleted_at`）保证历史可追溯——审计系统里"人可以离职，记录不能消失"。
- **为什么状态用 CHECK 而不用 ENUM 类型**：PostgreSQL 的 `ENUM` 类型加值需要 `ALTER TYPE ... ADD VALUE`，且不能在事务里回滚（老版本限制），跨迁移工具兼容性差。`VARCHAR + CHECK` 加新值只需一条可回滚的 `ALTER TABLE ... DROP/ADD CONSTRAINT`。
- **为什么 `user_roles` 不用复合主键**：保留独立 `id` 便于 ORM（Sequelize）与审计日志按行引用。
- **部分索引 `WHERE deleted_at IS NULL`**：90% 查询只关心在职用户，部分索引体积小、写入开销低。

### 4.2 主数据：设备与配方（02_master_data.sql）

```sql
BEGIN;

-- ============ equipments：设备台账 ============
CREATE TABLE equipments (
    id             BIGSERIAL PRIMARY KEY,
    code           VARCHAR(32)  NOT NULL,
    name           VARCHAR(128) NOT NULL,
    equipment_type VARCHAR(32)  NOT NULL,
    stage          VARCHAR(32)  NOT NULL,
    workshop       VARCHAR(64)  NOT NULL,
    vendor         VARCHAR(64),
    model          VARCHAR(64),
    install_date   DATE,
    status         VARCHAR(16)  NOT NULL DEFAULT 'running',
    health_score   NUMERIC(5,2),
    last_maintained_at TIMESTAMPTZ,
    created_at     TIMESTAMPTZ  NOT NULL DEFAULT now(),
    updated_at     TIMESTAMPTZ  NOT NULL DEFAULT now(),
    deleted_at     TIMESTAMPTZ,
    CONSTRAINT uq_equipments_code UNIQUE (code),
    CONSTRAINT ck_equipments_type CHECK (equipment_type IN
        ('litho', 'etch', 'deposition', 'implant', 'clean', 'cmp', 'inspection', 'metrology')),
    CONSTRAINT ck_equipments_status CHECK (status IN
        ('running', 'idle', 'maintenance', 'down', 'retired')),
    CONSTRAINT ck_equipments_health CHECK (health_score BETWEEN 0 AND 100)
);
COMMENT ON TABLE equipments IS '设备台账；code如ETCH-01/LITHO-02';
COMMENT ON COLUMN equipments.stage IS '所属工序： coating/exposure/develop/etch/strip/deposition/cmp/implant/inspection';
COMMENT ON COLUMN equipments.health_score IS '设备健康分0-100，由FDC模型每30分钟刷新';
CREATE INDEX idx_equipments_type_status ON equipments(equipment_type, status) WHERE deleted_at IS NULL;

-- ============ recipes：工艺配方 ============
CREATE TABLE recipes (
    id             BIGSERIAL PRIMARY KEY,
    code           VARCHAR(64)  NOT NULL,
    name           VARCHAR(128) NOT NULL,
    version        VARCHAR(16)  NOT NULL,
    equipment_type VARCHAR(32)  NOT NULL,
    stage          VARCHAR(32)  NOT NULL,
    params         JSONB        NOT NULL DEFAULT '{}',
    status         VARCHAR(16)  NOT NULL DEFAULT 'draft',
    created_by     BIGINT REFERENCES users(id),
    approved_by    BIGINT REFERENCES users(id),
    approved_at    TIMESTAMPTZ,
    created_at     TIMESTAMPTZ  NOT NULL DEFAULT now(),
    updated_at     TIMESTAMPTZ  NOT NULL DEFAULT now(),
    deleted_at     TIMESTAMPTZ,
    CONSTRAINT uq_recipes_code_version UNIQUE (code, version),
    CONSTRAINT ck_recipes_status CHECK (status IN ('draft', 'active', 'retired'))
);
COMMENT ON TABLE recipes IS '工艺配方；params存参数名->设定值映射，如{"rf_power": 1500, "pressure": 0.8}';
COMMENT ON COLUMN recipes.version IS '语义化版本，如v1.2.0；同code多版本共存，仅一个active';
CREATE INDEX idx_recipes_stage ON recipes(stage) WHERE status = 'active';
CREATE INDEX idx_recipes_params_gin ON recipes USING GIN (params jsonb_path_ops);
```

**设计决策讲解：**

- **为什么 `params` 用 JSONB 而不是"每个参数一列"**：刻蚀配方有几十个参数，光刻配方又是另一套参数集合，列会无限膨胀。JSONB + GIN 索引支持"哪些配方把 rf_power 设为 1500"这类查询：

```sql
SELECT code, version FROM recipes
WHERE params @> '{"rf_power": 1500}' AND status = 'active';
```

- **为什么配方版本是 `(code, version)` 唯一而不是 `code` 唯一**：根因分析要回答"这批货当时跑的是哪版配方"，历史版本必须永久保留。
- **`health_score` 为什么 NUMERIC 而不是 INT**：预留小数精度，模型输出 87.35 这类分值。

**设计决策讲解：**

- **`rootcause_results` 用 `(task_id, rank_no)` 唯一约束**：从物理上保证"Top-3 就只有 3 行"，应用层写重了直接报错。
- **`evidence` 存证据链 JSONB**：可解释性是本项目核心指标。每个根因结论必须能回溯：用了哪条图谱路径、哪个时间窗的时序、引用了哪个文档切片。
- **`approvals` 表没有 `updated_at`、没有软删除**：审批是法律意义上的事实记录，**只允许 INSERT，禁止 UPDATE/DELETE**。第 4.7 节会用权限回收硬约束这一点。

```sql
REVOKE UPDATE, DELETE ON audit_logs FROM ia;
REVOKE UPDATE, DELETE ON audit_logs_2026_10 FROM ia;
REVOKE UPDATE, DELETE ON audit_logs_2026_11 FROM ia;

-- 审批表同理
REVOKE UPDATE, DELETE ON approvals FROM ia;

-- 验证：用 ia 账号尝试删除会报 permission denied
-- DELETE FROM audit_logs WHERE id = 1;
-- ERROR:  permission denied for table audit_logs
```

**设计决策讲解：**

- **为什么 `audit_logs` 用声明式分区而不用 hypertable**：审计日志写入频率远低于传感器，但保留周期长（合规要求 ≥ 3 年）。按月 RANGE 分区后，过期数据 `DROP TABLE audit_logs_2024_01` 秒级归档，比 DELETE 快几个量级。
- **为什么 `actor_id` 不加外键**：审计必须记录"已经软删除/离职"的用户行为，且写入不能因为 FK 校验失败而丢失。`actor_type + actor_id` 松耦合引用一切主体（包括 Agent）。
- **`trace_id` 列**：与 OpenTelemetry 的分布式追踪 ID 打通，能从一条审计记录直接跳到完整调用链。

### 4.8 外键与级联策略总表

| 外键 | ON DELETE | 理由 |
|---|---|---|
| user_roles.user_id → users | CASCADE | 用户删则授权无意义 |
| wafers.lot_id → lot_batches | RESTRICT | 有晶圆的批次禁止删（先软删） |
| defect_records.wafer_id → wafers | RESTRICT | 质量事实禁止级联删除 |
| suggestions.result_id → rootcause_results | RESTRICT | 建议链禁止断 |
| notifications.user_id → users | CASCADE | 用户删除则通知无意义 |
| 其余 | 默认 NO ACTION | 一律显式软删除 |

> 未显式指定的外键全部走默认 `NO ACTION`：宁可插入失败报错，也不静默丢数据。

## 5. TimescaleDB 时序建模

### 5.1 时序表与超表创建（06_timeseries.sql）

```sql
-- ============ sensor_readings：传感器时序超表 ============
CREATE TABLE sensor_readings (
    equipment_id   BIGINT       NOT NULL,
    parameter_name VARCHAR(64)  NOT NULL,
    recorded_at    TIMESTAMPTZ  NOT NULL,
    value          DOUBLE PRECISION NOT NULL,
    unit           VARCHAR(32),
    quality        VARCHAR(16)  NOT NULL DEFAULT 'good',
    ingested_at    TIMESTAMPTZ  NOT NULL DEFAULT now(),
    PRIMARY KEY (equipment_id, parameter_name, recorded_at)
);

-- 转为超表：按 recorded_at 分区，chunk 覆盖 1 天
SELECT create_hypertable('sensor_readings', 'recorded_at',
    chunk_time_interval => INTERVAL '1 day',
    if_not_exists => TRUE);

-- 时间倒排索引（最新值查询的关键）
CREATE INDEX idx_sensor_equip_param_time
    ON sensor_readings (equipment_id, parameter_name, recorded_at DESC);

COMMENT ON TABLE sensor_readings IS '传感器时序超表：设备-参数-采集时刻三元组定位一条读数';
COMMENT ON COLUMN sensor_readings.quality IS 'good/suspect/bad：FDC预处理标记，bad数据保留但不参与统计';
COMMENT ON COLUMN sensor_readings.ingested_at IS '入库时间，与recorded_at的差值即管道延迟';
```

**关键设计决策：**

- **为什么主键是 `(equipment_id, parameter_name, recorded_at)` 而不是自增 id**：TimescaleDB 要求超表上所有唯一索引/主键**必须包含分区列 `recorded_at`**。三列复合主键同时天然去重（Kafka at-least-once 重放不产生重复行）。
- **为什么 `equipment_id` 不加 REFERENCES 外键**：超表不支持外键引用（也强烈不建议——每个 chunk 都要维护 FK 校验，写入性能崩塌）。引用完整性由 ETL 层保证：入库前 JOIN equipments 过滤。
- **`recorded_at` vs `ingested_at` 双时间列**：前者是设备侧采集时间（业务时间），后者是入库时间。两者的差是数据管道延迟的核心监控指标（见第 11 章）。
- **chunk 间隔为什么是 1 天**：沙盒每天约 30 设备 × 20 参数 × 1Hz × 86400s ≈ 5000 万行。单日 chunk 压缩后约 1~2 GB，查询基本都带"最近 N 小时"条件，1 天粒度的 chunk 裁剪效率最高。经验法则：**让最常用查询的时间窗口覆盖 1~10 个 chunk**。

### 5.2 压缩策略

```sql
-- 开启压缩：按设备+参数分段，段内按时间排序
ALTER TABLE sensor_readings SET (
    timescaledb.compress,
    timescaledb.compress_segmentby = 'equipment_id, parameter_name',
    timescaledb.compress_orderby   = 'recorded_at DESC'
);

-- 压缩策略：7 天前的 chunk 自动压缩
SELECT add_compression_policy('sensor_readings', INTERVAL '7 days');

-- 查看压缩效果
SELECT
    pg_size_pretty(before_compression_total_bytes) AS before_bytes,
    pg_size_pretty(after_compression_total_bytes)  AS after_bytes,
    ROUND(100.0 * (before_compression_total_bytes - after_compression_total_bytes)
        / NULLIF(before_compression_total_bytes, 0), 1) AS ratio_pct
FROM timescaledb_information.compression_settings cs
JOIN hypertable_compression_stats('sensor_readings') s ON true;

-- 手动压缩指定 chunk（验证用）
SELECT compress_chunk(c)
FROM show_chunks('sensor_readings', older_than => INTERVAL '10 days') c;
```

压缩原理一句话：`compress_segmentby` 指定的列值相同的连续行被合并成一个"段"，其余列转为列式存储。时序数据设备+参数重复度极高，实测压缩比通常 90%+（10 GB 原始数据压到 1 GB 以内）。

**注意**：压缩后的 chunk 数据变为只读。如需修改历史数据，先 `decompress_chunk()`，改完再压缩。这就是为什么压缩窗口要留 7 天——给数据订正留缓冲期。

### 5.4 连续聚合（小时级均值）

```sql
-- ============ sensor_readings_hourly：小时级连续聚合 ============
CREATE MATERIALIZED VIEW sensor_readings_hourly
WITH (timescaledb.continuous) AS
SELECT
    equipment_id,
    parameter_name,
    time_bucket(INTERVAL '1 hour', recorded_at) AS bucket,
    AVG(value)        AS avg_value,
    MIN(value)        AS min_value,
    MAX(value)        AS max_value,
    STDDEV(value)     AS std_value,
    COUNT(*)          AS sample_count,
    COUNT(*) FILTER (WHERE quality = 'bad') AS bad_count
FROM sensor_readings
GROUP BY equipment_id, parameter_name, time_bucket(INTERVAL '1 hour', recorded_at)
WITH NO DATA;

-- 刷新策略：每小时跑一次，刷新 [3小时前, 1小时前] 窗口
-- （1小时 end_offset 给乱序数据留迟到余量）
SELECT add_continuous_aggregate_policy('sensor_readings_hourly',
    start_offset      => INTERVAL '3 hours',
    end_offset        => INTERVAL '1 hour',
    schedule_interval => INTERVAL '30 minutes');

-- 开启实时聚合：未刷新窗口的查询自动下钻明细表补齐
ALTER MATERIALIZED VIEW sensor_readings_hourly
    SET (timescaledb.materialized_only = FALSE);

COMMENT ON MATERIALIZED VIEW sensor_readings_hourly IS '小时级连续聚合：看板/趋势分析的默认数据源';
```

设计要点：

- `WITH NO DATA`：建视图时不回填（大表回填单独跑 `refresh_continuous_aggregate`）；
- `end_offset => 1 hour`：迟到数据（乱序注入的脏数据）不会破坏已聚合结果；
- `bad_count`：把质量标记带进聚合，漂移检测（11 章）直接用。

首次手动回填示例：

```sql
CALL refresh_continuous_aggregate('sensor_readings_hourly',
    NULL, now() - INTERVAL '1 hour');
```

### 5.5 典型时序查询与 EXPLAIN 分析要点

#### 查询 1：区间查询（某设备某参数最近 2 小时明细）

```sql
SELECT time, value
FROM sensor_readings
WHERE equipment_id = 101
  AND parameter_name = 'etch_rf_power'
  AND recorded_at >= now() - INTERVAL '2 hours'
ORDER BY recorded_at;
```

EXPLAIN 分析要点：

```sql
EXPLAIN ANALYZE <上面的查询>;
```

重点看三件事：

1. **Chunk Append / ChunkExclusive**：计划里出现 `Append` 且只挂了 1~2 个 chunk，说明 chunk 裁剪（chunk pruning）生效。如果看到全部 chunk 都被扫描，通常是 `recorded_at` 条件写成了函数包裹（如 `date_trunc('day', recorded_at) = ...`），导致无法裁剪。
2. **Index Scan using idx_sensor_equip_param_time**：确认走到了 5.1 节建的复合索引。
3. **rows removed by filter**：如果这个数字远大于返回行数，说明索引列顺序与查询不匹配。

#### 查询 2：降采样（从连续聚合取 7 天趋势）

```sql
SELECT bucket, avg_value, min_value, max_value
FROM sensor_readings_hourly
WHERE equipment_id = 101
  AND parameter_name = 'etch_rf_power'
  AND bucket >= now() - INTERVAL '7 days'
ORDER BY bucket;
-- 7天明细约50万行，聚合视图只需168行，看板用它
```

#### 查询 3：最新值（DISTINCT ON）

```sql
SELECT DISTINCT ON (equipment_id, parameter_name)
       equipment_id, parameter_name, value, recorded_at
FROM sensor_readings
WHERE recorded_at >= now() - INTERVAL '5 minutes'
ORDER BY equipment_id, parameter_name, recorded_at DESC;
-- 配合 5.1 的 DESC 索引，毫秒级返回所有设备的最新读数
```

#### 查询 4：异常窗口（z-score 突变检测）

```sql
WITH recent AS (
    SELECT equipment_id, parameter_name,
           AVG(value) AS avg_r, STDDEV(value) AS std_r
    FROM sensor_readings
    WHERE recorded_at BETWEEN now() - INTERVAL '10 minutes' AND now()
    GROUP BY equipment_id, parameter_name
),
baseline AS (
    SELECT equipment_id, parameter_name,
           AVG(value) AS avg_b, STDDEV(value) AS std_b
    FROM sensor_readings
    WHERE recorded_at BETWEEN now() - INTERVAL '24 hours' AND now() - INTERVAL '1 hour'
    GROUP BY equipment_id, parameter_name
)
SELECT r.equipment_id, r.parameter_name,
       ROUND(r.avg_r::numeric, 3) AS recent_avg,
       ROUND(b.avg_b::numeric, 3) AS baseline_avg,
       ROUND(((r.avg_r - b.avg_b) / NULLIF(b.std_b, 0))::numeric, 2) AS z_score
FROM recent r
JOIN baseline b USING (equipment_id, parameter_name)
WHERE ABS((r.avg_r - b.avg_b) / NULLIF(b.std_b, 0)) > 3;
```

EXPLAIN 要点：24 小时基线窗口约 30~60 个 chunk，注意 `workers planned` 是否出现（并行扫描）；生产上建议把基线查询改为读 `sensor_readings_hourly` 聚合视图，扫描量降低两个数量级。

## 6. pgvector RAG 表设计

### 6.1 doc_chunks 表（07_vector.sql）

```sql
-- ============ doc_chunks：工艺文档切片向量表 ============
CREATE TABLE doc_chunks (
    id               BIGSERIAL PRIMARY KEY,
    doc_id           VARCHAR(64)  NOT NULL,
    source_bucket    VARCHAR(64)  NOT NULL DEFAULT 'process-docs',
    source_object_key VARCHAR(512) NOT NULL,
    chunk_index      INT          NOT NULL,
    title            VARCHAR(256),
    content          TEXT         NOT NULL,
    token_count      INT,
    embedding        vector(1536) NOT NULL,
    metadata         JSONB        NOT NULL DEFAULT '{}',
    embedding_model  VARCHAR(64)  NOT NULL DEFAULT 'text-embedding-3-small',
    created_at       TIMESTAMPTZ  NOT NULL DEFAULT now(),
    CONSTRAINT uq_doc_chunks_doc_idx UNIQUE (doc_id, chunk_index)
);

COMMENT ON TABLE doc_chunks IS '工艺文档切片向量表：RAG检索的唯一数据源';
COMMENT ON COLUMN doc_chunks.doc_id IS '文档逻辑ID（源文件去掉扩展名的md5前16位）';
COMMENT ON COLUMN doc_chunks.source_object_key IS 'MinIO process-docs桶中的原始文件对象键';
COMMENT ON COLUMN doc_chunks.chunk_index IS '切片序号，从0开始，按文档内顺序';
COMMENT ON COLUMN doc_chunks.embedding IS '1536维，与embedding_model强绑定，换模型必须整表重嵌入';
COMMENT ON COLUMN doc_chunks.metadata IS '自定义元数据：{"stage":"etch","equipment_type":"etch","version":"v2"}';

-- 按元数据过滤后再检索（混合检索的过滤层）
CREATE INDEX idx_doc_chunks_metadata ON doc_chunks USING GIN (metadata jsonb_path_ops);
CREATE INDEX idx_doc_chunks_doc_id   ON doc_chunks(doc_id);
```

**关键设计决策：**

- **维度 1536 与模型强绑定**：OpenAI `text-embedding-3-small`、智谱 `embedding-3` 等主流模型输出 1536 维。`vector(1536)` 在类型层面锁死维度——插入 1024 维向量会直接报错 `expected 1536 dimensions, not 1024`。
- **`embedding_model` 列**：向量不可比是 RAG 最隐蔽的坑（不同模型的向量空间完全不同）。带上模型标识，检索 SQL 里 `WHERE embedding_model = $model` 强制过滤。
- **`(doc_id, chunk_index)` 唯一**：重嵌入时按 doc_id 先删后插，不会产生重复切片。

### 6.2 索引：IVFFlat vs HNSW

```sql
-- ===== 方案A：IVFFlat（倒排文件平坦索引）=====
-- 前提：必须先插入数据（建议 ≥ lists × 10 = 1000 行）再建，否则聚类中心质量差
CREATE INDEX idx_doc_chunks_ivfflat ON doc_chunks
USING ivfflat (embedding vector_cosine_ops)
WITH (lists = 100);
ANALYZE doc_chunks;

-- ===== 方案B：HNSW（分层可导航小世界图，推荐）=====
CREATE INDEX idx_doc_chunks_hnsw ON doc_chunks
USING hnsw (embedding vector_cosine_ops)
WITH (m = 16, ef_construction = 200);
ANALYZE doc_chunks;
```

参数选择依据：

| 参数 | 本项目取值 | 选择理由 |
|---|---|---|
| 距离算子 | `vector_cosine_ops` | 文本语义相似度标准做法，查询用 `<=>` 余弦距离 |
| IVFFlat `lists` | 100 | 经验公式 `rows / 1000`；1万切片→10~100，取100兼顾召回与速度 |
| IVFFlat `probes`（查询时） | 10 | `SET ivfflat.probes = 10;` lists的10%，召回率可达95%+ |
| HNSW `m` | 16 | 每节点连接数，16是质量/内存平衡点 |
| HNSW `ef_construction` | 200 | 建索引慢一点，换来更高质量的图；查询时 `SET hnsw.ef_search = 40` |

**选型结论（本项目）**：文档量 1e3~1e4 级、追求召回率、写入少（文档更新频率低）——**HNSW 更合适**。IVFFlat 优势是建索引快、内存占用略小，适合千万级以上向量且可接受重训。

### 6.3 相似度检索查询

```sql
-- $1 为查询文本的 embedding（应用层生成后以 '[0.1,0.2,...]' 字符串或参数化传入）
-- Top-5 余弦相似度检索（含元数据过滤的混合检索）
SET hnsw.ef_search = 40;

SELECT
    doc_id,
    chunk_index,
    title,
    LEFT(content, 120) AS preview,
    1 - (embedding <=> '[0.12, -0.45, ...]'::vector) AS similarity,
    metadata->>'stage' AS stage
FROM doc_chunks
WHERE embedding_model = 'text-embedding-3-small'
  AND metadata @> '{"stage": "etch"}'
ORDER BY embedding <=> '[0.12, -0.45, ...]'::vector
LIMIT 5;
```

> 坑位提示：`ORDER BY embedding <=> $1` 必须与索引的 `vector_cosine_ops` 算子一致。如果索引建了 `vector_l2_ops` 而查询用 `<=>`，索引不生效，全表顺序扫描。

### 6.4 效果验证

```sql
-- 1. 索引是否被使用
EXPLAIN ANALYZE
SELECT doc_id FROM doc_chunks
ORDER BY embedding <=> (SELECT embedding FROM doc_chunks WHERE id = 42)
LIMIT 5;
-- 期望出现：Index Scan using idx_doc_chunks_hnsw

-- 2. 召回率粗测：取100个已知chunk，用自身向量查询Top-1是否命中原chunk
WITH probe AS (
    SELECT id, embedding FROM doc_chunks ORDER BY random() LIMIT 100
),
hits AS (
    SELECT p.id AS origin_id,
           (SELECT d.id FROM doc_chunks d
            WHERE d.id <> p.id
            ORDER BY d.embedding <=> p.embedding LIMIT 1) AS nn_id
    FROM probe p
)
SELECT COUNT(*) FILTER (WHERE ABS(origin_id - nn_id) <= 5) AS near_hits,
       COUNT(*) AS total
FROM hits;
-- 近邻命中（同一文档相邻chunk）占比高即语义空间健康
```

## 7. Neo4j 图谱建模

### 7.1 图模型设计

图谱回答的问题是关系推理型的："这个参数异常会影响哪些工序环节？""这种缺陷历史上和哪些设备强相关？"——这是关系型 SQL 的弱项。

```text
节点（5类）：
  (:Equipment {code, name, type, stage, status})
  (:Stage     {name})                     -- 工序：涂胶/曝光/刻蚀/沉积/清洗/CMP...
  (:Parameter {name, unit, normal_range}) -- 工艺参数：etch_rf_power/pressure...
  (:DefectType {name, severity})          -- 缺陷类型：微粒/微桥/划伤/图案缺失...
  (:Lot       {lotId, product, status})   -- 生产批次（镜像PG关键字段）

关系（7类）：
  (:Equipment)-[:BELONGS_TO]->(:Stage)          设备属于工序
  (:Stage)-[:HAS_PARAMETER]->(:Parameter)       工序涉及参数
  (:Equipment)-[:MONITORS]->(:Parameter)        设备采集该参数
  (:Parameter)-[:AFFECTS {confidence}]->(:DefectType)   参数影响缺陷类型（知识库核心）
  (:DefectType)-[:OCCURRED_ON {count}]->(:Equipment)    缺陷发生设备统计
  (:Lot)-[:PROCESSED_BY {at}]->(:Equipment)     批次流经设备（时序路径）
  (:Equipment)-[:FEEDS]->(:Equipment)           工序上下游衔接（ETCH-01 FEEDS STRIP-02）
```

#### 方式二：Python 批量导入（推荐，带事务与批处理）

```python
# scripts/graph_import.py
"""从 PG 读取主数据与生产事实，批量写入 Neo4j。"""
import os
import psycopg2
from neo4j import GraphDatabase

PG_DSN = os.getenv("PG_DSN", "postgresql://ia:ia_pg_2026@localhost:5432/ia_main")
NEO4J_URI = os.getenv("NEO4J_URI", "bolt://localhost:7687")
NEO4J_AUTH = ("neo4j", "ia_neo4j_2026")


def fetch_rows(sql):
    with psycopg2.connect(PG_DSN) as conn, conn.cursor() as cur:
        cur.execute(sql)
        cols = [d[0] for d in cur.description]
        return [dict(zip(cols, row)) for row in cur.fetchall()]


def batch_write(driver, cypher, rows, key, batch_size=1000):
    with driver.session() as session:
        buf = []
        total = 0
        for row in rows:
            buf.append(row)
            if len(buf) >= batch_size:
                session.execute_write(
                    lambda tx: tx.run(cypher, **{key: buf}).consume())
                total += len(buf)
                print(f"  wrote {total} rows")
                buf = []
        if buf:
            session.execute_write(
                lambda tx: tx.run(cypher, **{key: buf}).consume())
            total += len(buf)
        return total


EQUIP_CYPHER = """
UNWIND $rows AS r
MERGE (e:Equipment {code: r.code})
SET e.name = r.name, e.type = r.equipment_type,
    e.stage = r.stage, e.status = r.status
"""

ROUTE_CYPHER = """
UNWIND $rows AS r
MATCH (l:Lot {lotId: r.lot_no})
MATCH (e:Equipment {code: r.equip_code})
CREATE (l)-[:PROCESSED_BY {at: datetime(r.at)}]->(e)
"""


def main():
    driver = GraphDatabase.driver(NEO4J_URI, auth=NEO4J_AUTH)
    with driver.session() as s:
        s.run("CREATE CONSTRAINT equipment_code IF NOT EXISTS "
              "FOR (e:Equipment) REQUIRE e.code IS UNIQUE").consume()
        s.run("CREATE CONSTRAINT lot_id IF NOT EXISTS "
              "FOR (l:Lot) REQUIRE l.lotId IS UNIQUE").consume()

    equips = fetch_rows(
        "SELECT code, name, equipment_type, stage, status "
        "FROM equipments WHERE deleted_at IS NULL")
    print("equipments:", batch_write(driver, EQUIP_CYPHER, equips, "rows"))

    routes = fetch_rows("""
        SELECT lb.lot_no, e.code AS equip_code,
               lb.updated_at::text AS at
        FROM lot_batches lb
        JOIN equipments e ON e.id = lb.current_equipment_id
        WHERE lb.deleted_at IS NULL
    """)
    print("routes:", batch_write(driver, ROUTE_CYPHER, routes, "rows"))
    driver.close()


if __name__ == "__main__":
    main()
```

> 事务要点：Neo4j 的 `execute_write` 是自动重试的事务函数；批处理每批 1000 条既能吃满吞吐，又能保证单批失败可重试（`MERGE` 幂等，`CREATE` 不幂等——可重跑的导入一律用 `MERGE`）。

### 7.4 典型图谱查询

#### 查询 1：某参数异常的下游影响路径

```cypher
-- 刻蚀RF功率异常 → 影响哪些缺陷类型 → 这些缺陷在哪些设备高发 →波及哪些批次
MATCH (p:Parameter {name: 'etch_rf_power'})-[a:AFFECTS]->(d:DefectType),
      (d)-[o:OCCURRED_ON]->(e:Equipment),
      (l:Lot)-[:PROCESSED_BY]->(e)
WHERE l.status = 'processing'
RETURN p.name AS parameter,
       d.name AS defect_type,
       a.confidence AS affect_confidence,
       e.code AS equipment,
       o.count AS defect_count,
       collect(DISTINCT l.lotId) AS active_lots
ORDER BY a.confidence DESC, o.count DESC
LIMIT 20;
```

#### 查询 2：某缺陷类型关联设备 Top-N

```cypher
-- 微粒缺陷历史上最相关的设备Top-5（按共现次数与置信度加权）
MATCH (d:DefectType {name: '微粒'})<-[a:AFFECTS]-(p:Parameter)-[:MONITORS]-(e:Equipment)
WITH e, sum(a.confidence) AS weight, collect(DISTINCT p.name) AS params
ORDER BY weight DESC LIMIT 5
RETURN e.code AS equipment_code, e.name AS equipment_name,
       round(weight, 3) AS weight, params;
```

#### 查询 3：两实体之间的关联路径（根因推理可解释性）

```cypher
-- 异常设备与问题批次之间，3跳以内的最短关联路径
MATCH path = shortestPath(
  (e:Equipment {code: 'ETCH-01'})-[*..5]-(l:Lot {lotId: 'L241008001'})
)
RETURN [n IN nodes(path) | coalesce(n.code, n.name, n.lotId)] AS path_nodes,
       [r IN relationships(path) | type(r)] AS path_rels,
       length(path) AS hops;
-- 返回示例：['ETCH-01','etch_rf_power','微粒','L241008001']
--           ['MONITORS','AFFECTS','OCCURRED_ON']
```

#### 查询 4：根因 Agent 的图证据子查询（供 MCP 工具封装）

```cypher
// 给定设备+参数，产出一条可读的证据链（输出直接进 rootcause_results.evidence）
MATCH (e:Equipment {code: $equip_code})-[:MONITORS]->(p:Parameter {name: $param})
OPTIONAL MATCH (p)-[a:AFFECTS]->(d:DefectType)
RETURN e.code AS equip, p.name AS param,
       collect({defect: d.name, confidence: a.confidence}) AS affects;
```

## 9. 数据迁移管理

### 9.1 为什么禁止手工改表

真实教训（也是本项目的 ADR 结论）：开发阶段某人手工在测试库 `ALTER TABLE users ADD COLUMN phone VARCHAR(32)`，代码合并后其他环境报 `column users.phone does not exist`，排查 2 小时；更严重的是生产库结构与迁移历史不一致后，**所有后续迁移都可能失败**。

结论：**schema 的唯一真相来源是迁移文件**，环境差异只允许通过迁移序列收敛。


```js
 *  注意：CONCURRENTLY 不能在事务里跑，sequelize-cli 需关闭自动事务。 */

module.exports = {
  async up(queryInterface) {
    await queryInterface.sequelize.query(`
      CREATE INDEX CONCURRENTLY IF NOT EXISTS idx_defect_records_type_time
        ON defect_records (defect_type, detected_at DESC)
        WHERE deleted_at IS NULL;
    `, { transaction: null });   // 关键：退出迁移框架的事务包裹
  },

    await queryInterface.sequelize.query(`
      DROP INDEX CONCURRENTLY IF EXISTS idx_defect_records_type_time;
```

> 坑位提示：`CREATE INDEX CONCURRENTLY` 失败后会留下 `INVALID` 索引，必须先 `DROP` 再重建，否则索引永远不生效且占空间。检查：`SELECT indexrelid::regclass FROM pg_index WHERE NOT indisvalid;`

### 9.6 迁移流程规范

```text
开发 → 评审 → CI执行 → 生产两阶段兼容发布
```


### 9.7 生产两阶段兼容发布规范（红线）

以"给 `wafers.yield_rate` 加 NOT NULL + CHECK 约束，且删除旧列 `yield_pct`"为例，**分 3 个版本完成**：

| 版本 | 动作 | 迁移内容 | 兼容性 |
|---|---|---|---|
| V1.2.0 | 加列 | `ADD COLUMN yield_rate NUMERIC(6,4)`（可空） | 旧代码不认识新列，照常跑 |
| V1.3.0 | 回填+约束 | 应用层/脚本回填历史数据；`ADD CONSTRAINT ... CHECK (yield_rate IS NULL OR yield_rate BETWEEN 0 AND 1) NOT VALID`；`VALIDATE CONSTRAINT` | 新旧代码并存，写新旧两列或双读 |
| V1.4.0 | 收紧+删旧 | `ALTER COLUMN yield_rate SET NOT NULL`（此时数据已满）；确认无引用后 `DROP COLUMN yield_pct` | 只跑新代码 |

V1.3.0 的关键 SQL（NOT VALID + VALIDATE 两步走，避免长锁表）：

```sql
-- 第一步：加约束但不校验存量数据（瞬间完成，只锁表一瞬间）
ALTER TABLE wafers
  ADD CONSTRAINT ck_wafers_yield CHECK (yield_rate IS NULL OR yield_rate BETWEEN 0 AND 1)
  NOT VALID;

-- 第二步：后台校验存量（拿 SHARE UPDATE EXCLUSIVE 锁，不阻塞读写）
ALTER TABLE wafers VALIDATE CONSTRAINT ck_wafers_yield;
```

**三条红线：**

1. 禁止在同一版本里"加列 + 设 NOT NULL"（存量行会让后者直接失败或长时间锁表）。
2. 禁止在业务低峰外执行 `SET NOT NULL`、`DROP COLUMN`、改列类型。
3. `DROP COLUMN` 前必须确认 ≥ 1 个版本周期内无代码引用（全仓库 grep + 灰度观察）。

### 10.3 传感器时序合成（周期 + 噪声 + 漂移注入）

```python
# scripts/generate_sensor_timeseries.py
"""生成带日周期、噪声、缓慢漂移的传感器时序，批量 COPY 进 TimescaleDB。
用法：python scripts/generate_sensor_timeseries.py --days 7 --hz 1.0
"""
import argparse
import io
from datetime import datetime, timedelta, timezone

import numpy as np
import psycopg2

PG_DSN = "postgresql://ia:ia_pg_2026@localhost:5432/ia_main"

# 参数模板：参数名 -> (基准值, 日周期振幅, 噪声sigma, 单位, 漂移率/天)
PARAMS = {
    "etch": {
        "rf_power":   (1500.0, 30.0, 8.0,  "W",  2.0),
        "pressure":   (0.8,    0.02, 0.01, "Pa", 0.001),
        "gas_flow":   (120.0,  5.0,  2.0,  "sccm", 0.3),
        "dc_bias":    (350.0,  10.0, 4.0,  "V",  0.8),
    },
    "litho": {
        "exposure_dose": (45.0, 0.5, 0.15, "mJ/cm2", 0.02),
        "scan_speed":    (600.0, 10.0, 3.0, "mm/s", 0.5),
    },
    "deposition": {
        "temp":     (350.0, 5.0, 1.5, "C", 0.3),
        "pressure": (4.0,   0.1, 0.03, "Torr", 0.01),
    },
    "clean": {
        "temp": (65.0, 1.0, 0.3, "C", 0.05),
    },
    "default": {
        "temp": (50.0, 2.0, 0.5, "C", 0.1),
    },
}

EQUIP_TYPE_BY_CODE = {}   # 由查询填充


def load_equips(cur):
    cur.execute(
        "SELECT id, code, equipment_type FROM equipments "
        "WHERE status IN ('running','idle') AND deleted_at IS NULL")
    rows = cur.fetchall()
    for eid, code, etype in rows:
        EQUIP_TYPE_BY_CODE[eid] = etype
    return rows


def gen_series(base, amp, sigma, drift_per_day, n, t0, step_sec):
    """value(t) = base + amp*sin(日周期) + N(0,sigma) + drift*t"""
    t = np.arange(n) * step_sec
    daily_phase = 2 * np.pi * (t / 86400.0)
    rng = np.random.default_rng(seed=int(t0.timestamp()))
    noise = rng.normal(0.0, sigma, n)
    drift = drift_per_day * (t / 86400.0)
    return base + amp * np.sin(daily_phase) + noise + drift


def copy_batch(cur, buf):
    buf.seek(0)
    cur.copy_expert(
        "COPY sensor_readings "
        "(equipment_id, parameter_name, recorded_at, value, unit, quality, "
        " ingested_at) FROM STDIN WITH (FORMAT csv)",
        buf)


def main():
    ap = argparse.ArgumentParser()
    ap.add_argument("--days", type=int, default=7)
    ap.add_argument("--hz", type=float, default=1.0,
                    help="采样频率，1.0=每秒1条；0.01=每100秒1条(快速演示)")
    args = ap.parse_args()

    step_sec = 1.0 / args.hz
    n = int(args.days * 86400 / step_sec)
    t0 = datetime.now(timezone.utc) - timedelta(days=args.days)

    conn = psycopg2.connect(PG_DSN)
    with conn, conn.cursor() as cur:
        equips = load_equips(cur)
        print(f"equips={len(equips)} samples_per_param={n}")

        buf = io.StringIO()
        total, batch = 0, 0
        for eid, code, etype in equips:
            params = PARAMS.get(etype, PARAMS["default"])
            for pname, (base, amp, sigma, unit, drift) in params.items():
                series = gen_series(base, amp, sigma, drift, n, t0, step_sec)
                for i, v in enumerate(series):
                    ts = t0 + timedelta(seconds=i * step_sec)
                    buf.write(
                        f"{eid},{pname},{ts.isoformat()},{v:.4f},{unit},"
                        f"good,{ts.isoformat()}\n")
                    batch += 1
                    if batch >= 500_000:
                        copy_batch(cur, buf)
                        total += batch
                        print(f"  copied {total} rows...")
                        buf = io.StringIO()
                        batch = 0
        if batch:
            copy_batch(cur, buf)
            total += batch
        print(f"done, total={total}")
        cur.execute("SELECT count(*), min(recorded_at), max(recorded_at) "
                    "FROM sensor_readings")
        print(cur.fetchone())
    conn.commit()


if __name__ == "__main__":
    main()
```

### 10.4 脏数据注入器（五类注入完整函数）

```python
# scripts/dirty_data_injector.py
"""五类脏数据注入器：缺失/漂移/尖峰/重复/乱序。
注入目标为原始staging表 sensor_readings_raw（含id列，允许真重复），
由清洗任务去重修复后写入超表 sensor_readings。
用法：python scripts/dirty_data_injector.py --type all --ratio 0.02
"""
import argparse
import random
from datetime import timedelta

import numpy as np
import psycopg2
import psycopg2.extras

PG_DSN = "postgresql://ia:ia_pg_2026@localhost:5432/ia_main"


def inject_missing(cur, ratio=0.02):
    """1) 缺失值：随机删除 + 30分钟连续缺失（模拟断流）"""
    cur.execute("SELECT count(*) FROM sensor_readings_raw")
    total = cur.fetchone()[0]
    n_del = int(total * ratio / 2)
    cur.execute(
        """DELETE FROM sensor_readings_raw WHERE id IN
           (SELECT id FROM sensor_readings_raw
            TABLESAMPLE SYSTEM (%s))""", (ratio * 50,))
    cur.execute(
        """SELECT equipment_id, parameter_name, recorded_at
           FROM sensor_readings_raw
           WHERE recorded_at > now() - INTERVAL '2 days'
           ORDER BY random() LIMIT 5""")
    for eid, pname, ts in cur.fetchall():
        cur.execute(
            "DELETE FROM sensor_readings_raw "
            "WHERE equipment_id=%s AND parameter_name=%s "
            "AND recorded_at BETWEEN %s AND %s",
            (eid, pname, ts, ts + timedelta(minutes=30)))
    print(f"[missing] deleted ~{n_del} random + 5 x 30min gaps")


def inject_drift(cur, ratio=0.02):
    """2) 均值漂移：随机选5个设备-参数，最近6小时读数整体抬高3sigma"""
    cur.execute(
        """SELECT DISTINCT equipment_id, parameter_name
           FROM sensor_readings_raw
           WHERE recorded_at > now() - INTERVAL '1 day' LIMIT 5""")
    for eid, pname in cur.fetchall():
        cur.execute(
            """UPDATE sensor_readings_raw SET value = value * 1.15,
                   quality = 'suspect'
               WHERE equipment_id=%s AND parameter_name=%s
                 AND recorded_at > now() - INTERVAL '6 hours'""",
            (eid, pname))
    print(f"[drift] +15% mean shift on 5 series (last 6h, marked suspect)")


def inject_spike(cur, ratio=0.001):
    """3) 尖峰：随机点上叠加5~10倍sigma的脉冲"""
    cur.execute(
        """UPDATE sensor_readings_raw
           SET value = value + (random()*10-5) * 50, quality='suspect'
           WHERE id IN (SELECT id FROM sensor_readings_raw
                        TABLESAMPLE SYSTEM (%s))""", (ratio * 100,))
    print(f"[spike] injected random spikes on ~{ratio:.2%} rows")


def inject_duplicate(cur, n=500):
    """4) 重复：整行复制（staging表无唯一约束，模拟Kafka重放）"""
    cur.execute(
        """INSERT INTO sensor_readings_raw
             (equipment_id, parameter_name, recorded_at, value, unit, quality, ingested_at)
           SELECT equipment_id, parameter_name, recorded_at, value, unit,
                  'suspect', now()
           FROM sensor_readings_raw ORDER BY random() LIMIT %s""", (n,))
    print(f"[duplicate] duplicated {n} rows with quality='suspect'")


def inject_out_of_order(cur, n=200):
    """5) 乱序：把n条记录的recorded_at改到过去2小时（模拟延迟到达）"""
    cur.execute(
        """UPDATE sensor_readings_raw
           SET recorded_at = now() - (random() * interval '2 hours'),
               quality = 'suspect'
           WHERE id IN (SELECT id FROM sensor_readings_raw
                        WHERE recorded_at > now() - INTERVAL '1 day'
                        ORDER BY random() LIMIT %s)""", (n,))
    print(f"[out_of_order] rewrote {n} timestamps into the past 2h")


def main():
    ap = argparse.ArgumentParser()
    ap.add_argument("--type", default="all",
                    choices=["all", "missing", "drift", "spike",
                             "duplicate", "out_of_order"])
    ap.add_argument("--ratio", type=float, default=0.02)
    args = ap.parse_args()

    injectors = {
        "missing": lambda cur: inject_missing(cur, args.ratio),
        "drift": lambda cur: inject_drift(cur, args.ratio),
        "spike": lambda cur: inject_spike(cur, args.ratio / 10),
        "duplicate": lambda cur: inject_duplicate(cur),
        "out_of_order": lambda cur: inject_out_of_order(cur),
    }
    targets = (injectors if args.type == "all"
               else {args.type: injectors[args.type]})

    conn = psycopg2.connect(PG_DSN)
    with conn, conn.cursor() as cur:
        # 保证staging表存在
        cur.execute("""
            CREATE TABLE IF NOT EXISTS sensor_readings_raw (
                id BIGSERIAL PRIMARY KEY,
                equipment_id BIGINT NOT NULL,
                parameter_name VARCHAR(64) NOT NULL,
                recorded_at TIMESTAMPTZ NOT NULL,
                value DOUBLE PRECISION NOT NULL,
                unit VARCHAR(32),
                quality VARCHAR(16) NOT NULL DEFAULT 'good',
                ingested_at TIMESTAMPTZ NOT NULL DEFAULT now()
            );
            TRUNCATE sensor_readings_raw;
            INSERT INTO sensor_readings_raw
                (equipment_id, parameter_name, recorded_at, value, unit, quality)
            SELECT equipment_id, parameter_name, recorded_at, value, unit, quality
            FROM sensor_readings
            WHERE recorded_at > now() - INTERVAL '1 day';
        """)
        for name, fn in targets.items():
            fn(cur)
    conn.commit()
    print("injection committed (staging=sensor_readings_raw)")


if __name__ == "__main__":
    main()
```

## 11. 数据质量监控

### 11.1 数据健康检查 SQL 集（db/quality/health_checks.sql）

```sql
-- ===== 检查1：断流检测（某设备-参数超过90秒无数据） =====
-- 期望采样间隔≤10秒，gap>90s 即断流
WITH gaps AS (
    SELECT equipment_id, parameter_name, recorded_at,
           recorded_at - LAG(recorded_at) OVER (
               PARTITION BY equipment_id, parameter_name
               ORDER BY recorded_at) AS gap
    FROM sensor_readings
    WHERE recorded_at > now() - INTERVAL '1 hour'
)
SELECT equipment_id, parameter_name,
       MAX(gap) AS max_gap,
       COUNT(*) FILTER (WHERE gap > INTERVAL '90 seconds') AS gap_count
FROM gaps
GROUP BY equipment_id, parameter_name
HAVING COUNT(*) FILTER (WHERE gap > INTERVAL '90 seconds') > 0
ORDER BY gap_count DESC;

-- ===== 检查2：重复检测（staging表真重复） =====
SELECT equipment_id, parameter_name, recorded_at, COUNT(*) AS dup
FROM sensor_readings_raw
WHERE ingested_at > now() - INTERVAL '1 hour'
GROUP BY equipment_id, parameter_name, recorded_at
HAVING COUNT(*) > 1
ORDER BY dup DESC
LIMIT 50;

-- ===== 检查3：漂移检测（近1h vs 前24h基线，z-score>3） =====
WITH recent AS (
    SELECT equipment_id, parameter_name,
           AVG(value) AS avg_r, COUNT(*) AS n
    FROM sensor_readings
    WHERE recorded_at > now() - INTERVAL '1 hour'
      AND quality = 'good'
    GROUP BY equipment_id, parameter_name
    HAVING COUNT(*) > 100
)
SELECT r.equipment_id, r.parameter_name,
       ROUND(r.avg_r::numeric, 4) AS recent_avg,
       ROUND(h.avg_value::numeric, 4) AS baseline_24h_avg,
       ROUND(h.std_value::numeric, 4) AS baseline_std,
       ROUND(((r.avg_r - h.avg_value)
              / NULLIF(h.std_value, 0))::numeric, 2) AS z_score
FROM recent r
JOIN sensor_readings_hourly h
  ON h.equipment_id = r.equipment_id
 AND h.parameter_name = r.parameter_name
 AND h.bucket = time_bucket(INTERVAL '24 hours', now() - INTERVAL '25 hours')
WHERE ABS((r.avg_r - h.avg_value) / NULLIF(h.std_value, 0)) > 3
ORDER BY ABS((r.avg_r - h.avg_value) / NULLIF(h.std_value, 0)) DESC;

-- ===== 检查4：管道延迟（ingested_at - recorded_at 分布） =====
SELECT
    percentile_disc(0.5)  WITHIN GROUP (ORDER BY EXTRACT(EPOCH FROM (ingested_at - recorded_at))) AS p50_sec,
    percentile_disc(0.95) WITHIN GROUP (ORDER BY EXTRACT(EPOCH FROM (ingested_at - recorded_at))) AS p95_sec,
    MAX(EXTRACT(EPOCH FROM (ingested_at - recorded_at))) AS max_sec
FROM sensor_readings
WHERE ingested_at > now() - INTERVAL '10 minutes';

-- ===== 检查5：坏值率（quality='bad'占比突增） =====
SELECT equipment_id, parameter_name,
       ROUND(100.0 * bad_count / NULLIF(sample_count, 0), 2) AS bad_pct
FROM sensor_readings_hourly
WHERE bucket = date_trunc('hour', now()) - INTERVAL '1 hour'
  AND bad_count::float / NULLIF(sample_count, 0) > 0.05
ORDER BY bad_pct DESC;

-- ===== 检查6：孤儿外键（超表无FK，人工对账） =====
SELECT DISTINCT s.equipment_id
FROM sensor_readings s
LEFT JOIN equipments e ON e.id = s.equipment_id
WHERE s.recorded_at > now() - INTERVAL '1 day'
  AND e.id IS NULL;
```

## 13. 常见坑 FAQ（12 条）

**FAQ-1 时区：为什么必须 UTC，怎么转？**
所有 `TIMESTAMPTZ` 库内统一 UTC。PG 的 `TIMESTAMPTZ` 存储时是 UTC 秒值，展示时按会话时区转换。踩坑场景：应用容器时区是 CST，写入 `TIMESTAMP`（无时区）列，跨服务读取差 8 小时。规则：列类型一律 `TIMESTAMPTZ`；应用层传 ISO8601 带时区字符串（`2026-10-15T08:00:00+08:00`）；展示层 `SET timezone='Asia/Shanghai'` 或前端转换。

**FAQ-2 hypertable 主键/唯一索引必须包含分区键**
`ERROR: cannot create a unique index without the partitioning column`。任何超表上的 UNIQUE/PK 都必须含 `recorded_at`。反例：想给 `sensor_readings` 加 `UNIQUE(id)`——不允许；去重语义改由 `(equipment_id, parameter_name, recorded_at)` 复合主键承载。

**FAQ-3 vector 维度不匹配**
`ERROR: expected 1536 dimensions, not 1024`。原因：换了 embedding 模型（如 3-small→3-large，1536→3072）没重建表。处置：新模型→新建列/表→全量重嵌入→切换；永远不要在同一列混两个模型的向量。

**FAQ-4 HNSW 索引没生效，查询全表扫描**
检查三点：① 查询排序算子 `<=>` 是否与索引的 `vector_cosine_ops` 匹配（用 `<->` 配 cosine 索引不生效）；② 建完索引是否 `ANALYZE`；③ 旧的 IVFFlat 索引是否还在（优化器可能选错）。

**FAQ-5 压缩后的 chunk 无法更新**
`ERROR: cannot update a compressed chunk`。历史数据订正流程：`SELECT decompress_chunk('_timescaledb_internal/_hyper_X_Y_chunk');` → UPDATE → `SELECT compress_chunk(...)`。批量订正后记得重新 `ANALYZE`。

**FAQ-6 Neo4j 写入报 MaxRetriesException**
单条循环 `session.run()` 百万级写入必然超时。用 `execute_write` 事务函数 + `UNWIND $rows` 批处理（每批 1000~10000），并确认 `MERGE`（幂等可重试）而非 `CREATE`。

**FAQ-7 连续聚合查不到最新数据**
默认 `materialized_only=true` 时，未刷新窗口返回空。两种解法：`ALTER MATERIALIZED VIEW ... SET (timescaledb.materialized_only = FALSE)` 开实时聚合；或手动 `CALL refresh_continuous_aggregate(...)`。本项目开了实时聚合。

**FAQ-8 COPY 报 invalid byte sequence**
CSV 文本含非法 UTF-8 字节（Windows 下生成的 GBK 文件）。转换：`iconv -f GBK -t UTF-8 in.csv > out.csv`；或 COPY 时用 `WITH (FORMAT csv, ENCODING 'GBK')`（需客户端编码配合）。

**FAQ-9 ivfflat 索引建在空表上**
空表建 IVFFlat，聚类中心是随机的，之后插入再多数据召回率也差。规则：IVFFlat 必须在数据 ≥ `lists × 10` 后建。HNSW 无此问题（增量构建）。

**FAQ-10 Sequelize 迁移在 CI 报 connection refused**
CI 里 PG 是服务容器，host 不是 127.0.0.1。GitHub Actions 服务容器映射到 `postgres` 主机名；config.json 里 development 写死了 `127.0.0.1`。解法：CI 用 `DATABASE_URL` 环境变量走 production 段（`use_env_variable`）。

**FAQ-11 预签名 URL 在浏览器打不开（SignatureDoesNotMatch）**
常见原因：endpoint 用了内网地址（容器网络名）而浏览器走外网；或 boto3 未指定 `signature_version="s3v4"`。规则：签发 URL 的 endpoint 必须与浏览器访问 MinIO 的地址完全一致（域名/端口/协议）。

**FAQ-12 审计表想要"不可篡改"只靠 REVOKE 够吗**
`REVOKE UPDATE, DELETE` 挡住了应用账号，但超级用户仍可改。加强方案（按需叠加）：① 审计库独立实例，只开放 INSERT 权限的网络账号；② 每日把 `audit_logs` 追加到 WORM 存储（MinIO 对象锁模式）；③ 哈希链（每行存前一行 hash）。沙盒用 REVOKE + 每日归档 MinIO 即可。

### 14.1 工艺文档 embedding 入库（doc 分块 → 向量化 → 批量入库）

第 6 章建好了 `doc_chunks` 表与 HNSW 索引，但没有解决"文档从哪来、怎么切块、怎么调 embedding、怎么入库"。完整脚本如下（OpenAI 兼容接口，支持私有部署模型，呼应"数据不出域"约束）。

```python
# db/scripts/embed_docs.py
"""
工艺文档 embedding 入库脚本
用法：python db/scripts/embed_docs.py --docs-dir ./db/raw_docs --rebuild
依赖：pip install psycopg2-binary openai tqdm
"""
import argparse
import hashlib
import os
import sys
import time

import psycopg2
import psycopg2.extras
from openai import OpenAI
from tqdm import tqdm

# ---- 配置（与 .env 保持一致） ----
DSN = "host=127.0.0.1 port=5433 dbname=ia_vector user=ia_app password=ia_app_2026"
LLM_BASE_URL = os.getenv("LLM_BASE_URL", "https://llm.ia.local/v1")   # 私有部署 vLLM/Qwen
LLM_API_KEY = os.getenv("LLM_API_KEY", "sk-local-dev")
EMBED_MODEL = os.getenv("EMBED_MODEL", "text-embedding-3-small")      # 1536 维

CHUNK_SIZE = 500      # 每块约 500 字符
CHUNK_OVERLAP = 50    # 相邻块重叠 50 字符
BATCH_SIZE = 32       # embedding 批量

client = OpenAI(base_url=LLM_BASE_URL, api_key=LLM_API_KEY)


def chunk_text(text: str, size: int = CHUNK_SIZE, overlap: int = CHUNK_OVERLAP):
    """滑窗切块：保证跨块的语义连续性。"""
    chunks, start = [], 0
    while start < len(text):
        end = start + size
        piece = text[start:end].strip()
        if piece:
            chunks.append(piece)
        start = end - overlap
    return chunks


def embed_batch(texts: list[str]) -> list[list[float]]:
    """批量调用 embedding 接口，带重试与限速退避。"""
    for attempt in range(5):
        try:
            resp = client.embeddings.create(model=EMBED_MODEL, input=texts)
            # 按 index 排序保证与入参顺序一致
            data = sorted(resp.data, key=lambda d: d.index)
            return [d.embedding for d in data]
        except Exception as e:
            wait = 2 ** attempt
            print(f"  [embed] 第{attempt+1}次失败：{e}，{wait}s 后重试")
            time.sleep(wait)
    raise RuntimeError("embedding 调用连续 5 次失败，请检查 LLM_BASE_URL / LLM_API_KEY")


def load_doc(path: str) -> dict:
    """读取文档并抽取元数据。约定：Markdown 文件首行 `# 标题`，`<!-- meta: k=v -->` 注释携带元数据。"""
    with open(path, encoding="utf-8") as fp:
        raw = fp.read()
    title = os.path.basename(path).replace(".md", "")
    doc_type, equipment = "process_doc", None
    for line in raw.splitlines()[:10]:
        if line.startswith("# "):
            title = line[2:].strip()
        if line.strip().startswith("<!-- meta:"):
            for kv in line.strip()[10:-4].split(","):
                if "=" in kv:
                    k, v = kv.split("=", 1)
                    if k.strip() == "type":
                        doc_type = v.strip()
                    if k.strip() == "equipment":
                        equipment = v.strip()
    return {"title": title, "type": doc_type, "equipment": equipment,
            "content": raw, "hash": hashlib.sha256(raw.encode()).hexdigest()[:16]}


def main():
    parser = argparse.ArgumentParser()
    parser.add_argument("--docs-dir", default="./db/raw_docs")
    parser.add_argument("--rebuild", action="store_true", help="清空 doc_chunks 后全量重建")
    args = parser.parse_args()

    conn = psycopg2.connect(DSN)
    cur = conn.cursor()

    if args.rebuild:
        cur.execute("TRUNCATE TABLE doc_chunks")
        conn.commit()
        print("[rebuild] 已清空 doc_chunks")

    files = [f for f in sorted(os.listdir(args.docs_dir)) if f.endswith(".md")]
    print(f"[scan] 发现 {len(files)} 个文档")

    for fname in tqdm(files, desc="文档入库"):
        doc = load_doc(os.path.join(args.docs_dir, fname))
        # 幂等：内容 hash 未变的文档跳过
        cur.execute(
            "SELECT 1 FROM doc_chunks WHERE doc_id = %s AND content_hash = %s LIMIT 1",
            (doc["title"], doc["hash"]))
        if cur.fetchone():
            continue

        chunks = chunk_text(doc["content"])
        rows = []
        for idx, piece in enumerate(chunks):
            rows.append({
                "doc_id": doc["title"], "chunk_index": idx, "content": piece,
                "content_hash": doc["hash"], "doc_type": doc["type"],
                "equipment": doc["equipment"],
            })

        # 分批 embedding 并插入
        for i in range(0, len(rows), BATCH_SIZE):
            batch = rows[i:i + BATCH_SIZE]
            vectors = embed_batch([r["content"] for r in batch])
            psycopg2.extras.execute_values(
                cur,
                """INSERT INTO doc_chunks
                   (doc_id, chunk_index, content, embedding, content_hash, doc_type, equipment)
                   VALUES %s""",
                [(r["doc_id"], r["chunk_index"], r["content"],
                  psycopg2.Binary(psycopg2.extras.Json(v) if False else _vec(v)),
                  r["content_hash"], r["doc_type"], r["equipment"]) for r, v in zip(batch, vectors)])
        conn.commit()

    # 统计验证
    cur.execute("SELECT count(*), count(DISTINCT doc_id) FROM doc_chunks")
    total, docs = cur.fetchone()
    print(f"[done] 共 {docs} 个文档、{total} 个向量块")
    conn.close()


def _vec(v: list[float]):
    """pgvector 接受 '[0.1,0.2,...]' 文本格式。"""
    return "[" + ",".join(f"{x:.6f}" for x in v) + "]"


if __name__ == "__main__":
    sys.exit(main())
```

### 14.1 工艺文档 embedding 入库（doc 分块 → 向量化 → 批量入库）

第 6 章建好了 `doc_chunks` 表与 HNSW 索引，但没有解决"文档从哪来、怎么切块、怎么调 embedding、怎么入库"。完整脚本如下（OpenAI 兼容接口，支持私有部署模型，呼应"数据不出域"约束）。

```python
# db/scripts/embed_docs.py
"""
工艺文档 embedding 入库脚本
用法：python db/scripts/embed_docs.py --docs-dir ./db/raw_docs --rebuild
依赖：pip install psycopg2-binary openai tqdm
"""
import argparse
import hashlib
import os
import sys
import time

import psycopg2
import psycopg2.extras
from openai import OpenAI
from tqdm import tqdm

# ---- 配置（与 .env 保持一致） ----
DSN = "host=127.0.0.1 port=5433 dbname=ia_vector user=ia_app password=ia_app_2026"
LLM_BASE_URL = os.getenv("LLM_BASE_URL", "https://llm.ia.local/v1")   # 私有部署 vLLM/Qwen
LLM_API_KEY = os.getenv("LLM_API_KEY", "sk-local-dev")
EMBED_MODEL = os.getenv("EMBED_MODEL", "text-embedding-3-small")      # 1536 维

CHUNK_SIZE = 500      # 每块约 500 字符
CHUNK_OVERLAP = 50    # 相邻块重叠 50 字符
BATCH_SIZE = 32       # embedding 批量

client = OpenAI(base_url=LLM_BASE_URL, api_key=LLM_API_KEY)


def chunk_text(text: str, size: int = CHUNK_SIZE, overlap: int = CHUNK_OVERLAP):
    """滑窗切块：保证跨块的语义连续性。"""
    chunks, start = [], 0
    while start < len(text):
        end = start + size
        piece = text[start:end].strip()
        if piece:
            chunks.append(piece)
        start = end - overlap
    return chunks


def embed_batch(texts: list) -> list:
    """批量调用 embedding 接口，带重试与限速退避。"""
    for attempt in range(5):
        try:
            resp = client.embeddings.create(model=EMBED_MODEL, input=texts)
            data = sorted(resp.data, key=lambda d: d.index)
            return [d.embedding for d in data]
        except Exception as e:
            wait = 2 ** attempt
            print(f"  [embed] 第{attempt+1}次失败：{e}，{wait}s 后重试")
            time.sleep(wait)
    raise RuntimeError("embedding 调用连续 5 次失败，请检查 LLM_BASE_URL / LLM_API_KEY")


def load_doc(path: str) -> dict:
    """读取文档并抽取元数据。约定：首行 `# 标题`，`<!-- meta: k=v -->` 注释携带元数据。"""
    with open(path, encoding="utf-8") as fp:
        raw = fp.read()
    title = os.path.basename(path).replace(".md", "")
    doc_type, equipment = "process_doc", None
    for line in raw.splitlines()[:10]:
        if line.startswith("# "):
            title = line[2:].strip()
        if line.strip().startswith("<!-- meta:"):
            for kv in line.strip()[10:-4].split(","):
                if "=" in kv:
                    k, v = kv.split("=", 1)
                    if k.strip() == "type":
                        doc_type = v.strip()
                    if k.strip() == "equipment":
                        equipment = v.strip()
    return {"title": title, "type": doc_type, "equipment": equipment,
            "content": raw, "hash": hashlib.sha256(raw.encode()).hexdigest()[:16]}


def _vec(v: list) -> str:
    """pgvector 接受 '[0.1,0.2,...]' 文本格式。"""
    return "[" + ",".join(f"{x:.6f}" for x in v) + "]"


def main():
    parser = argparse.ArgumentParser()
    parser.add_argument("--docs-dir", default="./db/raw_docs")
    parser.add_argument("--rebuild", action="store_true", help="清空 doc_chunks 后全量重建")
    args = parser.parse_args()

    conn = psycopg2.connect(DSN)
    cur = conn.cursor()

    if args.rebuild:
        cur.execute("TRUNCATE TABLE doc_chunks")
        conn.commit()
        print("[rebuild] 已清空 doc_chunks")

    files = [f for f in sorted(os.listdir(args.docs_dir)) if f.endswith(".md")]
    print(f"[scan] 发现 {len(files)} 个文档")

    for fname in tqdm(files, desc="文档入库"):
        doc = load_doc(os.path.join(args.docs_dir, fname))
        # 幂等：内容 hash 未变的文档跳过
        cur.execute(
            "SELECT 1 FROM doc_chunks WHERE doc_id = %s AND content_hash = %s LIMIT 1",
            (doc["title"], doc["hash"]))
        if cur.fetchone():
            continue

        chunks = chunk_text(doc["content"])
        rows = []
        for idx, piece in enumerate(chunks):
            rows.append({
                "doc_id": doc["title"], "chunk_index": idx, "content": piece,
                "content_hash": doc["hash"], "doc_type": doc["type"],
                "equipment": doc["equipment"],
            })

        for i in range(0, len(rows), BATCH_SIZE):
            batch = rows[i:i + BATCH_SIZE]
            vectors = embed_batch([r["content"] for r in batch])
            psycopg2.extras.execute_values(
                cur,
                """INSERT INTO doc_chunks
                   (doc_id, chunk_index, content, embedding, content_hash, doc_type, equipment)
                   VALUES %s""",
                [(r["doc_id"], r["chunk_index"], r["content"], _vec(v),
                  r["content_hash"], r["doc_type"], r["equipment"])
                 for r, v in zip(batch, vectors)])
        conn.commit()

    cur.execute("SELECT count(*), count(DISTINCT doc_id) FROM doc_chunks")
    total, docs = cur.fetchone()
    print(f"[done] 共 {docs} 个文档、{total} 个向量块")
    conn.close()


if __name__ == "__main__":
    sys.exit(main())
```

### 14.5 一键初始化脚本 init_all.sh

把前 13 章的散装步骤串成一条命令（幂等，可重复执行）：

```bash
#!/usr/bin/env bash
# db/init_all.sh —— 从空环境到全量演示数据
# 用法：bash db/init_all.sh [--skip-graph]
set -euo pipefail
cd "$(dirname "$0")/.."   # 回到仓库根目录

PG="docker exec -i ia-pg psql -U ia_admin -d"
STEP() { echo -e "\n==> $1"; }

STEP "0/9 检查容器"
docker ps --format '{{.Names}}' | grep -q ia-pg || { echo "ia-pg 未启动，请先执行第 2 章环境准备"; exit 1; }

STEP "1/9 建库与扩展（ia_main / ia_ts / ia_vector）"
$PG postgres -tc "SELECT 1 FROM pg_database WHERE datname='ia_main'" | grep -q 1 || \
  $PG postgres -c "CREATE DATABASE ia_main"
$PG postgres -tc "SELECT 1 FROM pg_database WHERE datname='ia_ts'" | grep -q 1 || \
  $PG postgres -c "CREATE DATABASE ia_ts"
$PG postgres -tc "SELECT 1 FROM pg_database WHERE datname='ia_vector'" | grep -q 1 || \
  $PG postgres -c "CREATE DATABASE ia_vector"
$PG ia_ts     -c "CREATE EXTENSION IF NOT EXISTS timescaledb;"
$PG ia_vector -c "CREATE EXTENSION IF NOT EXISTS vector;"

STEP "2/9 业务表 DDL（04 章 01_business.sql）"
$PG ia_main < db/sql/01_business.sql

STEP "3/9 审计分区表（04 章 02_audit.sql）"
$PG ia_main < db/sql/02_audit.sql

STEP "4/9 时序超表 + 连续聚合（05 章 03_timeseries.sql）"
$PG ia_ts < db/sql/03_timeseries.sql

STEP "5/9 向量表 + HNSW 索引（06 章 04_vector.sql）"
$PG ia_vector < db/sql/04_vector.sql

STEP "6/9 Neo4j 图谱种子（14.2 演示图谱，含约束）"
if [[ "${1:-}" != "--skip-graph" ]]; then
  docker exec -i ia-neo4j cypher-shell -u neo4j -p ia_neo4j_2026 < db/graph/constraints.cypher
  docker exec -i ia-neo4j cypher-shell -u neo4j -p ia_neo4j_2026 < db/graph/seed_demo.cypher
fi

STEP "7/9 背景种子（10.2 业务数据 + 10.3 时序合成）"
pip show faker >/dev/null 2>&1 || pip install faker psycopg2-binary
python db/seeds/seed_business.py
python db/scripts/synthesize_sensors.py --days 14

STEP "8/9 演示事件全链路（14.4）"
python db/seeds/seed_demo_event.py

STEP "9/9 验证断言"
$PG ia_main -tc "SELECT count(*) FROM anomaly_events WHERE event_no='EVT-20261015-007';" | grep -q 1 || { echo "演示事件缺失"; exit 1; }
$PG ia_ts -tc "SELECT count(*) FROM sensor_readings WHERE recorded_at > NOW() - INTERVAL '1 day';" | grep -qv "^ *0" || { echo "时序数据缺失"; exit 1; }
echo ""
echo "全部初始化完成：业务表 / 超表 / 向量表 / 图谱 / 背景种子 / 演示事件 就绪"
```
