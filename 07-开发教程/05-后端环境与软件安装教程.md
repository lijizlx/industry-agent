# 1. 导读：要装什么、为什么这么装

## 1.1 安装总清单

后端教程的全部外部依赖共 6 项。**除 Python 外全部跑在 Docker 容器里**，宿主机保持干净，版本一致、一键销毁重建：

| # | 组件 | 版本/镜像 | 形态 | 名称/端口 | 凭证 | 后端教程哪章用 |
|---|---|---|---|---|---|---|
| 1 | Docker Desktop | 最新稳定版 | 宿主机软件 | —— | —— | 全书容器的运行底座 |
| 2 | PostgreSQL | `postgres:16-alpine` | 容器 `ia-pg` | 5432 | industry / industry123，库 industryagent | 第 2 章（业务数据） |
| 3 | Redis | `redis:7-alpine` | 容器 `ia-redis` | 6379 | 无密码（本地开发） | 第 2 章（缓存/幂等/Token） |
| 4 | Python | 3.10+（推荐 3.12） | 宿主机软件 | agent-mock 服务 8000 | —— | 第 8 章（智能体 Mock：fastapi+uvicorn） |
| 5 | MinIO | `minio/minio` | 容器 `ia-minio` | API 9000 / 控制台 9001 | industry / industry123 | 第 18 章（缺陷图对象存储） |
| 6 | Keycloak | `quay.io/keycloak/keycloak:24.0` | 容器 `ia-keycloak` | 8080 | admin / admin123 | 第 19 章（可选进阶） |

另外两个"不需要单独安装"的：

- **Node 20+ 与 Git**：你已装好（本教程的前置条件）。
- **curl**：Windows 的 Git Bash 自带，无需安装；后端教程的全部 `curl` 验证命令在 Git Bash 中直接执行。

> **为什么 Python 不放容器**：后端教程 8.3 节的 agent-mock 是一个 30 行的学习用 Mock，教程要求你能在它的终端里 Ctrl+C 停服务来演示熔断器，放宿主机最直观。而且它也是后续《03-智能体开发教程》的开发语言，宿主机装一份 Python 是必要投资。

# 2. Docker Desktop（Windows）安装与配置

## 2.1 做什么 / 为什么

PG、Redis、MinIO、Keycloak 全部以容器形态运行，Docker Desktop 是唯一的运行底座。**不推荐**在 Windows 宿主机直接安装 PostgreSQL/Redis 原生服务——版本漂移、卸载残留、服务冲突都是坑，这与后端教程 2.1 节的理念一致。

## 2.2 前置检查：WSL2 与 CPU 虚拟化

Docker Desktop 在 Windows 上依赖 WSL2，WSL2 依赖 CPU 虚拟化。以管理员身份打开 PowerShell（开始菜单搜 PowerShell → 右键"以管理员身份运行"）：

```powershell
# 查看虚拟化是否开启
Get-ComputerInfo -Property "HyperVRequirementVirtualizationFirmwareEnabled"
# 预期输出：HyperVRequirementVirtualizationFirmwareEnabled : True
# 若为 False：重启进 BIOS，开启 Intel VT-x / AMD SVM（各主板叫法不同，一般在 Advanced/CPU Configuration）

# 一键安装 WSL2（Windows 10 2004+ / Windows 11）
wsl --install
# 预期输出：正在安装: 虚拟机平台... 安装完成后需要重启电脑

# 已装过 WSL 的机器只更新即可
wsl --update
wsl --status
# 预期输出：默认版本: 2
```

> 老版本 Windows 10（低于 2004）请先升级系统，或改用 Docker Toolbox 时代以前的方案不在本教程支持范围。

## 2.3 安装 Docker Desktop

1. 官网下载安装器：https://www.docker.com/products/docker-desktop/ （Windows 版，AMD64）。
2. 双击安装，安装选项保持默认：**Use WSL 2 instead of Hyper-V（推荐）务必勾选**。
3. 安装完成重启电脑，启动 Docker Desktop（桌面鲸鱼图标）。
4. 首次启动若提示 "Sign in"，直接点跳过（Docker Hub 账号不是必需的）。

## 2.4 验证

Git Bash（或 CMD）执行：

```bash
docker version
# 预期输出：Client 与 Server 两段版本信息（Server 段出现即说明后台引擎就绪）

docker run --rm hello-world
# 预期输出：Hello from Docker!（说明拉取→创建→运行→清理全链路通）
```

> 若 `docker version` 只有 Client 段没有 Server 段：Docker Desktop 没启动成功，看系统托盘鲸鱼图标是否在转，报错见 FAQ Q5。

## 2.5 配置镜像加速（国内网络必做）

Docker Hub 在国内直连经常超时。Docker Desktop → 右上角齿轮 **Settings** → **Docker Engine**，在 JSON 中追加 `registry-mirrors` 字段（注意前一项末尾补逗号）：

```json
{
  "builder": {
    "gc": {
      "defaultKeepStorage": "20GB",
      "enabled": true
    }
  },
  "experimental": false,
  "registry-mirrors": [
    "https://docker.1ms.run",
    "https://docker.m.daocloud.io"
  ]
}
```

点 **Apply & Restart**，验证：

```bash
docker info | grep -A3 "Registry Mirrors"
# 预期输出：列出刚才配置的镜像地址
```

> 公共镜像加速地址时效性强，若两个都失效，去阿里云容器镜像服务控制台（需登录）领取个人专属加速地址替换。Keycloak 的镜像在 quay.io（不走 Docker Hub），加速器对它无效，但 quay.io 国内一般可直连；仍超时就先跳过第 8 章，用到第 19 章再解决。

## 2.6 资源分配建议

Settings → **Resources**（WSL2 模式下若该页灰色，去 %USERPROFILE%\.wslconfig 全局配置）：本教程四个容器都很轻量，默认配置（4GB 内存 / 2 CPU）足够；后续要跟《03-智能体开发教程》跑本地大模型推理时再调大。

# 3. PostgreSQL 16 容器

## 3.1 启动

```bash
docker run -d \
  --name ia-pg \
  --restart unless-stopped \
  -e POSTGRES_USER=industry \
  -e POSTGRES_PASSWORD=industry123 \
  -e POSTGRES_DB=industryagent \
  -p 5432:5432 \
  -v ia-pg-data:/var/lib/postgresql/data \
  postgres:16-alpine
# 预期输出：一长串容器 ID（64 位十六进制字符串）
```

> **与后端教程 2.3 节的差异说明**：本命令与教程完全同名（ia-pg）、同端口（5432）、同凭证（industry/industry123），仅多两项增强，教程正文所有 `docker exec -it ia-pg ...` 验证命令原样可用：
> - `-v ia-pg-data:...`：数据落 Docker 卷。**教程原版命令没挂数据卷，容器一旦删除（docker rm）数据全丢**；挂卷后数据独立于容器生命周期，重置见 9.4 节。
> - `--restart unless-stopped`：Docker Desktop 启动时容器自动跟随启动，不用每天手敲命令。
>
> 若你已经按教程裸跑过 ia-pg，想补数据卷：数据目前只有教程种子数据，直接 `docker rm -f ia-pg` 删除后用上面命令重建即可（有自定义数据先 `docker exec ia-pg pg_dump -U industry industryagent > backup.sql` 备份）。

## 3.2 验证

```bash
# 等待约 3~5 秒初始化完成，然后查版本
docker exec -it ia-pg psql -U industry -d industryagent -c "SELECT version();"
# 预期输出（节选）：
# PostgreSQL 16.x on x86_64-pc-linux-musl ...

# 顺手验证数据卷已挂上
docker inspect ia-pg --format '{{ json .Mounts }}'
# 预期输出：含 "ia-pg-data" 与 "/var/lib/postgresql/data" 的 JSON 段
```

## 3.3 （可选）图形化客户端

教程全程用 `docker exec` 进 psql 已够用。想要图形界面的话二选一，连接参数：`127.0.0.1:5432`，用户 industry，密码 industry123，库 industryagent：

- **DBeaver Community**（免费，支持 PG/Redis 图形管理插件）
- **VS Code 插件**：Database Client（weijanet.database-client）

# 6. Python 3.10+（第 8 章智能体 Mock 用）

## 6.1 安装

**方式 A：官网安装包（推荐）**

1. 下载：https://www.python.org/downloads/ → 最新 3.12.x Windows installer（64-bit）。
2. 安装第一屏**务必勾选 "Add python.exe to PATH"**（不勾的话后面所有命令都找不到 python），其余默认，点 Install Now。

```powershell
winget install Python.Python.3.12
# 预期输出：Successfully installed（装完重开 Git Bash 让 PATH 生效）
```

> **Windows Store 陷阱**：Win10/11 自带的 "python" 别名会弹出应用商店。若 `python --version` 弹商店而不是出版本号：设置 → 应用 → 高级应用设置 → 应用执行别名 → 把 python.exe / python3.exe 两项**关掉**。

## 6.2 验证

```bash
python --version
# 预期输出：Python 3.12.x（≥ 3.10 即可）

pip --version
# 预期输出：pip 2x.x from ...
```

配置 pip 国内镜像（一劳永逸，后面装 fastapi/uvicorn 及智能体教程的依赖都受益）：

# 7. MinIO 对象存储容器（第 18 章前置，可先装）

## 7.1 启动

```bash
docker run -d \
  --name ia-minio \
  --restart unless-stopped \
  -e MINIO_ROOT_USER=industry \
  -e MINIO_ROOT_PASSWORD=industry123 \
  -p 9000:9000 -p 9001:9001 \
  -v ia-minio-data:/data \
  minio/minio server /data --console-address ":9001"
# 预期输出：一长串容器 ID
```

凭证与后端教程 18.0.2 节 `.env` 中的 `IA_MINIO_ACCESS_KEY=industry / IA_MINIO_SECRET_KEY=industry123` 一致，装完第 18 章无需改任何配置。

## 7.2 验证

```bash
# 健康检查端点（返回 HTTP 状态码）
curl -s -o /dev/null -w "%{http_code}" http://127.0.0.1:9000/minio/health/live
# 预期输出：200
```

浏览器打开 `http://127.0.0.1:9001`，用 industry / industry123 登录控制台，能看到 Object Browser 即成功。

> **桶（bucket）不用手工建**：`defect-images` 桶由第 18 章缺陷 Service 的 `ensureBucket` 在首次访问时自动创建（后端教程 18.3.2 节原话）。现在控制台里空无一桶是正常的。

# 9. 容器日常管理与一键验证

## 9.1 日常命令速查表

| 场景 | 命令 |
|---|---|
| 看全部容器状态 | `docker ps -a` |
| 看某个容器日志 | `docker logs -f ia-pg`（Ctrl+C 退出） |
| 单个启停 | `docker stop ia-minio` / `docker start ia-minio` |
| 进入容器内部 | `docker exec -it ia-pg bash`（alpine 镜像无 bash，用 `sh`） |
| 删除容器（数据保留在卷里） | `docker rm -f ia-pg` 后按 3.1 重建即恢复 |

## 9.2 开机自启已配好

四个容器都带了 `--restart unless-stopped`：Docker Desktop 启动（默认开机自启，Settings → General → Start Docker Desktop when you sign in）后容器自动拉起，无需手动。用 `docker stop` 手动停过的容器不会被自启覆盖（unless-stopped 语义），需要时 `docker start` 即可。

## 9.3 一键启动 / 停止 / 全量验证

三个容器一起操作（顺序无所谓，`--restart` 已解除启动顺序心智负担）：

```bash
# 一键启动（电脑重启 / Docker 重装后）
docker start ia-pg ia-redis ia-minio
# 可选第 19 章容器：docker start ia-keycloak

# 一键停止（释放内存，数据不丢）
docker stop ia-pg ia-redis ia-minio
```

每日开发前的**环境就绪检查**（一条命令验全部，建议加进个人笔记）：

```bash
docker ps --format "table {{.Names}}\t{{.Status}}\t{{.Ports}}" && \
docker exec ia-pg psql -U industry -d industryagent -c "SELECT 1;" && \
docker exec ia-redis redis-cli ping && \
curl -s -o /dev/null -w "minio: %{http_code}\n" http://127.0.0.1:9000/minio/health/live
# 预期输出：容器表格（3 个 Up）+ " 1" + "PONG" + "minio: 200"，四段全绿即环境就绪
```

## 9.4 数据都在哪、如何彻底重置

| 卷名 | 内容 | 重置命令 |
|---|---|---|
| ia-pg-data | 全部业务数据（开发库+测试库） | `docker rm -f ia-pg && docker volume rm ia-pg-data` 后按 3.1 重建，再跑后端教程 `npm run seed` 重新灌种子 |
| ia-redis-data | 缓存/幂等键（易失） | 同上，重建后无需灌数据 |
| ia-minio-data | 缺陷图文件 | 同上，第 18 章代码会自动重建桶 |

卷的实际存储位置（WSL2 内部路径，不需要也不建议直接动）：`docker volume inspect ia-pg-data` 看 Mountpoint。

# 10. 常见安装问题 FAQ

**Q1：端口被占用（docker run 报 "port is already allocated" 或绑定失败）**

```bash
# 找出占用者（以 5432 为例）
netstat -ano | grep ":5432" | grep LISTEN
# 预期输出：TCP 0.0.0.0:5432 ... LISTENING <PID>
tasklist | grep <PID>     # 看 PID 对应进程名
```

处置：本机以前装过原生 PostgreSQL/Redis 服务 → `services.msc` 里停用并禁用（或卸载）；被无关软件占用 → 改宿主机映射端口（如 `-p 15432:5432`），**同时必须同步修改后端教程 `.env` 里的 `IA_DB_PORT`**（容器内端口 5432 不变，只动冒号左边）。Keycloak 8080 冲突最常见，同理改 `-p 18080:8080` 并同步教程 19 章所有 URL。

**Q2：`docker: command not found` / 鲸鱼图标一启动就退**

前者是 PATH 没生效，重开 Git Bash；后者去 任务管理器 → 性能 → CPU 看"虚拟化：已启用"，未启用回 2.2 节开 BIOS。仍不行就 Docker Desktop → Troubleshoot（小虫子图标）→ Reset to factory defaults。

**Q3：镜像拉取超时 / very slow**

确认 2.5 节镜像加速已 Apply & Restart；仍超时换一个镜像地址重试。已有镜像被缓存后，`docker run` 不再联网，失败重试无额外代价。

**Q4：容器名冲突（"The container name /ia-pg is already in use"）**

说明之前跑过同名容器。`docker ps -a | grep ia-` 查看：Exited 状态的直接 `docker rm ia-pg` 后重跑安装命令；Up 状态说明已经装过了，跳到 9.3 节验证即可。

**Q5：WSL2 相关报错（"WslRegisterDistribution failed" / error 0x80370102）**

0x80370102 = 虚拟化未开启（回 2.2 节 BIOS）；其他 WSL 报错先 `wsl --update` 再 `wsl --shutdown`，重启 Docker Desktop。BIOS 开了虚拟化但 BIOS 又开了 Hyper-Threading 冲突的老主板，尝试 BIOS 里关掉 "Intel SGX"。

**Q6：装了这些容器，第 15 章的 docker-compose 还能跑吗？**

能。第 15 章 compose 栈用的是**另一组**容器名（ia-compose-*）与**错开的**宿主机端口（PG 用 15432、Redis 用 16379），与本教程的 ia-pg/ia-redis 完全并行不冲突，后端教程 15.4 节注释里写明了这是特意为之。两套可以同时运行。

**Q7：agent-mock 的 8000 端口将来和真实智能体冲突吗？**

第 8 章阶段不冲突（Mock 只在演示时启动）。将来跟《03-智能体开发教程》联调时，真实智能体服务监听 8300，与 Mock 的 8000 错开；届时 `.env` 的 `IA_AGENT_BASE_URL` 指向谁，后端就调用谁，无需改代码。

**Q8：杀毒软件 / 防火墙拦截**

Docker Desktop 与 WSL2 首次启动被拦截时，在杀软（360/火绒等）里给 `%ProgramFiles%\Docker` 与 `wsl.exe` 加白名单。容器内部互相访问（backend → ia-pg）不走 Windows 防火墙，无需放行；只有宿主机 curl 容器端口若被拦，放行对应端口即可。

**Q9：磁盘空间清理**

```bash
docker system df          # 看镜像/卷/构建缓存各占多少
docker builder prune      # 清构建缓存（最安全）
docker image prune -a     # 删除未被任何容器使用的镜像（不影响本教程四个容器）
```
