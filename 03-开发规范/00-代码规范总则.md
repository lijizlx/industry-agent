## 1. 适用范围

本总则适用于 IndustryAgent（工业智能体平台——半导体良率根因分析智能体）项目的全部代码仓库：

| 仓库 | 技术栈 | 责任范围 |

| industryagent-web | React 18 + TypeScript + Vite + Ant Design 5 | 前端界面 |

## 3. 命名总则

| 对象 | 规则 | 正例 | 反例 |
|---|---|---|---|
| 目录 | kebab-case | `yield-analysis/` | `YieldAnalysis/`、`yield_analysis/` |
| TS/JS 文件 | kebab-case | `root-cause.service.ts` | `RootCauseService.ts` |
| React 组件文件 | PascalCase（与组件名一致） | `YieldTrendChart.tsx` | `yieldTrendChart.tsx` |
| 变量、函数 | camelCase，名词/动词开头，见名知义 | `getDefectRate()` | `getData()`、`dr` |
| 类、接口、类型 | PascalCase；接口不加 `I` 前缀 | `class BizError`、`interface WaferLot` | `IWaferLot` |
| 常量 | UPPER_SNAKE_CASE，集中定义 | `MAX_RETRY_COUNT` | `maxRetry` |
| 布尔变量 | is/has/can/should 前缀 | `isRootCauseConfirmed` | `rootCauseFlag` |
| 异步函数 | 体现异步语义或返回 Promise 命名 | `fetchYieldData()` | — |
| 事件处理 | handle + 事件源 | `handleSubmit()` | `submit()`（作为 props 名时） |
| 数据库表 | snake_case 复数（详见 IA-DEV-006） | `wafer_lots` | `WaferLot`、`waferlot` |
| 数据库字段 | snake_case | `created_at` | `createdAt` |
| Git 分支 | `feature/IA-123-kebab-desc` | `feature/IA-123-rootcause-agent` | `feature/根因分析`、`feat_123` |
| 枚举值 | 小写，字典表或联合类型管理 | `'pending' \| 'running'` | `STATUS_1` |

命名长度控制：变量名 2~4 个单词为宜；禁止无意义缩写（`tmp`、`res2`、`data1`），领域通用缩写除外（`id`、`url`、`params`、`ctx`）。

```typescript
// ✅ 正例
const MAX_ROOT_CAUSE_COUNT = 3;
const isAnomalyDetected = fdcResult.isAnomaly;

// ❌ 反例
const n = 3;                 // 魔法数字 + 无意义命名
const flag = r.f;            // 无法理解
const data1 = await getData(); // 无意义后缀
```

## 4. 注释规范

### 4.1 基本原则

1. 注释解释 **为什么**，而不是复述代码 **做什么**。
2. 公开导出的函数、类、接口必须写 JSDoc。
3. 删掉的代码直接删除，依赖 Git 历史，禁止注释保留。

### 4.2 必须注释的场景

| 场景 | 注释要求 |
|---|---|
| 导出的公共函数/类/工具 | JSDoc：用途、参数、返回值、示例 |
| 业务规则来源 | 注明需求编号或工艺文档出处（如"依据 SECS/GEM 规范 5.3 节"） |
| 复杂算法 | 根因评分算法、因果推断逻辑等，须注释算法出处与公式 |
| 临时绕过/妥协代码 | 注明原因、关联 issue、计划移除版本 |
| 正则表达式 | 说明匹配目标 |
| 非直觉的数值/阈值 | 说明来源（实验结论、SLA 约定） |

## 5. 魔法值禁止

代码中禁止出现未经命名的字符串、数字字面量。所有业务阈值、状态值、错误码、配置项必须收敛到常量文件或枚举中。

```typescript
// ❌ 反例：魔法值散落
if (lot.status === '3') { ... }
if (yieldRate < 0.93) { alarm(); }
if (retry > 5) { ... }

// ✅ 正例：常量收敛（src/common/constants.ts）
export const LOT_STATUS = {
  PENDING: 'pending',
  RUNNING: 'running',
  COMPLETED: 'completed',
  SCRAPPED: 'scrapped',
} as const;

/** 良率告警阈值：依据 2026Q3 工艺评审会决议（目标 95%，容忍下限 93%） */
export const YIELD_ALARM_THRESHOLD = 0.93;

export const AGENT_MAX_RETRY = 5;
```

## 6. 函数与圈复杂度阈值

| 指标 | 阈值 | 超出处理 |
|---|---|---|
| 圈复杂度（cyclomatic complexity） | ≤ 15 | 必须拆分为多个函数或引入策略表 |
| 函数行数（不含空行/注释） | ≤ 120 | 拆分 |
| 函数参数个数 | ≤ 5 | 超出时收拢为对象参数 |
| 嵌套深度 | ≤ 4 | 提前返回（guard clause）拍平 |
| 单文件行数 | ≤ 500（后端）/ ≤ 300（前端组件） | 拆分模块 |

```typescript
// ❌ 反例：嵌套过深 + 圈复杂度高
function processLot(lot: WaferLot) {
  if (lot) {
    if (lot.wafers.length > 0) {
      for (const wafer of lot.wafers) {
        if (wafer.defects) {
          if (wafer.defects.length > 10) {
            // ...
          }
        }
      }
    }
  }
}

// ✅ 正例：guard clause 拍平
function processLot(lot: WaferLot | null): void {
  if (!lot || lot.wafers.length === 0) return;

  for (const wafer of lot.wafers) {
    processWaferDefects(wafer);
  }
}
```

## 7. 目录组织原则

1. **按业务域组织，而非按技术类型组织**：优先按领域（良率分析、设备监控、审批流）划分目录。
2. **就近原则**：仅某模块使用的类型、常量、工具放在该模块内；跨模块使用的上提到 `common/` 或 `shared/`。
3. **禁止循环依赖**：模块依赖必须是 DAG，ESLint `import/no-cycle` 规则强制。
4. 每个仓库根目录必须包含：`README.md`、`.editorconfig`、`.eslintrc.js`、`.prettierrc`、`.gitignore`、`LICENSE`（内部密级声明）。

```text
industryagent-server/
├── app/
│   ├── controller/          # 薄控制器（详见 IA-DEV-002）
│   ├── service/             # 业务逻辑
│   ├── model/               # 数据模型
│   ├── middleware/          # 中间件
│   ├── router.ts
│   └── common/              # 跨模块常量、错误码、工具
├── config/
│   ├── config.default.ts

├── test/

```

## 9. 检查与豁免流程

1. CI（GitHub Actions）在每个 PR 上执行 `eslint`、`prettier --check`、`tsc --noEmit`、单元测试，任一红灯禁止合并。
2. 确因第三方库类型缺陷等客观原因需要豁免时：在代码中注明原因与 issue 号，并在 PR 描述中列出豁免清单，经技术负责人（李吉）确认后方可合并。
3. 本总则每季度复盘一次，修订须走修订记录流程并重新评审。
