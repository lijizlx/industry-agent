## 1. 适用范围

本规范覆盖 IndustryAgent 平台全部数据存储：

- **PostgreSQL 16 + TimescaleDB + pgvector**：业务库、时序库（FDC 传感器数据）、向量库（RAG）
- **Neo4j 5.x**：工艺/设备知识图谱
- **Redis 7**：缓存与分布式锁（仅 KV 使用规范见 IA-DEV-002）
- **MinIO**：缺陷图、工艺文档对象存储（本规范仅涉及元数据命名）

所有 DDL/数据变更必须通过 sequelize migration 版本化执行，**禁止直接操作生产库**。

## 2. 命名规范

### 2.1 表与字段

| 对象 | 规则 | 正例 | 反例 |
|---|---|---|---|
| 表名 | snake_case，**复数**，按业务域前缀分组 | `wafer_lots`、`yield_products` | `WaferLot`、`waferlot`、`wl` |
| 业务域前缀 | yield / fdc / agent / auth / rpt | `agent_task_runs` | `tasks2` |
| 字段名 | snake_case，单数 | `lot_no`、`product_id` | `lotNo`、`No` |
| 布尔字段 | is_/has_ 前缀 | `is_scrapped` | `scrap_flag` |
| 外键字段 | `<被引表单数>_id` | `product_id` | `pid`、`prodId` |
| 主键 | `id` | `id` | `pk_wafer_lot` |

### 2.2 索引与约束

| 对象 | 规则 | 正例 |
|---|---|---|
| 普通索引 | `idx_<表名>_<字段1>_<字段2>` | `idx_wafer_lots_product_status` |
| 唯一索引 | `uk_<表名>_<字段>` | `uk_wafer_lots_lot_no` |
| 主键约束 | `pk_<表名>` | `pk_wafer_lots` |
| 外键约束 | `fk_<表名>_<引用表>` | `fk_wafer_lots_products` |
| Check 约束 | `ck_<表名>_<字段>_<语义>` | `ck_wafer_lots_yield_range` |

## 3. 字段规范

1. **主键**：`id BIGINT GENERATED ALWAYS AS IDENTITY`，禁止 UUID 作主键（索引膨胀），确需对外暴露的实体另设 `uuid` 列 + 唯一索引。
2. **审计三件套必备**：`created_at TIMESTAMPTZ NOT NULL DEFAULT now()`、`updated_at TIMESTAMPTZ NOT NULL DEFAULT now()`。
3. **软删除**：业务表使用 `deleted_at TIMESTAMPTZ NULL`（Sequelize paranoid）；查询默认过滤 `deleted_at IS NULL`。
4. **金额与精度**：良率、比例类用 `NUMERIC(6,4)`；金额用 `NUMERIC(12,2)`；**禁止 FLOAT/DOUBLE 存储精度敏感值**。
5. **枚举**：用小写 `VARCHAR(16)` + CHECK 约束，或字典表（枚举值会扩展、需翻译时优先字典表）。

```sql
-- ✅ 正例：标准业务表
CREATE TABLE wafer_lots (
  id            BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  lot_no        VARCHAR(32)  NOT NULL,
  product_id    BIGINT       NOT NULL,
  yield_rate    NUMERIC(6,4),
  status        VARCHAR(16)  NOT NULL DEFAULT 'pending',
  created_at    TIMESTAMPTZ  NOT NULL DEFAULT now(),
  updated_at    TIMESTAMPTZ  NOT NULL DEFAULT now(),
  deleted_at    TIMESTAMPTZ,
  CONSTRAINT uk_wafer_lots_lot_no UNIQUE (lot_no),
  CONSTRAINT ck_wafer_lots_status CHECK (status IN ('pending','running','completed','scrapped')),
  CONSTRAINT ck_wafer_lots_yield_range CHECK (yield_rate IS NULL OR (yield_rate >= 0 AND yield_rate <= 1))
);
CREATE INDEX idx_wafer_lots_product_status ON wafer_lots (product_id, status) WHERE deleted_at IS NULL;

-- ❌ 反例
CREATE TABLE wl (                              -- 无意义缩写表名
  no VARCHAR(50) PRIMARY KEY,                  -- 字符串主键
  yield FLOAT,                                 -- 浮点存良率，精度丢失
  status INT,                                  -- 魔法数字状态，语义不明
  ctime DATETIME                               -- 缩写字段、无时区
);
```

## 4. SQL 编写规范

1. **禁止 `SELECT *`**：显式列出所需字段（ORM 中用 `attributes`），原因：覆盖索引失效、列变更引发隐式 bug、传输浪费。
2. **JOIN 写法**：超过 3 张表 JOIN 须评审说明；JOIN 字段必须有索引且类型一致；优先 `INNER JOIN` 显式声明，禁止逗号隐式 JOIN。
3. **子查询深度**：嵌套不超过 2 层，深层嵌套改写为 CTE（`WITH`）。
4. **分页规范**：统一 `LIMIT/OFFSET`，`OFFSET < 10000`；深分页改用键集分页（`WHERE id > :lastId LIMIT :pageSize`）。
5. **慢查询目标**：所有线上查询 P95 < **200ms**，超过即触发优化（看执行计划、加索引、改写）。
6. 大批量写操作分批（每批 ≤ 5000 行），避免长事务。

```sql
-- ❌ 反例：SELECT * + 隐式 JOIN + 深分页
SELECT * FROM wafer_lots a, products b WHERE a.product_id = b.id
ORDER BY a.id LIMIT 10 OFFSET 500000;

-- ✅ 正例：显式字段 + 显式 JOIN + 键集分页
SELECT a.id, a.lot_no, a.yield_rate, b.product_name
FROM wafer_lots a
INNER JOIN products b ON b.id = a.product_id
WHERE a.deleted_at IS NULL AND a.id > :last_id
ORDER BY a.id ASC
LIMIT 20;
```

## 5. 索引规范

| 规则 | 说明 |
|---|---|
| 最左前缀 | 复合索引 `(product_id, status)` 可服务 `product_id` 单条件查询，反之不行 |
| 区分度 | 区分度 < 0.1 的列（如 status 只有 4 个值）不单独建索引，只进复合索引 |
| 复合索引顺序 | 等值条件列在前、范围条件列在后：`(product_id, created_at)` |
| 覆盖索引 | 高频查询建覆盖索引避免回表：`idx_wafer_lots_product_status INCLUDE (yield_rate)` |
| 单表索引上限 | ≤ **6 个**（含主键、唯一约束），超限须 DBA 会审 |
| 外键列必须索引 | 避免级联操作全表扫描 |
| 部分索引 | 软删除表的高频查询加 `WHERE deleted_at IS NULL` |

```sql
-- ❌ 反例：低区分度单列索引 + 冗余索引
CREATE INDEX idx_wafer_lots_status ON wafer_lots (status);              -- 仅 4 个取值
CREATE INDEX idx_wafer_lots_product ON wafer_lots (product_id);         -- 被 (product_id,status) 覆盖

-- ✅ 正例
CREATE INDEX idx_wafer_lots_product_created ON wafer_lots (product_id, created_at DESC)
  WHERE deleted_at IS NULL;
```

## 6. 事务与锁

1. **短事务**：事务只包数据库操作，单事务 ≤ 10 条语句、执行 ≤ 200ms；外部调用移出事务（outbox 模式发 Kafka）。
2. **禁止循环内事务**：循环内每条开一个事务 = 连接风暴；应改为单事务批量提交或分批。
3. 更新语句必须命中索引，避免锁升级与全表扫描锁。
4. **死锁处理**：多表更新按固定顺序（如按 id 升序）访问；捕获 `40P01` 死锁错误后由应用层重试（≤ 3 次、指数退避）。

```sql
-- ❌ 反例：循环内逐条事务
-- for lot in lots: BEGIN; UPDATE ...; COMMIT;   -- 1 万批次 = 1 万次事务

-- ✅ 正例：单事务分批更新
BEGIN;
UPDATE wafer_lots SET status = 'completed'
WHERE id IN (:batch_ids) AND deleted_at IS NULL;
COMMIT;
```

## 7. TimescaleDB 专项（FDC 时序数据）

### 7.1 Hypertable 分区

- 传感器时序表（如 `fdc_sensor_readings`）必须建为 hypertable，**分区键统一 `time`**，分区粒度按数据量选择（传感器数据选 1 天）。
- 空间分区（`space_partition`）按设备 ID，仅当单日数据 > 5000 万行时启用。
- 所有查询必须带时间范围条件，禁止全时段扫描。

```sql
CREATE TABLE fdc_sensor_readings (
  time        TIMESTAMPTZ  NOT NULL,
  equipment_id BIGINT      NOT NULL,
  sensor_code VARCHAR(32)  NOT NULL,
  value       NUMERIC(12,6) NOT NULL,
  quality     SMALLINT     NOT NULL DEFAULT 0
);
SELECT create_hypertable('fdc_sensor_readings', 'time',
  chunk_time_interval => INTERVAL '1 day');

-- ✅ 查询必带时间窗
SELECT time_bucket('5 minutes', time) AS bucket, avg(value)
FROM fdc_sensor_readings
WHERE time >= now() - INTERVAL '24 hours' AND equipment_id = :eid
GROUP BY bucket ORDER BY bucket;

-- ❌ 反例：无时间条件全表扫描
SELECT * FROM fdc_sensor_readings WHERE equipment_id = :eid;
```

### 7.2 连续聚合与压缩

- 5 分钟/1 小时聚合用**连续聚合**（continuous aggregate）物化，异常检测读聚合视图不扫原始数据；聚合策略随 migration 版本化。
- 原始数据保留 90 天，通过压缩策略自动压缩：压缩开启后禁止 `DELETE/UPDATE` 历史数据。

```sql
CREATE MATERIALIZED VIEW fdc_sensor_5m WITH (timescaledb.continuous) AS
SELECT time_bucket('5 minutes', time) AS bucket, equipment_id, sensor_code,
       avg(value) AS avg_value, max(value) AS max_value
FROM fdc_sensor_readings
GROUP BY bucket, equipment_id, sensor_code
WITH NO DATA;

SELECT add_compression_policy('fdc_sensor_readings', INTERVAL '7 days');
SELECT add_retention_policy('fdc_sensor_readings', INTERVAL '90 days');
```

### 7.3 pgvector

- 向量表（RAG 文档块）embedding 列类型 `vector(1024)`；规模 > 10 万条时建 HNSW 索引：`CREATE INDEX ON doc_chunks USING hnsw (embedding vector_cosine_ops)`。

## 8. 迁移规范

1. 全部结构/数据变更写成 **sequelize migration**，文件名时间戳前缀：`20261015090001-add-yield-baseline.ts`，入 `database/migrations/`。
2. **向前兼容两阶段发布**：
   - 阶段一（随 vN 发布）：只做加列（可空/带默认）、加表、加索引（`CONCURRENTLY`）；旧代码不受影响；
   - 阶段二（随 vN+1 发布）：切换读写新列后，再出删除旧列的 migration。
   - **禁止**在同一版本中"加列 + 删旧列"一步到位。
3. **禁止直接改生产**：migration 由 CI/CD 流水线在部署阶段执行（`sequelize-cli db:migrate`），生产手工操作须经技术负责人 + DevOps 双人授权并全程留痕。
4. 建/删索引必须 `CONCURRENTLY`；migration 必须提供 `down` 回滚（不可逆的须注明原因与恢复预案）。

```javascript
// ✅ 正例：向前兼容的加列迁移
module.exports = {
  up: async (queryInterface) => {
    const t = queryInterface.sequelize;
    await t.transaction(async () => {
      await queryInterface.addColumn('wafer_lots', 'baseline_yield', {
        type: Sequelize.NUMERIC(6, 4),
        allowNull: true, // 可空，旧代码兼容
      });
    });
  },
  down: async (queryInterface) => {
    await queryInterface.removeColumn('wafer_lots', 'baseline_yield');
  },
};
```

## 9. Neo4j 规范

| 对象 | 规则 | 正例 |
|---|---|---|
| 节点标签 | 大驼峰 PascalCase | `:Equipment`、`:ProcessStep`、`:DefectMode` |
| 关系类型 | 大写蛇形，动词方向语义 | `:CAUSES`、`:PART_OF`、`:MEASURED_BY` |
| 属性名 | camelCase | `equipmentName`、`installedAt` |
| 节点唯一约束 | 每个标签必须定义业务唯一键 | `CREATE CONSTRAINT eq_no FOR (e:Equipment) REQUIRE e.equipmentNo IS UNIQUE` |

- 查询必须参数化（`$param`），禁止字符串拼接 Cypher（注入风险）。
- 图查询路径深度限制 ≤ 4 跳；深度遍历前先用唯一约束/索引定位起点。
- 图谱结构变更（新增标签/关系类型）同样走 migration 脚本版本化（`database/graph-migrations/`）。

```cypher
// ✅ 正例：参数化 + 索引起点 + 限深
MATCH (d:DefectMode {code: $defectCode})-[r:CAUSES*1..3]-(related:ProcessStep)
RETURN d, related LIMIT 50;

// ❌ 反例：拼接 + 无界遍历
MATCH (d {name: '${userInput}'})-[r*]-(n) RETURN n;
```

## 10. 数据安全

### 10.1 脱敏字段清单（查询/日志/导出必须脱敏）

| 字段 | 脱敏规则 | 示例 |
|---|---|---|
| 用户手机号 | 中间 4 位掩码 | 138****5678 |
| 用户邮箱 | 首字符 + 域名保留 | z***@ia.com |
| 访问令牌 / API Key | 仅保留前 4 位 | eyJh**** |
| 工艺配方参数（敏感 Recipe） | 导出须审批 + 打水印 | — |
| 客户代码 | 按客户等级掩码或禁导出 | — |

### 10.2 备份与恢复要求

| 指标 | 要求 |
|---|---|
| RPO（最大可容忍数据丢失窗口） | < **15 分钟**（PostgreSQL 持续 WAL 归档 + TimescaleDB 增量） |
| RTO（最大恢复时间） | < **1 小时** |
| 备份策略 | 每日全量 + WAL 连续归档至 MinIO 异地桶；Neo4j 每日 `dump` |
| 恢复演练 | 每季度一次，DevOps 主持并留演练报告 |
| 保留周期 | 全量 30 天，月备 1 年 |

### 10.3 访问与审计

- 应用账号（industryagent_app）仅授予 DML，DDL 由迁移专用账号持有；禁止业务代码使用 superuser。
- 涉及导出、批量删除的 SQL 审计日志保留 ≥ 180 天。
- 数据不出域：禁止将生产数据拷贝至外部环境；开发/测试使用合成数据（见手册第 9 章数据策略）。

## 11. 检查清单速览

- [ ] 表/字段/索引命名符合第 2 章规则
- [ ] id BIGINT 主键 + created_at/updated_at/deleted_at 齐备
- [ ] 精度敏感字段用 NUMERIC，枚举有 CHECK/字典表
- [ ] 无 SELECT *，JOIN 有索引，分页合规，慢查询 < 200ms
- [ ] 索引 ≤ 6 个/表，符合最左前缀与区分度要求
- [ ] 事务短小、无循环事务、无事务内慢 IO
- [ ] hypertable 分区键为 time，查询带时间窗，聚合走连续聚合
- [ ] migration 两阶段向前兼容，未直连生产
- [ ] Neo4j 标签/关系/属性命名合规，Cypher 参数化
- [ ] 脱敏清单落实，备份 RPO<15min / RTO<1h
