## 1. E2E 范围与原则

端到端测试在真实浏览器中验证**完整业务闭环**，成本最高、稳定性最差，因此遵循以下原则：

1. **只覆盖核心业务闭环，不超过 30 条**。UI 细节回归交给组件测试，接口契约交给集成测试。
2. **一条用例 = 一条可向业务演示的路径**。不能向产品经理讲述的场景，不配进入 E2E 套件。
3. **断言结构与状态，不断言自然语言全文**。LLM 生成的报告文字逐次不同，断言结构化字段（嫌疑数量、置信度区间、报告章节存在性）。
4. **每条用例数据自隔离**，失败原因可唯一归因。
5. **无裸等待**：显式等待 locator / 状态，`page.waitForTimeout` 一律禁止（见 §6 稳定剂）。

## 2. 核心 E2E 场景清单

| 编号 | 场景 | 链路 | 优先级 | 说明 |
|---|---|---|---|---|
| E2E-01 | 良率异常全链路（主闭环） | 登录→看板→异常详情→根因Top3→审批→8D报告 | P0 | 覆盖监控→根因→建议→审批→报告五个 Agent，发布必过 |
| E2E-02 | 拒绝建议后重新生成 | 登录→异常详情→根因Top3→审批【拒绝+理由】→建议重新生成 | P0 | HITL 否决分支 |
| E2E-03 | 权限隔离 | viewer 登录→看板只读→审批入口不可见/403 | P0 | RBAC 核心安全路径 |
| E2E-04 | 告警到看板实时性 | 注入传感器异常→看板 WebSocket 推送→30s 内出现新告警 | P1 | 验证 Kafka→前端推送链路 |
| E2E-05 | 报告归档下载 | 完成审批后→报告页→下载 8D PDF→MinIO 签名 URL 可用 | P1 | 报告 Agent + MinIO |
| E2E-06 | 会话与审计 | 登录→审批→退出→审计日志页可见本人审批记录 | P2 | 合规要求 |
| E2E-07 | 低置信强制人工复核 | 根因置信度<0.5→系统拒绝直提审批→提示人工复核 | P2 | 阈值边界（联动 IA-QA-002 §6.2） |
| E2E-08 | 断线重连恢复 | 看板停留中断网 10s→恢复→数据自动追齐 | P3 | 弱网容忍 |

当前在库 8 条，上限 30 条。新增场景必须替换或说明与现有场景的覆盖差异，防止套件无限膨胀。

## 3. Playwright 工程结构（Page Object 模式）

```
e2e/
├── playwright.config.ts          # 全局配置： baseURL、workers、trace、video
├── tests/                        # 用例层：只写业务流程
│   ├── e2e01-full-loop.spec.ts
│   ├── e2e02-approval-reject.spec.ts
│   └── ...
├── pages/                        # POM 层：页面元素与操作封装
│   ├── LoginPage.ts
│   ├── DashboardPage.ts
│   ├── AnomalyDetailPage.ts
│   ├── ApprovalPanel.ts
│   └── ReportPage.ts
├── fixtures/                     # 测试夹具
│   ├── auth.ts                   # 预置登录态（storageState）
│   ├── tenant.ts                 # 每用例独立租户/数据前缀
│   └── seed.ts                   # 调用后端 seed API 准备数据
└── utils/
    ├── api.ts                     # API 侧车：绕过 UI 准备/查询数据
    └── wait.ts                    # 封装的业务语义等待
```

分层规则：`tests/` 内不出现 `page.locator`（元素细节全部沉入 POM）；`pages/` 内不出现业务断言以外的流程编排。

## 4. 完整示例代码

### 4.1 登录页 POM

```typescript
// e2e/pages/LoginPage.ts
import { Page, Locator, expect } from '@playwright/test';

export class LoginPage {
  readonly page: Page;
  readonly usernameInput: Locator;
  readonly passwordInput: Locator;
  readonly submitButton: Locator;
  readonly errorMsg: Locator;

  constructor(page: Page) {
    this.page = page;
    this.usernameInput = page.getByPlaceholder('工号 / 邮箱');
    this.passwordInput = page.getByPlaceholder('密码');
    this.submitButton = page.getByRole('button', { name: '登录' });
    this.errorMsg = page.getByTestId('login-error');
  }

  async goto() {
    await this.page.goto('/login');
    await expect(this.usernameInput).toBeVisible();
  }

  async login(username: string, password: string) {
    await this.usernameInput.fill(username);
    await this.passwordInput.fill(password);
    await this.submitButton.click();
    // 等待登录成功的确定性信号：跳转到看板（禁止 waitForTimeout）
    await expect(this.page).toHaveURL(/\/dashboard/);
  }

  async loginExpectFail(username: string, password: string) {
    await this.usernameInput.fill(username);
    await this.passwordInput.fill(password);
    await this.submitButton.click();
    await expect(this.errorMsg).toBeVisible();
  }
}
```

### 4.2 根因分析流程 E2E 用例（E2E-01 主闭环）

```typescript
// e2e/tests/e2e01-full-loop.spec.ts
import { test, expect } from '../fixtures/tenant';   // tenant fixture 见 §5
import { LoginPage } from '../pages/LoginPage';
import { DashboardPage } from '../pages/DashboardPage';
import { AnomalyDetailPage } from '../pages/AnomalyDetailPage';
import { ApprovalPanel } from '../pages/ApprovalPanel';
import { ReportPage } from '../pages/ReportPage';

test.describe('E2E-01 良率异常全链路：登录→看板→详情→Top3→审批→8D', () => {
  test('工艺工程师应完成一次完整的根因分析与审批闭环', async ({ page, tenant }) => {
    test.setTimeout(6 * 60 * 1000); // 端到端目标 <5min，预留 CI 抖动余量

    // ---- 准备：通过 API 侧车注入一条带漂移特征的 P1 异常（秒级，不走 UI）----
    const anomalyNo = await tenant.seedAnomaly({
      lot: `LOT-${tenant.prefix}-E2E01`,
      defectCode: 'CD_UNIF',
      severity: 'P1',
      sensorProfile: 'drift',   // 合成时序：25 分钟后均值 +3σ
    });

    // ---- 1. 登录 ----
    const login = new LoginPage(page);
    await login.goto();
    await login.login(tenant.users.processEngineer, 'Passw0rd!e2e');

    // ---- 2. 看板：新告警 30s 内可见（WebSocket 推送）----
    const dashboard = new DashboardPage(page);
    await expect
      .async(() => expect(page.getByTestId(`anomaly-${anomalyNo}`)).toBeVisible())
      .toPass({ timeout: 30_000 });

    // ---- 3. 进入异常详情 ----
    await dashboard.openAnomaly(anomalyNo);
    const detail = new AnomalyDetailPage(page);
    await expect(detail.heading).toContainText(anomalyNo);
    await expect(detail.sensorChart).toBeVisible();   // 时序图渲染完成

    // ---- 4. 发起根因分析并等待 Top-3 ----
    await detail.clickStartRca();
    // 等待策略：先等任务受理的进度条出现，再等 Top-3 表格渲染（确定性节点，无裸 sleep）
    await expect(detail.rcaProgress).toBeVisible({ timeout: 10_000 });
    await expect(detail.suspectTable).toBeVisible({ timeout: 5 * 60_000 }); // G5: <5min
    const suspects = detail.suspectRows();
    await expect(suspects).toHaveCount(3);
    // 断言结构化字段：Top-3 存在、置信度合法降序（不断言文案）
    const confidences: number[] = [];
    for (const row of await suspects.all()) {
      const text = await row.getByTestId('confidence').innerText();
      const value = Number(text.replace('%', '')) / 100;
      expect(value).toBeGreaterThanOrEqual(0);
      expect(value).toBeLessThanOrEqual(1);
      confidences.push(value);
    }
    expect([...confidences].sort((a, b) => b - a)).toEqual(confidences);

    // ---- 5. HITL 审批：批准 Top-1 建议（模拟审批人操作）----
    const approval = new ApprovalPanel(page);
    await approval.approveTop1('E2E-01 自动化审批：同意下调温度 2℃');
    await expect(approval.resultBanner).toHaveText(/已批准/);

    // ---- 6. 8D 报告生成与查看 ----
    const report = new ReportPage(page);
    await report.open(anomalyNo);
    await expect(report.downloadButton).toBeVisible({ timeout: 60_000 });
    for (const section of ['D1 团队', 'D2 问题描述', 'D4 根本原因', 'D8 预防']) {
      await expect(report.section(section)).toBeVisible();  // 报告章节完整性
    }

    // ---- 7. 审计落库校验（API 侧车，闭环留痕）----
    const audit = await tenant.getAuditLogs(anomalyNo);
    expect(audit.some(l => l.action === 'APPROVE_SUGGESTION')).toBeTruthy();
  });
});
```

### 4.3 HITL 审批 POM（拒绝分支供 E2E-02 复用）

```typescript
// e2e/pages/ApprovalPanel.ts
import { Page, Locator, expect } from '@playwright/test';

export class ApprovalPanel {
  readonly approveBtn: Locator;
  readonly rejectBtn: Locator;
  readonly commentBox: Locator;
  readonly resultBanner: Locator;

  constructor(protected page: Page) {
    this.approveBtn = page.getByRole('button', { name: '批准' });
    this.rejectBtn = page.getByRole('button', { name: '驳回' });
    this.commentBox = page.getByPlaceholder('请填写审批意见');
    this.resultBanner = page.getByTestId('approval-result');
  }

  async approveTop1(comment: string) {
    await this.page.getByTestId('suspect-row-0')
      .getByRole('button', { name: '提交审批' }).click();
    await this.commentBox.fill(comment);   // HITL 强制留痕：不填意见按钮禁用
    await expect(this.approveBtn).toBeEnabled();
    await this.approveBtn.click();
  }

  async rejectTop1(reason: string) {
    await this.page.getByTestId('suspect-row-0')
      .getByRole('button', { name: '提交审批' }).click();
    await this.commentBox.fill(reason);
    await this.rejectBtn.click();
    await expect(this.resultBanner).toHaveText(/已驳回/);
  }
}
```

## 5. 测试账号与数据隔离策略

**每个 E2E 用例运行在独立测试租户/数据前缀之下**，杜绝用例串扰，实现并行执行安全：

```typescript
// e2e/fixtures/tenant.ts
import { test as base, expect } from '@playwright/test';
import { ApiClient } from '../utils/api';

type Tenant = {
  prefix: string;                       // 如 e2e-20261015-3381
  users: Record<'processEngineer' | 'viewer' | 'qualityEngineer', string>;
  seedAnomaly(opts: any): Promise<string>;
  getAuditLogs(anomalyNo: string): Promise<any[]>;
};

export const test = base.extend<{ tenant: Tenant }>({
  tenant: async ({ }, use) => {
    const prefix = `e2e-${Date.now()}-${Math.floor(Math.random() * 9000 + 1000)}`;
    const api = new ApiClient(process.env.E2E_API_URL!);
    const tenantId = await api.createTenant(prefix, { dirtyData: false });
    const users = await api.createTenantUsers(tenantId, [
      'processEngineer', 'viewer', 'qualityEngineer',
    ]);
    await use({
      prefix,
      users,
      seedAnomaly: o => api.seedAnomaly(tenantId, o),
      getAuditLogs: n => api.getAuditLogs(tenantId, n),
    });
    await api.disposeTenant(tenantId);   // 用例结束即清理，Staging 不留残骸
  },
});
export { expect };
```

配套规则：

1. 测试账号由 seed API 按租户动态创建，禁止共享账号；角色矩阵对齐 RBAC 设计（process_engineer / viewer / quality_engineer）。
2. 所有业务数据（异常、工单、报告）通过租户前缀（`LOT-{prefix}-*`）物理区分。
3. 审批"模拟审批人"使用专用 `quality_engineer` 账号，与发起人分离，保证审批人/发起人审计字段正确。
4. 登录态复用：登录一次后导出 `storageState`，其余用例复用以压缩时长；但权限类用例（E2E-03）必须重新走登录页。

## 6. 稳定剂（Flaky 治理）

| 措施 | 具体做法 |
|---|---|
| 显式等待 | 一律等待 locator 可见/文本/URL 等确定性信号；**禁止 `page.waitForTimeout`（CI 中以 lint 规则扫描禁用）** |
| 自动重试 | `playwright.config.ts` 配置 `retries: { open: 0, ci: 2 }`；重试仍失败才计失败 |
| 动画禁用 | 启动参数注入 CSS：`* { transition: none !important; animation: none !important; caret-color: transparent }` |
| WebSocket 轮换 | 看板推送断言用 `expect.toPass` 轮询包装，容忍首次连接抖动 |
| 网络容忍 | 静态资源 abort，只保留 API/WS，降低偶发超时 |
| trace/video | 失败自动保留 trace + 截图 + 视频（见 §7），本地一键复现 |

```typescript
// e2e/playwright.config.ts（关键片段）
export default defineConfig({
  testDir: './tests',
  fullyParallel: true,
  workers: process.env.CI ? 4 : undefined,
  retries: { open: 0, ci: 2 },
  reporter: [['html', { open: 'never' }], ['list']],
  use: {
    baseURL: process.env.E2E_BASE_URL ?? 'http://localhost:5173',
    trace: 'retain-on-failure',
    video: 'retain-on-failure',
    screenshot: 'only-on-failure',
    actionTimeout: 10_000,
    navigationTimeout: 30_000,
  },
  projects: [{ name: 'chromium', use: { ...devices['Desktop Chrome'] } }],
});
```

## 7. CI 集成

1. **触发**：夜间定时全量（每日 02:00）+ 发布前手工触发；PR 阶段只跑 P0 用例（E2E-01~03）作为门禁。
2. **并行执行**：`fullyParallel: true` + 4 workers；租户隔离保证并行安全；单次全量 ≤ 40 分钟。
3. **失败取证**：`trace: retain-on-failure` + 截图 + 视频，连同 `playwright-report/index.html` 一并归档为 CI artifacts，保留 14 天。
4. **失败分级响应**：P0 用例失败即阻塞发布（参照 IA-QA-001 缺陷定级）；连续 3 次 flaky 的用例必须治理（根因分析或降级到集成层），禁止无限重试掩盖。

```yaml
# .github/workflows/e2e.yml（片段）
  - name: Run E2E (P0 gate)
    if: github.event_name == 'pull_request'
    run: npx playwright test --grep "@p0"
  - name: Run E2E (full suite)
    if: github.event_name == 'schedule'
    run: npx playwright test
  - uses: actions/upload-artifact@v4
    if: failure()
    with:
      name: playwright-artifacts
      path: |
        playwright-report/
        test-results/
      retention-days: 14
```

## 8. HITL 审批环节的 E2E 处理要点

1. **真实操作而非 API 直改**：审批是主闭环的核心节点，E2E 中必须模拟审批人 UI 操作（点击、填意见、提交），不得用接口把状态直接改成"已批准"。
2. **审批人账号独立**：使用 `quality_engineer` 等具备审批权限的账号，验证 RBAC 的同时也验证发起人/审批人审计分离。
3. **强制留痕断言**：审批意见为空时按钮禁用（组件测试已覆盖交互，E2E 断言流程层：审批完成后审计日志含 `APPROVE_SUGGESTION` 且记录审批人）。
4. **异步状态收敛**：审批提交后后端写库 + Kafka 通知报告 Agent 存在毫秒级延迟，断言使用 `expect(...).toBeVisible` 自动等待而非 sleep。
5. **驳回分支成对覆盖**：E2E-02 验证驳回后建议重新生成的状态机迁移，与 E2E-01 批准分支构成审批闭环双向覆盖。

## 9. 用例评审与维护

1. 新增 E2E 用例须附场景说明与手动演示对照，测试工程师评审后方可入库。
2. 每迭代末梳理 flaky 清单，flaky 率（连续 10 次执行中非确定性失败）超过 5% 的用例必须下线治理。
3. 套件规模红线：30 条。超出必须裁剪——优先保留 P0 主闭环与权限路径。
