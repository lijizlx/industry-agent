## 1. 目的与适用范围

本规范定义 IndustryAgent 项目单元测试的范围边界、编写标准、覆盖率门禁与评审要求，适用于后端（Egg.js 4.0）、前端（React 18 + TS）、智能体服务（Python FastAPI + LangGraph）三个代码库。单元测试的目标是**以最低成本获得最快的缺陷反馈**，因此必须做到：无网络、无数据库、无 LLM、无文件系统真实写入，单次全量运行 ≤ 10 分钟。

## 2. 范围与优先级

### 2.1 必须测试（强制覆盖）

| 类别 | 示例 | 优先级 |
|---|---|---|
| Service 层业务逻辑 | 告警聚合、工单状态机、审批流转换、权限判断 | P0 |
| 工具函数 | 时间窗计算、阈值比较、分页参数归一化、脱敏函数 | P0 |
| 智能体工具函数 | `query_knowledge_graph`、`rag_search`、`timeseries_window` 等工具的入参处理与结果归一化 | P0 |
| 提示词组装逻辑 | 提示词模板拼接、变量注入、边界变量 | P1 |
| 自定义 Hook | 前端数据请求轮询 hook、审批表单 hook | P1 |
| 展示型组件（含逻辑） | 置信度徽章、审批结果标签、告警级别过滤 | P1 |

### 2.2 可以不测试

1. 第三方库内部实现（Egg.js 插件、React、LangGraph 框架本身）。
2. 纯数据声明（常量表、配置文件、类型定义）。
3. 纯 UI 摆放组件（无逻辑的静态布局），由 E2E 覆盖。
4. 与真实数据库/Kafka/LLM 的交互——归 IA-QA-003 集成测试管辖。

### 2.3 优先级排序原则

按"变更频率 × 业务影响 × 故障代价"排序：审批状态机与权限判断最高（缺陷代价 P0），工具函数次之，展示组件最低。

## 3. 后端单元测试（Egg.js，mocha + chai + sinon）

### 3.1 命名与组织

- 文件放置：`test/unit/service/{service名}.test.js`，与源文件一一对应。
- 描述结构：`describe('Service名.方法名')` → `it('应在【条件】时【行为】')`，用例名可读为自然语言。
- 每个用例独立：`beforeEach` 重建 stub，禁止用例间共享可变状态。

### 3.2 Egg.js Service 单测完整示例（根因嫌疑排序服务）

以下示例覆盖：正常分支、空输入分支、数据库异常分支、脏数据处理分支。

```javascript
// test/unit/service/rcaRankService.test.js
const { expect } = require('chai');
const sinon = require('sinon');
const assert = require('assert');

describe('service/rcaRank 生成根因嫌疑排名', () => {
  let ctx;
  let app;
  let rcaRankService;

  beforeEach(() => {
    // 构造 mock app 与 ctx：不启动真实 Egg 应用
    app = {
      model: {
        Suspect: {
          findOne: sinon.stub(),
          create: sinon.stub(),
        },
        Anomaly: { findByPk: sinon.stub() },
      },
      redis: { get: sinon.stub(), set: sinon.stub() },
    };
    ctx = { logger: { warn: sinon.stub(), error: sinon.stub() } };
    rcaRankService = require('../../app/service/rcaRankService')(ctx, app);
  });

  afterEach(() => sinon.restore());

  it('应在多嫌疑因素输入时返回按置信度降序的 Top-3', async () => {
    const suspects = [
      { cause: 'ETCH-07 温度漂移', confidence: 0.72 },
      { cause: 'PHOTO-12 光强尖峰', confidence: 0.91 },
      { cause: 'IMP-03 注入剂量漂移', confidence: 0.85 },
      { cause: 'CMP-05 压力异常', confidence: 0.40 },
    ];
    app.model.Suspect.create.resolves({ id: 1 });

    const result = await rcaRankService.rankTop3('ANM-20261015-001', suspects);

    expect(result).to.have.lengthOf(3);
    expect(result[0].cause).to.equal('PHOTO-12 光强尖峰');
    expect(result.map(s => s.confidence)).to.deep.equal([0.91, 0.85, 0.72]);
  });

  it('应在输入为空数组时返回空列表且不写库', async () => {
    const result = await rcaRankService.rankTop3('ANM-20261015-002', []);
    expect(result).to.deep.equal([]);
    assert.ok(app.model.Suspect.create.notCalled);
  });

  it('应在置信度非法（NaN/负数/大于1）时剔除该项并记录 warn 日志', async () => {
    const suspects = [
      { cause: 'A', confidence: 0.5 },
      { cause: 'B', confidence: NaN },
      { cause: 'C', confidence: 1.5 },
      { cause: 'D', confidence: -0.1 },
    ];
    const result = await rcaRankService.rankTop3('ANM-20261015-003', suspects);
    expect(result).to.have.lengthOf(1);
    expect(result[0].cause).to.equal('A');
    assert.ok(ctx.logger.warn.calledThrice); // 每条脏数据一条 warn
  });

  it('应在数据库写入抛异常时返回排序结果并记录 error 日志（降级不阻断）', async () => {
    app.model.Suspect.create.rejects(new Error('ECONNREFUSED'));
    const suspects = [{ cause: 'ETCH-07 温度漂移', confidence: 0.8 }];
    const result = await rcaRankService.rankTop3('ANM-20261015-004', suspects);
    expect(result).to.have.lengthOf(1);
    assert.ok(ctx.logger.error.calledOnce);
  });

  it('应在异常事件不存在时抛出业务异常 INVALID_ANOMALY', async () => {
    app.model.Anomaly.findByPk.resolves(null);
    await expect(
      rcaRankService.rankTop3('ANM-NOT-EXIST', [{ cause: 'A', confidence: 0.5 }])
    ).to.be.rejectedWith('INVALID_ANOMALY');
  });
});
```

### 5.2 提示词回归测试思路

提示词模板变更极易引发质量回归（Top-3 准确率、误报率），采用三层防线：

1. **快照测试**：将提示词模板渲染结果存入 `snapshots/` 目录，pytest 快照比对——模板变更必须显式更新快照，防止无意识改动。
2. **结构断言**：断言 LLM 输出解析后的 JSON 结构（`suspects` 长度 ∈ [1,3]、`confidence ∈ [0,1]`、必填字段存在），用固定 mock 响应驱动。
3. **评估集回归（联动 IA-QA-001 §7.3）**：模板/模型/温度参数任何变更，CI 触发标注评估集跑批，Top-3 准确率下降超过 2 个百分点即阻断合并。

## 6. 用例设计方法实例（边界值 + 等价类）

### 6.1 分页参数（page / pageSize）

有效等价类：`1 ≤ page ≤ 10^6`、`1 ≤ pageSize ≤ 100`；无效等价类：非数字、0、负数、超上限。

| 用例 | 输入 (page, pageSize) | 期望 |
|---|---|---|
| 等价类-正常 | (1, 20) | 正常返回第一页 |
| 边界-min | (1, 1) | 合法，返回 1 条 |
| 边界-min-1 | (0, 20) | 归一化为 page=1（或 422，按接口约定） |
| 边界-max | (1, 100) | 合法，返回最多 100 条 |
| 边界-max+1 | (1, 101) | 归一化为 pageSize=100 |
| 等价类-非数字 | ('abc', 20) | 422 / 归一化默认值 |
| 边界-超深翻页 | (10^6+1, 20) | 返回空列表（不报错、不拖库） |

### 6.2 置信度阈值（Top-3 展示与审批门槛）

阈值定义：`confidence ≥ 0.8` 高置信（徽章绿色、可直提审批）；`0.5 ≤ confidence < 0.8` 中置信（黄色、需补充证据）；`< 0.5` 低置信（红色、强制人工复核）。

| 用例 | confidence 输入 | 期望分类 | 期望行为 |
|---|---|---|---|
| 边界-下界 | 0.5 | 中置信 | 黄色徽章 |
| 边界-下界-1 | 0.499999 | 低置信 | 红色徽章、拦截直提 |
| 边界-上界 | 0.8 | 高置信 | 绿色徽章、可直提审批 |
| 边界-上界+1 | 0.800001 | 高置信 | 绿色徽章 |
| 等价类-合法两端 | 0 / 1 | 低/高置信 | 不抛异常 |
| 等价类-非法 | NaN / '0.8' / 1.5 / -0.1 | — | 剔除该项 + warn 日志（见 §3.2） |

### 6.3 其他强制应用场景

边界值/等价类法必须应用于：Kafka 消费批大小、时间窗（分钟）参数、8D 报告字段长度上限、Top-K（1~3）、审批意见长度（1~500 字）。规则：任何数值型输入至少覆盖 min、min-1、max、max+1、正常值五个用例。


### 7.2 前端（vitest thresholds）

`vitest.config.ts` 中 `coverage.thresholds` 设为 70（见 §4.1），低于阈值 vitest 进程退出码非 0，CI 失败。

### 7.3 智能体服务（pytest-cov）

```yaml
# .github/workflows/agent-ci.yml（片段）
- name: Run agent unit tests with coverage gate
  run: |
    pytest tests/unit --cov=app --cov-report=term \
      --cov-fail-under=80 --cov-report=xml:coverage.xml
```

### 7.4 门禁规则

1. 后端语句/分支 ≥ 80%，前端语句/分支 ≥ 70%，智能体服务 ≥ 80%（核心 `app/tools`、`app/prompts` ≥ 85%）。
2. 覆盖率门禁在 CI 中为**硬门禁**：不达标即失败，禁止 `continue-on-error` 跳过。
3. 增量代码要求：新增/修改文件覆盖率不得低于存量平均水平 5 个百分点以上。
4. 覆盖率报告（lcov）作为 CI artifact 归档，纳入迭代质量小结。

## 8. 编写与评审检查清单

提交单测 PR 前自查：

- [ ] 所有外部依赖（DB/Redis/Kafka/LLM/HTTP）均为 stub/mock，无网络调用

- [ ] 用例名描述业务语义而非实现细节
- [ ] 新增公共工具函数/Service 方法的单测与源码同一 PR 提交
