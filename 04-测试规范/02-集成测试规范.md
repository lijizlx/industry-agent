## 1. 目的与范围

集成测试验证**模块间接口契约**：数据能按预期在两个模块之间流动、事务边界正确、故障传播可控。本规范覆盖以下接口边界：

| 编号 | 接口边界 | 关键验证点 |
|---|---|---|
| INT-1 | Egg.js ↔ PostgreSQL/TimescaleDB | 事务原子性、迁移脚本可重放、连接池耗尽降级 |
| INT-2 | Egg.js ↔ Python 智能体服务（FastAPI） | HTTP 契约、超时/重试、降级策略 |
| INT-3 | Kafka 消费链路（传感器事件→TimescaleDB→告警） | 消费落库、积压、重复消费幂等、乱序容忍 |
| INT-4 | Egg.js/Python ↔ Neo4j | 图查询参数与返回结构、连接超时 |
| INT-5 | Python ↔ MinIO | 8D 报告 PDF/缺陷图存取、签名 URL 有效期 |
| INT-6 | Egg.js ↔ Redis | 缓存读写、缓存击穿保护 |
| INT-7 | 契约测试（Egg.js ↔ FastAPI，JSON Schema） | 请求/响应结构防漂移 |

不在范围：页面渲染（E2E 覆盖）、纯函数逻辑（单测覆盖）。

### 3.1 事务测试

```javascript
// test/integration/db/transaction.test.js
const { expect } = require('chai');
const { app } = require('../helpers/bootstrap'); // 已连接 test stack

describe('告警确认事务 [INT-1]', () => {
  it('应在同一事务中更新告警状态并写入审计日志，任一失败整体回滚', async () => {
    const anomalyId = await seedAnomaly({ level: 'P1', lot: 'LOT-TX-01' });
    // 预埋审计表约束冲突：让 AuditLog 插入失败，验证整体回滚
    await app.model.AuditLog.sync({ force: false });
    const brokenAudit = { anomalyId, approverId: null }; // 违反 NOT NULL

    let err;
    try {
      await app.model.transaction(async t => {
        await app.model.Anomaly.update(
          { status: 'CONFIRMED' },
          { where: { id: anomalyId }, transaction: t }
        );
        await app.model.AuditLog.create(brokenAudit, { transaction: t });
      });
    } catch (e) { err = e; }

    expect(err).to.exist;
    const anomaly = await app.model.Anomaly.findByPk(anomalyId);
    expect(anomaly.status).to.not.equal('CONFIRMED'); // 告警状态未被半提交
  });

  it('应在迁移脚本可重放：第二次执行 migrate 不报错且不重复建列', async () => {
    const { execSync } = require('child_process');
    execSync('npx sequelize db:migrate', { env: process.env });
    const cols = await app.queryInterface.describeTable('anomalies');
    expect(cols.confidence).to.exist;
  });
});
```

### 3.2 迁移脚本测试要求

1. 每个迁移脚本必须可在空库与带数据库上重复执行（幂等或幂等跳过）。
2. 迁移后执行种子数据 seed，校验关键表行数与约束。
3. 回滚脚本（`db:migrate:undo`）必须同样纳入测试，支持发布失败回退。

## 4. API 集成测试（supertest）

### 4.1 完整根因分析流程 happy path

```javascript
// test/integration/api/rcaFlow.test.js
const { expect } = require('chai');
const request = require('supertest');
const { app, seedAnomaly } = require('../helpers/bootstrap');
const { loginAs } = require('../helpers/auth');

describe('根因分析全流程 API [INT-2] happy path', () => {
  let token;

  before(async () => {
    token = await loginAs('process_engineer'); // RBAC：工艺工程师
  });

  it('POST /api/v1/anomalies/:id/rca → 应在 5 分钟内返回 Top-3 嫌疑并入库', async () => {
    const anomalyId = await seedAnomaly({
      lot: 'LOT-E2E-001',
      defectCode: 'CD_UNIF',
      severity: 'HIGH',
      sensorTrail: [/* 30 分钟合成时序，含漂移特征 */],
    });

    const res = await request(app.callback())
      .post(`/api/v1/anomalies/${anomalyId}/rca`)
      .set('Authorization', `Bearer ${token}`)
      .send({ topK: 3 })
      .expect(202); // 异步任务受理

    const taskId = res.body.data.taskId;
    expect(taskId).to.be.a('string');

    // 轮询任务状态直至 done（内部轮询间隔 2s，总超时 5min）
    const deadline = Date.now() + 5 * 60 * 1000;
    let payload;
    while (Date.now() < deadline) {
      const poll = await request(app.callback())
        .get(`/api/v1/rca-tasks/${taskId}`)
        .set('Authorization', `Bearer ${token}`);
      if (poll.body.data.status === 'done') { payload = poll.body.data.result; break; }
      expect(poll.body.data.status).to.be.oneOf(['queued', 'running']);
      await new Promise(r => setTimeout(r, 2000));
    }

    expect(payload, '5 分钟内必须完成').to.exist;
    expect(payload.suspects).to.have.lengthOf(3);
    expect(payload.suspects.map(s => s.confidence))
      .to.satisfy(cs => cs.every(c => c >= 0 && c <= 1));
    expect(payload.suspects).to.satisfy(ss =>
      ss[0].confidence >= ss[1].confidence && ss[1].confidence >= ss[2].confidence);

    // 结果已持久化
    const saved = await request(app.callback())
      .get(`/api/v1/anomalies/${anomalyId}/suspects`)
      .set('Authorization', `Bearer ${token}`)
      .expect(200);
    expect(saved.body.data).to.have.lengthOf(3);
  });
});
```

### 5.1 mock LLM 的契约测试（自研 JSON Schema 校验）

原则：功能集成测试**永不调用真实 LLM**，用 fixture 固化 LLM 输出，验证 FastAPI 服务对输入输出的契约。

```python
# tests/integration/test_rca_contract.py
import json
import pytest
from fastapi.testclient import TestClient
from jsonschema import validate, ValidationError
from app.main import app
from tests.fixtures.llm_stubs import LLMBusStub

RCA_RESPONSE_SCHEMA = {
    "type": "object",
    "required": ["taskId", "status", "result"],
    "properties": {
        "taskId": {"type": "string", "pattern": "^rca-[0-9a-f-]{36}$"},
        "status": {"type": "string", "enum": ["done", "failed"]},
        "result": {
            "type": "object",
            "required": ["suspects"],
            "properties": {
                "suspects": {
                    "type": "array", "minItems": 1, "maxItems": 3,
                    "items": {
                        "type": "object",
                        "required": ["cause", "confidence", "evidence"],
                        "properties": {
                            "cause": {"type": "string", "minLength": 1},
                            "confidence": {"type": "number", "minimum": 0, "maximum": 1},
                            "evidence": {"type": "array", "items": {"type": "string"}},
                        },
                    },
                },
            },
        },
    },
}

@pytest.fixture
def client(llm_stub):
    app.state.llm_bus = llm_stub
    return TestClient(app)

@pytest.mark.parametrize("llm_stub", [
    LLMBusStub(r'{"suspects":[{"cause":"ETCH-07 温度漂移","confidence":0.91,"evidence":["FDC 10:23 告警"]}]}'),
], indirect=True)
def test_rca_endpoint_contract(client, seeded_anomaly):
    """Egg.js↔FastAPI 契约：无论 LLM 返回什么文本，接口必须产出结构合法的 JSON。"""
    resp = client.post("/v1/rca/analyze", json={"anomalyId": seeded_anomaly, "topK": 3})
    assert resp.status_code == 200
    validate(instance=resp.json(), schema=RCA_RESPONSE_SCHEMA)  # 结构漂移即失败

def test_rca_contract_rejects_llm_garbage(client_garbage_llm):
    """LLM 输出无法解析时必须 failed 且带 reason，不得返回 500。"""
    resp = client_garbage_llm.post("/v1/rca/analyze", json={"anomalyId": "ANM-X", "topK": 3})
    body = resp.json()
    assert body["status"] == "failed"
    assert "reason" in body
    assert resp.status_code == 200
```

## 6. 消息队列测试（INT-3）

| 场景 | 构造方式 | 验证点 |
|---|---|---|
| 正常消费落库 | producer 发送 100 条合成传感器事件 | TimescaleDB 行数一致、无丢失 |
| 重复消费 | 同一事件重发 3 次（重平衡/重试模拟） | 幂等：落库仅 1 条（事件 ID 去重） |
| 乱序到达 | 按时间戳倒序发送 | 乱序容忍：窗口聚合结果正确或标记 `out_of_order` |
| 积压 | 注入 50000 条后观察消费速率 | Lag 恢复时间 < 10 分钟、无 OOM |
| 延迟注入 | producer 端 `delayConnection` | 端到端延迟指标正确上报 |


## 8. 契约测试方案（JSON Schema）

考虑到 Egg.js 与 FastAPI 同仓演进、双向调用方单一，采用**自研 JSON Schema 契约**而非引入 Pact broker，降低维护成本：

1. `contracts/` 目录存放接口 schema：`rca-analyze.request.json`、`rca-analyze.response.json`、`approval.request.json` 等。
2. 双方 CI 均执行契约校验：请求方以 schema 校验响应，服务方以 schema 校验自己的响应（双保险）。
3. 修改契约 = 修改 schema 文件，PR 显式可见，任何一方单独变更契约即失败。

```javascript
// test/contract/verify-contracts.test.js
```

## 9. 测试数据准备：seed 脚本 + 工厂函数

```javascript
// test/helpers/factories.js — 工厂函数：确定性合成 + 脏数据注入开关
const faker = require('@faker-js/faker').faker;

function makeSensorTrail({ minutes = 30, dirty = false } = {}) {
  const trail = [];
  for (let i = 0; i < minutes; i++) {
    let value = 80 + Math.sin(i / 5) * 2 + (Math.random() - 0.5);
    if (dirty && i === 22) value = null;              // 缺失
    if (dirty && i > 25) value += 3;                 // 漂移（+3σ）
    if (dirty && i === 15) value = 800;               // 尖峰
    trail.push({ t: Date.now() - (minutes - i) * 60000, equipment: 'ETCH-07', value });
  }
  if (dirty) trail.push(trail[trail.length - 1]);    // 重复
  return dirty ? trail.concat(trail.slice(0, 3)) : trail; // 乱序片段
}

async function seedAnomaly(overrides = {}) {
  const lot = overrides.lot || `LOT-${faker.string.alphanumeric(6).toUpperCase()}`;
  const [row] = await app.model.Anomaly.create({
    lot,
    defectCode: overrides.defectCode || 'CD_UNIF',
    severity: overrides.severity || 'HIGH',
    sensorTrail: overrides.sensorTrail || makeSensorTrail({ dirty: overrides.dirty }),
    occurredAt: overrides.occurredAt || new Date(),
  });
  return row.id;
}

module.exports = { seedAnomaly, makeSensorTrail };
```

seed 脚本要求（对齐 IA-QA-001 §7）：

1. `make seed` 幂等，可重复执行；本地/CI/Staging 同一脚本。
2. 评估数据（SECOM/WM-811K 派生）与功能数据分库前缀，禁止交叉使用。
3. 脏数据注入由 `dirty=true` 参数控制，功能用例默认关闭。
4. 每次集成测试运行使用独立数据前缀（时间戳），用例自身清理或整库销毁。

## 10. 执行与 CI 要求

| 项 | 要求 |
|---|---|
| 触发 | 每次 push 到 main / 迭代分支；PR 必跑 |
| 时长预算 | 全量集成 ≤ 25 分钟，超时即失败（防隐性挂起） |
| 隔离 | 每任务独立容器栈，禁止复用 |
| 用例顺序 | 支持 `--parallel`，用例间禁止共享状态 |
| 失败处理 | 首次失败自动重跑 1 次（容器抖动容错），再失败即判失败 |
| 报告 | mochawesome HTML 报告归档为 CI artifact |
