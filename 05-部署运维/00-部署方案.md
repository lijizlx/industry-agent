## 1. 概述

### 1.1 目的

本文档定义 IndustryAgent（工业智能体平台——半导体良率根因分析智能体）的部署环境规划、资源规划、网络规划、域名与 TLS 策略、Docker Compose 部署步骤、环境变量清单、Kubernetes 生产形态以及数据初始化流程，作为开发、测试、运维团队部署实施的统一依据。

### 1.2 适用范围

- 开发环境（本地 Docker Compose）
- CI 环境（GitHub Actions services）
- Staging 环境（单机 Compose 模拟生产）
- 生产环境（Kubernetes，沙盒中用单节点 k3s 模拟）

### 1.3 关键非功能约束

| 约束 | 要求 | 部署侧落地措施 |
|------|------|----------------|
| 可用性 | 99.9% | 健康检查 + 自动重启；K8s 多副本 + 滚动更新 |
| 数据不出域 | 私有化部署、全部组件本地/内网 | 镜像走内网 Harbor 或 ghcr 内网代理；无外网数据传输 |
| 端到端延迟 | < 5 分钟 | Agent 异步任务队列化，Kafka 消费能力容量规划 |
| 审计日志保留 | ≥ 1 年 | 审计日志独立卷/持久卷，按月归档至 MinIO |
| 监控告警 | 全链路可观测 | Prometheus + Grafana + Loki，见 IA-OPS-004 |

### 1.4 术语

| 术语 | 说明 |
|------|------|
| I2~I5 迭代 | 项目第 2 至第 5 次迭代，采用 Docker Compose 部署 |
| 沙盒 | 芯联半导体 12 英寸晶圆厂虚拟环境，数据不出域 |
| k3s | 轻量级 Kubernetes 发行版，用于单节点模拟生产 K8s |

## 5. 域名与 TLS

### 5.1 域名规划（企业内部 DNS 或 hosts 静态解析）

| 域名 | 指向 | 用途 |
|------|------|------|
| industryagent.internal | Nginx 443 | 生产入口 |
| staging.industryagent.internal | Nginx 443 | Staging 入口 |
| keycloak.industryagent.internal | Keycloak 8080（经 Nginx /auth） | OIDC 认证 |
| grafana.industryagent.internal | Grafana 3000 | 监控看板 |

### 5.2 证书策略

- **优先企业 CA**：向公司 PKI 申请 `*.industryagent.internal` 通配符证书，有效期 1 年。
- **沙盒回退方案：内网自签**，用 openssl 生成自签 CA 与服务证书：

```bash
# 1) 生成自签 CA（有效期 10 年）
openssl genrsa -out ca.key 4096
openssl req -new -x509 -days 3650 -key ca.key -subj "/CN=IndustryAgent Internal CA" -out ca.crt

# 2) 生成服务私钥与 CSR
openssl genrsa -out industryagent.key 2048
openssl req -new -key industryagent.key -subj "/CN=*.industryagent.internal" -out industryagent.csr

# 3) 用 CA 签发服务证书（含 SAN，有效期 1 年）
cat > san.cnf <<'EOF'
subjectAltName = DNS:industryagent.internal, DNS:staging.industryagent.internal, DNS:keycloak.industryagent.internal, DNS:grafana.industryagent.internal
EOF
openssl x509 -req -days 365 -in industryagent.csr -CA ca.crt -CAkey ca.key -CAcreateserial -extfile san.cnf -out industryagent.crt

# 4) 校验
openssl verify -CAfile ca.crt industryagent.crt
```

证书放置于 `/data/certs/`（compose 卷挂载），所有内网客户端导入 `ca.crt` 至信任库。

### 5.3 Nginx TLS 配置要点

- 仅 TLSv1.2/1.3；关闭 TLS1.0/1.1；
- HTTP 强制 301 跳转 HTTPS；
- `ssl_session_cache shared:SSL:10m` 复用会话；
- HSTS 头开启（内网自签环境同样开启，`max-age=31536000`）。

```
      ════════════════════ backend network（数据不出域）════════════════════

 观测面（monitoring network）: Prometheus :9090 → node-exporter :9100 / 各服务 /metrics

 传感器模拟数据源（MQTT/Kafka 生产者） ──> Kafka topic: wafer.sensor.readings
```

### 6.2 数据流要点

1. 传感器/合成数据生产者将时序数据写入 Kafka topic `wafer.sensor.readings`；
2. industryagent-agent 消费 Kafka → 异常检测 → 写 TimescaleDB；
3. 触发根因分析任务 → LangGraph 编排（Neo4j 图谱查询 + pgvector RAG 检索 + MinIO 缺陷图）；
4. 结论与建议经 server 审计落库，审批结果回写，形成闭环；
5. 全链路 traceId 透传，Prometheus 采集 `industryagent_*` 自定义指标。

## 7. Docker Compose 完整部署步骤（从零开始）

以下步骤适用于 Staging 单机与开发环境，以 root 或具备 docker 权限的运维账号执行。

### 7.1 安装 Docker 与 Compose 插件（Ubuntu 22.04）

```bash
# 1) 卸载旧版本（如有）
apt-get remove -y docker docker-engine docker.io containerd runc || true

# 2) 安装依赖与官方源（沙盒内网环境可用内部镜像源替换 download.docker.com）
apt-get update
apt-get install -y ca-certificates curl gnupg lsb-release
install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | gpg --dearmor -o /etc/apt/keyrings/docker.gpg
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] \
  https://download.docker.com/linux/ubuntu $(lsb_release -cs) stable" > /etc/apt/sources.list.d/docker.list
apt-get update
apt-get install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

# 3) 配置 daemon（日志轮转 + 内网 registry mirror）
mkdir -p /etc/docker
cat > /etc/docker/daemon.json <<'EOF'
{
  "log-driver": "json-file",
  "log-opts": { "max-size": "50m", "max-file": "5" },
  "registry-mirrors": ["https://harbor.industryagent.internal/v2"],
  "insecure-registries": ["harbor.industryagent.internal"]
}
EOF
systemctl enable --now docker
docker info
docker compose version
```

### 7.2 拉取代码

```bash
mkdir -p /data/app && cd /data/app
```

### 7.4 启动服务

```bash

# 2) 等待数据层就绪（观察 healthy 状态）
watch -n 5 'docker compose -f deploy/docker-compose.yml ps'

# 3) 启动安全与观测层
docker compose -f deploy/docker-compose.yml up -d keycloak opa prometheus grafana node-exporter

# 4) 启动应用层
docker compose -f deploy/docker-compose.yml up -d industryagent-server industryagent-agent industryagent-web
```

### 7.5 初始化 Keycloak Realm

方式一：脚本自动导入（推荐）。将 `deploy/keycloak/industryagent-realm.json` 放入 Keycloak 导入目录（compose 已挂载 `/opt/keycloak/data/import`），并在首次启动时执行：

```bash
docker compose -f deploy/docker-compose.yml exec keycloak \
  /opt/keycloak/bin/kc.sh import --realm industryagent \
  --file /opt/keycloak/data/import/industryagent-realm.json --override false
```

方式二：手动控制台配置（http://keycloak:8080，管理员见 .env）：

1. 创建 Realm `industryagent`；
2. 创建 Client `industryagent-web`（confidential，Valid Redirect URI：`https://staging.industryagent.internal/*`）；
3. 创建角色：`process-engineer`（工艺工程师）、`equipment-engineer`、`quality-engineer`、`admin`；
4. 创建种子用户并绑定角色：`li.gongyi` → process-engineer，`admin` → admin。

### 7.6 导入 OPA 策略

```bash
# 1) 策略文件位于 deploy/opa/policies/，包含 rca_authz.rego / approval_authz.rego
# 2) 推送策略到 OPA（bundle 模式或 REST 推送）
curl -X PUT http://127.0.0.1:8181/v1/policies/rca_authz \
  --data-binary @deploy/opa/policies/rca_authz.rego \
```

### 7.7 健康检查验证清单

```bash
cd /data/app/industryagent

# 1) 全部容器状态为 healthy / running
docker compose -f deploy/docker-compose.yml ps

# 2) 数据层探活
docker compose -f deploy/docker-compose.yml exec postgres pg_isready -U industryagent
docker compose -f deploy/docker-compose.yml exec redis redis-cli -a "$REDIS_PASSWORD" ping
docker compose -f deploy/docker-compose.yml exec kafka kafka-topics.sh --bootstrap-server localhost:9092 --list
docker compose -f deploy/docker-compose.yml exec neo4j cypher-shell -a bolt://localhost:7687 "RETURN 1 AS ok;"
curl -sf http://127.0.0.1:9000/minio/health/live && echo "minio ok"

# 3) 应用层探活
curl -sf http://127.0.0.1:7001/healthz        # 期望 {"status":"ok"}
curl -sf http://127.0.0.1:8000/healthz         # 期望 {"status":"ok"}
curl -sfk https://127.0.0.1/                   # Web 首页 200

# 4) 认证链路验证（获取 token）
curl -sk -X POST https://staging.industryagent.internal/auth/realms/industryagent/protocol/openid-connect/token \
  -d "grant_type=password&client_id=industryagent-web&username=li.gongyi&password=<密码>" | head -c 200

# 5) 监控链路验证
curl -sf http://127.0.0.1:9090/-/healthy
curl -sf http://127.0.0.1:9090/api/v1/targets | grep -c '"up"'   # 目标数应与规划一致
```

全部通过后，将结果（含时间戳截图）记录至部署检查单并归档。

## 9. Kubernetes 生产形态概述

### 9.1 Namespace 划分

| Namespace | 内容 |
|-----------|------|
| industryagent-app | web、server、agent、ingress |
| industryagent-data | postgres、redis、kafka、zookeeper、neo4j、minio（有状态） |
| industryagent-security | keycloak、opa |
| industryagent-observability | prometheus、grafana、loki、otel-collector |
| industryagent-ci | 镜像仓库代理 / Runner（Harbor 可独立于集群） |

### 9.2 工作负载形态

- **无状态（Deployment）**：web、server、agent、opa、grafana —— 副本数 ≥2，配合 PDB 与滚动更新（maxUnavailable=0）保障 99.9%。
- **有状态（StatefulSet）**：postgres、redis、kafka、zookeeper、neo4j、minio —— 通过 `volumeClaimTemplates` 绑定 PV；沙盒单节点 k3s 使用 local-path storageclass，生产规划使用企业存储（Ceph/企业 SAN）。
- **入口（Ingress）**：Nginx Ingress Controller 终结 TLS，路由规则：`/`→web-svc、`/api`→server-svc:7001、`/agent`→agent-svc:8000、`/auth`→keycloak-svc:8080；secret 挂载企业 CA 证书。
- **探针**：所有 Deployment 配置 readinessProbe/livenessProbe（/healthz，initialDelaySeconds=15，periodSeconds=10）。
- **沙盒 k3s 初始化**：

```bash
curl -sfL https://get.k3s.io | INSTALL_K3S_EXEC="--disable traefik" sh -
mkdir -p ~/.kube && cp /etc/rancher/k3s/k3s.yaml ~/.kube/config
kubectl get nodes   # 单节点 Ready 即就绪
```

## 10. 数据初始化

### 10.1 数据库迁移（幂等、可重放）

```bash
# 1) 安装迁移工具（server 内置 npm script）
cd services/server && npm ci

# 2) 执行迁移（顺序：业务表 → TimescaleDB 超表 → pgvector 扩展）
npm run migrate:up
# 实际执行等价于：
#   psql "$DATABASE_URL" -f migrations/0001_init_schema.sql
#   psql "$DATABASE_URL" -c "CREATE EXTENSION IF NOT EXISTS timescaledb; CREATE EXTENSION IF NOT EXISTS vector;"
#   psql "$DATABASE_URL" -f migrations/0002_timescale_hypertables.sql
#   psql "$DATABASE_URL" -f migrations/0003_pgvector_tables.sql
#   psql "$DATABASE_URL" -f migrations/0004_audit_schema.sql

# 3) 校验
psql "$DATABASE_URL" -c "\dt" 
psql "$DATABASE_URL" -c "SELECT extname FROM pg_extension WHERE extname IN ('timescaledb','vector');"
```

### 10.2 种子数据

```bash
# 1) 业务种子数据（Recipe、设备档案、用户映射）
psql "$DATABASE_URL" -f deploy/seed/001_business_seed.sql

# 2) 合成时序数据（Faker+TimeGAN 生成脚本，写入 30 天历史）
python deploy/seed/gen_sensor_timeseries.py --days 30 --topic wafer.sensor.readings

# 3) 脏数据注入（缺失/漂移/尖峰，用于测试鲁棒性）
python deploy/seed/inject_dirty_data.py --rate 0.05
```

### 10.3 Neo4j 知识图谱导入

```bash
# 1) 图谱种子（工艺-设备-参数-缺陷 实体与关系）
docker compose -f deploy/docker-compose.yml exec -T neo4j \
  cypher-shell -a bolt://localhost:7687 -u neo4j -p "$NEO4J_AUTH_PWD" \
  < deploy/seed/neo4j_graph_seed.cypher

# 2) 校验节点与关系数量
docker compose -f deploy/docker-compose.yml exec neo4j \
  cypher-shell -a bolt://localhost:7687 -u neo4j -p "$NEO4J_AUTH_PWD" \
  "MATCH (n) RETURN labels(n)[0] AS label, count(n) AS cnt ORDER BY cnt DESC LIMIT 10;"
```

### 10.4 MinIO 桶初始化

```bash
docker compose -f deploy/docker-compose.yml exec minio mc alias set local \
  http://localhost:9000 "$MINIO_ROOT_USER" "$MINIO_ROOT_PASSWORD"
docker compose -f deploy/docker-compose.yml exec minio \
  mc mb local/wafer-defect-images local/process-docs local/audit-archive
docker compose -f deploy/docker-compose.yml exec minio \
  mc version enable local/audit-archive   # 审计归档桶开启版本化，防误删
```

### 10.5 初始化验收标准

| 检查项 | 通过标准 |
|--------|----------|
| 迁移 | `migrate:up` 退出码 0，重复执行无副作用 |
| 种子数据 | Recipe ≥ 50 条、设备 ≥ 20 台、时序覆盖 30 天 |
| 图谱 | 节点 ≥ 1000，关系 ≥ 5000 |
| MinIO | 3 桶创建成功，audit-archive 版本化开启 |
| 审计 | 登录、查询、审批各操作一次，审计表均有记录且含 traceId |
