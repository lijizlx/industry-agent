## 1. 验收目标与依据

### 1.1 验收目标

IndustryAgent（工业智能体平台）为芯联半导体制造有限公司（12英寸晶圆厂）建设的半导体良率根因分析智能体系统。本次验收旨在确认：

1. 系统功能满足《IndustryAgent 软件需求规格说明书（SRS）》（IA-SRS-001）约定的全部需求项；
2. 系统性能与智能体质量达到合同约定的量化指标；
3. 全部交付物（源码、文档、镜像、培训、演示视频）完整、可用、可交接；
4. 系统可在客户内网生产环境（Docker/K8s）稳定运行，具备投产条件。

### 2.3 智能体质量验收

#### 2.3.1 根因 Top-3 准确率评估方法

**标注样本集构建（50 个）：**

| 项目 | 说明 |
|---|---|
| 样本来源 | SECOM/WM-811K 公开数据改造 15 个 + 合成数据生成 35 个 |
| 样本构成 | 覆盖 6 类典型根因：设备参数漂移、腔体污染、Recipe 错配、传感器故障、来料批次异常、环境波动 |
| 标注方式 | 由客户方工艺工程师 + 质量工程师双人独立标注根因（金标准），标注一致性 Kappa ≥ 0.8 后冻结样本集 |
| 样本文件 | `D:\IndustryAgent-Docs\06-验收交付\附件-标注评估集\ground_truth_50.csv` |
| 回放方式 | 通过回放工具 `agent/eval/replay.py` 将 50 个样本的事件流注入 Staging 环境，逐个触发根因 Agent |
| 判定口径 | Top-3 嫌疑列表中包含金标准根因即记命中；命中率 = 命中数 / 50 |
| 达标线 | 命中率 > 80%（即 ≥ 41/50） |

**评估执行步骤：**

1. 冻结样本集并双方签字确认（禁止验收期间修改金标准）；
2. 在 Staging 环境以生产同版本镜像执行回放；
3. 输出原始结果 `eval_result_50.json` 与混淆矩阵；
4. 双方代表现场复核争议样本（预计 ≤ 5 个），按预登记的仲裁规则判定；
5. 出具《智能体质量评估报告》（IA-EVAL-R-001）。

#### 2.3.2 误报率统计口径

| 项目 | 口径 |
|---|---|
| 分子 | 试运行期内被人工确认为"非真实异常"的 FDC 告警条数（状态为"误报"或 24 小时内未处置且复核无异常） |
| 分母 | 试运行期内全部 FDC 告警条数 |
| 排除项 | 数据源中断导致的系统性缺数不计入分母（单列"数据质量事件"统计） |
| 达标线 | 误报率 < 10% |

#### 2.3.3 人工接管率统计口径

| 项目 | 口径 |
|---|---|
| 分子 | 审批环节中"驳回 + 重写 + 人工改判"的智能体建议条数 |
| 分母 | 进入审批环节的全部智能体建议条数 |
| 达标线 | 人工接管率 < 30% |

#### 2.3.4 智能体链路功能验收

| 链路环节 | 验收要点 |
|---|---|
| 监控 Agent → 根因 Agent | 事件触发自动派发，根因 Agent 5 分钟内返回 Top-3 |
| 根因 Agent → 建议 Agent | 根因确认后自动生成调参/停线建议，含风险与影响范围 |
| 建议 Agent → 审批 Agent | 建议必经人工审批（HITL），无绕过路径 |
| 审批 Agent → 报告 Agent | 审批完成后自动汇总生成 8D 报告初稿 |
| 失败降级 | 任一 Agent 失败时链路告警并支持人工重试，不阻塞其他事件 |

## 3. 验收流程

### 3.1 流程总述

```text
┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
│ 提交申请  │ →  │ 验收测试  │ →  │ 问题整改  │ →  │   复验    │ →  │ 签署报告  │
└──────────┘    └──────────┘    └──────────┘    └──────────┘    └──────────┘
 项目组提交      双方联合执行     P0/P1缺陷修复    对整改项逐条     双方签署
 验收申请+      功能/性能/      限期完成并       重新测试并       《验收报告》
 自检报告       智能体质量测试   提交整改报告      确认关闭         归档移交
                     │               │
                     ▼               ▼
               发现缺陷→定级     复验不通过→回到整改
               (P0/P1/P2)       (最多2轮，超限提交仲裁)
```

### 3.2 流程节点说明

| 阶段 | 输入 | 活动 | 输出 | 责任方 |
|---|---|---|---|---|
| 1. 提交申请 | 自测报告、版本冻结说明 | 项目组提交《验收申请》及自检证据 | 验收受理回执 | 项目组 |
| 2. 验收测试 | 测试用例集、样本集 | 按本计划 §2 执行功能、性能、智能体质量测试 | 缺陷清单（含定级）、测试记录 | 双方联合 |
| 3. 问题整改 | 缺陷清单 | 缺陷修复、回归自测 | 整改报告、新版本 | 项目组 |
| 4. 复验 | 整改报告 | 逐条复验关闭项 + 抽样回归 | 复验结论 | 双方联合 |
| 5. 签署报告 | 全部测试结论 | 填写达标结论、双方评审签署 | 《验收报告》（IA-AC-R-001） | 双方 |

### 3.3 缺陷定级标准

| 级别 | 定义 | 处理要求 |
|---|---|---|
| P0（致命） | 系统不可用、核心链路断裂、数据丢失、安全漏洞 | 阻塞验收，必须清零 |
| P1（严重） | 主要功能错误、指标不达标、无替代方案 | 阻塞验收，必须清零 |
| P2（一般） | 次要功能缺陷、界面/文案问题、有规避方案 | 允许 ≤ 3 个带规避方案通过 |
| P3（轻微） | 优化建议类 | 记录进二期需求池，不影响验收 |

## 4. 验收环境与数据

### 4.1 验收环境

| 环境 | 地址 | 用途 | 说明 |
|---|---|---|---|
| Staging（验收主环境） | 客户内网 K8s 集群 ia-staging 命名空间 | 全部功能与性能验收 | 与生产同版本镜像、同规格资源（可缩减副本数） |
| 前端入口 | https://ia-staging.芯联.local | Web 验收 | React 18 生产构建 |
| API 入口 | https://ia-staging.芯联.local/api/v1 | 接口验收 | Egg.js 4.0 |
| 智能体入口 | https://ia-staging.芯联.local/agent | 智能体质量验收 | FastAPI |
| 本地开发环境（辅助） | http://localhost:5173 | 演示与培训预演 | 仅用于演示，不作为验收依据 |

### 4.2 验收数据

1. **脱敏数据**：试运行期真实数据经字段脱敏（工单号哈希、人名替换）后导入 Staging，仅限验收期内使用，验收后按约定清除；
2. **合成数据**：覆盖 6 类根因场景的合成数据集（时序、Recipe、缺陷图、工艺文档），用于 50 样本回放与延迟测试；
3. **脏数据注入**：按 10% 比例注入缺失、漂移、重复、延迟，验证系统鲁棒性与误报率口径；
4. **数据冻结**：验收开始前对 Staging 数据做快照，验收期间数据只读快照保留，供争议复核。

| 工具 | 用途 |
|---|---|
| 回放工具 agent/eval/replay.py | 50 样本回放 |
| 压测脚本 server/test/load/ | 并发与延迟测试 |
| Prometheus + Grafana | 可用性、延迟、Kafka 积压等指标取证 |
