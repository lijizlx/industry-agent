## 状态

已接受（2026-10-15，架构评审会通过）

## 背景

IndustryAgent 的智能体链路为：**监控Agent(FDC异常检测) → 根因Agent(知识图谱+DoWhy因果推断+RAG检索 → Top-3嫌疑) → 建议Agent(调参/停线建议+风险评估) → 审批Agent(人工确认+审计) → 报告Agent(8D报告)**，另有评估 Agent 离线闭环。该链路对编排框架提出如下硬性要求：

1. **人在回路（HITL）是硬约束**：审批节点必须能"挂起数小时等待人工决策，决策后从断点恢复"——关键建议必须人工审批是本项目的合规红线；
2. **状态可控性与可审计性**：监管与复盘要求每一步的输入输出可回放（trace_id 全链路），状态机流转显式可见；
3. **持久化与容错**：服务重启不得丢失等待审批中的任务；单节点失败需可控重试（≤3 次指数退避）；
4. **工具调用标准化**：工具统一封装为 MCP（由 Egg.js MCP Server 暴露），框架需支持将 MCP 工具挂载为节点能力；
5. 团队为 Python 算法工程师（2 名），需与 FastAPI 服务集成。

## 备选方案对比

| 维度 | LangGraph | AutoGen | CrewAI | 自研状态机 |
|---|---|---|---|---|
| 状态可控性 | ★★★★★ 显式 StateGraph：节点/边/条件边全部代码可见，State TypedDict 强类型 | ★★★ 对话驱动，控制流隐式（依赖 LLM 决定下一步），流程不可显式审计 | ★★★★ 角色任务流较清晰，但细粒度分支控制弱 | ★★★★★ 完全可控 |
| 人机协同（HITL） | ★★★★★ 原生 `interrupt()/Command(resume)`，挂起-恢复一等公民 | ★★★ 需借 human_input 回复模式，长时挂起非原生 | ★★ 偏好自主完成任务，HITL 需绕行实现 | ★★★★ 需自研断点持久化 |
| 持久化 | ★★★★★ PostgresSaver checkpointer，thread_id 断点恢复 | ★★★ 有记忆存储，流程级断点恢复弱 | ★★ 会话记忆为主 | ★★★★ 需自研 |

| 与本项目流程匹配度 | ★★★★★ 线性管道+条件分支+HITL 中断，正是 LangGraph 的目标形态 | ★★ 对话式多智能体与"确定性管道+审批断点"的形态错配 | ★★ 偏 role-playing 协作，与审批流形态错配 | ★★★★★ 天然匹配但成本最高 |

## 决策

**采用 LangGraph 作为智能体编排框架（Python FastAPI 内嵌），工具层统一经 Egg.js MCP Server 暴露（LangGraph + Egg.js MCP 工具层的混合架构）。**

架构分工：

```text
FastAPI + LangGraph（ai-service）
  ├─ StateGraph: monitor → rootcause → suggest → approve(interrupt) → report
  ├─ PostgresSaver：checkpointer 按 thread_id=task_id 持久化
  └─ 工具调用（query_graph / search_docs / run_causality / query_sensors…）
        ──MCP──► Egg.js MCP Server（工具实现复用 service 层，权限/审计统一）
```

## 理由

1. **HITL 是本项目的合规红线，而 interrupt/resume 是 LangGraph 的原生能力**：审批等待可达 30 分钟～2 小时（超时升级），LangGraph 的 checkpointer 挂起-恢复模型与之完全同构，AutoGen/CrewAI 均需大量补丁；
2. **流程形态匹配**：本项目是"确定性管道 + 少量条件分支"，不是自由对话协作。LangGraph 显式状态机让流程对审计者完全透明（六层复杂度中"组织/合规"层的直接要求）；
3. **状态可控可回放**：State TypedDict 强类型 + LangSmith trace + 时间旅行调试，满足全链路审计与事故复盘需求；
4. **避免自研陷阱**：自研虽匹配度最高，但断点持久化、重试、可观测需 4-6 周额外投入，且长期维护负担与 LangGraph 社区迭代速度不成正比；
5. **MCP 工具层与业务后端统一**：LangGraph 的工具挂载直接对接 Egg.js MCP Server，权限与审计在业务侧收口，智能体不直连数据库（见 ADR-001）。

## 后果

### 正面

- HITL 审批断点开箱即用，服务重启后任务可从检查点恢复，无丢失；
- 流程代码即架构文档（节点/边/条件边显式），评审与审计成本降低；
- LangSmith/时间旅行让根因链路问题可逐状态回放定位。

### 负面

- LangGraph 迭代快、API 有破坏性变更风险（0.x 版本）；
- 框架与 LangChain 生态耦合较深，若未来更换需适配成本；
- 团队需学习 LangGraph 心智模型（约 1 周），且 LangSmith 若用云版与"数据不出域"冲突。

### 缓解

- 锁定 LangGraph 次版本（`~=` 约束），升级在灰度环境对历史任务做影子回放（评估 Agent 对比指标，见 IA-SD-006 第 8/12 章）后再切；
- Agent 节点内部逻辑与框架解耦（纯函数 + 显式 State），最坏情况可迁移到其他框架或薄自研层；
- 不使用 LangSmith 云版：trace 通过 OpenTelemetry 落本地 Jaeger，可观测性自持，满足数据不出域。
